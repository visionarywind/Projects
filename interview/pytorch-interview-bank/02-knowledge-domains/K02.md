# K02 autograd、计算图与梯度

## 范围

requires_grad、leaf、反向、view、detach、checkpoint 和梯度语义。

## 学习重点

- 先建立概念和输入/输出契约，再追踪实现、状态、资源和失败路径。
- 结合对应难度题，逐步练习测试、性能、设计和专家决策。
- 版本、硬件、源码行号和实验结果按题目事实状态处理，未运行内容标为 [待验证]。

## 领域边界

本域聚焦“反向传播如何在动态图上被记录与执行”，即 autograd 引擎的**图结构、梯度语义与内存/计算代价模型**。它回答：

1. 谁参与求导：`requires_grad`、叶子张量、`grad_fn` 的传播规则。
2. 反向如何执行：拓扑序、梯度累加、`backward` 的种子与 `retain_graph`。
3. 如何控制记录：`detach`、`no_grad`、`inference_mode` 的差别。
4. 正确性陷阱：in-place 与版本计数、`.data` 的绕过。
5. 代价权衡：梯度检查点（显存换计算）、高阶梯度（`create_graph`）。

本域**不负责**：

- 张量布局与设备搬运本身：`view`/`stride`/`contiguous` 的机制属 K01；本域只讲它们如何影响 autograd 的梯度回流。
- 优化器更新与学习率调度：属 K05。
- 混合精度导致的数值问题：属 K06；本域只讲 autograd 与 dtype 交互的边界。
- 自定义 kernel 的底层实现：`Function` 的注册属 K11。

与相邻域的接口：

- 依赖 K01：梯度张量与输入张量形状一致，其布局/连续性影响 `grad` 的写出与后续 `view` 的关系。
- 向 K03 输出：`Parameter.requires_grad`、`Module.zero_grad()`、`state_dict` 中是否保存梯度。
- 向 K05 输出：`.grad` 的累加语义决定 `optimizer.zero_grad()` 的必要性。
- 向 K06 输出：`autocast` 下的梯度 dtype 与 `GradScaler` 的交互。
- 向 K09 输出：backward 是显存与时间的主要来源之一，profiling 需区分 forward/backward。

## 先修知识

- **微积分**：偏导数、链式法则、雅可比矩阵、向量-雅可比积（VJP）。
- **K01 张量与布局**：shape/stride、视图与拷贝的区别，是理解 `view` 梯度与版本计数的前提。
- **Python 控制流**：动态图是“运行时构建”，`if`/`for` 会实际决定图结构。
- **内存生命周期**：中间激活张量在 backward 后释放，是理解 `retain_graph` 与 checkpoint 的基础。

## 核心机制

### 1. requires_grad、叶子与非叶子张量

**叶子张量（leaf）**是用户直接创建的张量（不是某个算子输出的结果），例如 `torch.randn(3, requires_grad=True)`。**非叶子张量**是算子输出，带有 `grad_fn`，指向图中的下一个节点。

```python
w = torch.randn(3, requires_grad=True)   # leaf, requires_grad=True
y = w * 2                                 # non-leaf, requires_grad=True, y.grad_fn != None
w.is_leaf, y.is_leaf                      # (True, False)
w.requires_grad, y.requires_grad          # (True, True)
```

`requires_grad` 的传播规则：如果一个张量由**至少一个** `requires_grad=True` 的输入，经**可微算子**、且**不在 `no_grad`/`inference_mode` 下**计算得到，则输出 `requires_grad=True`。整数/布尔张量永不能 `requires_grad=True`（只有浮点与复数可以）。

**`.grad` 只对叶子张量自动填充**。非叶子中间结果默认不保存梯度；要观察需调用 `.retain_grad()`：

```python
x = torch.randn(3, requires_grad=True)
y = x * 2
z = y.sum()
z.backward()
x.grad          # tensor([2., 2., 2.])
y.grad          # None（非叶子默认不保留）
y.retain_grad() # 需在 backward 前调用
```

### 2. 动态图（define-by-run）与 grad_fn 图

PyTorch 采用**定义即运行**：每次 forward 都会基于当时的张量和控制流**重新构建**一张有向无环图。节点分两类：

- **叶子节点**：`AccumulateGrad`，负责把梯度累加进 `.grad`。
- **中间节点**：每个算子对应一个 `grad_fn`（如 `MulBackward0`、`AddmmBackward0`），通过 `next_functions` 连向上游。

```python
x = torch.tensor(1.0, requires_grad=True)
a = x * 2
b = a + 1
b.grad_fn                 # AddBackward0
b.grad_fn.next_functions  # ((MulBackward0, 0),)
```

反向传播时 autograd 对图做**反向拓扑排序**，保证一个节点的所有下游贡献被累加完，才继续向上游传播。这就是为什么图中可以存在同一个张量被多条路径使用（“多路径”）而结果正确。

### 3. backward 的语义：种子、累加与拓扑

```python
loss = model(x).sum()
loss.backward()          # 等价于 loss.backward(torch.tensor(1.))
```

要点：

- **只能对标量调用无参 `backward()`**，否则报 “grad can be implicitly created only for scalar outputs”。非标量需显式传 `gradient`（即 `grad_output`）。
- `backward(gradient=v)` 计算的是 **向量-雅可比积** `v^T · J`，而非完整雅可比。autograd 只实现 VJP（以及 `torch.autograd.grad` 的 VJP/JVP 组合）。
- **梯度是累加（`+=`）而非覆盖**：多次 backward、多个 loss 相加后 backward，都会把贡献加到 `.grad`。因此训练循环必须 `zero_grad()`。

```python
x = torch.tensor([1., 2.], requires_grad=True)
(x * 3).sum().backward()
x.grad                      # tensor([3., 3.])
(x * 2).sum().backward()
x.grad                      # tensor([5., 5.])  <- 累加，不是 [2.,2.]
```

### 4. retain_graph 与图的释放

backward 默认在完成后**释放中间缓存**（保存的激活），图随即不可再用。再次 backward 会报：

```
RuntimeError: Trying to backward through the graph a second time (or directly
access saved tensors after they have already been freed)...
```

解决办法：

- `backward(retain_graph=True)` 保留缓存，可多次反向；代价是显存不释放。
- 或 `backward(create_graph=True)` 会隐式保留图（为高阶梯度服务）。

多次反向通常用于：多个 loss 共享同一个 forward（如多任务、GAN），或需要在同一图上多次 VJP。注意每次调用仍会**累加**梯度。

### 5. detach vs no_grad vs inference_mode

| 工具 | 作用范围 | 对结果张量 | 内存 | 典型用途 |
|---|---|---|---|---|
| `t.detach()` | 单一张量 | 共享 storage，`requires_grad=False`，无 `grad_fn` | 无额外图 | 阻断某条支路的梯度 |
| `torch.no_grad()` | 上下文 | 输出 `requires_grad=False` | 不保存激活 | 推理、评估、手工更新参数 |
| `torch.inference_mode()` | 上下文 | 输出为 inference tensor，`requires_grad=False` | 比 `no_grad` 更省 | 纯推理部署 |

要点：

- `no_grad` 下**已经存在的叶子张量**若 `requires_grad=True`，在其中运算得到的输出依然 `requires_grad=False`。
- `detach()` 返回的视图与原张量**共享 storage**（改一个另一个变），但**不影响**原张量的图。
- `inference_mode` 产出的张量**不能用于后续 autograd**；一旦把它放进需要求导的计算会报错。它也禁用 view 的版本追踪，因此更快 [待验证：收益依赖场景]。

```python
with torch.no_grad():
    y = x * 2          # y.requires_grad == False
y = x * 2              # 恢复记录
```

### 6. in-place 操作与版本计数

每个张量维护一个**版本计数器（version counter）**，任何原地修改都会使其自增。autograd 在保存某个张量用于 backward 时，会记录其版本；backward 时若发现版本已变，则报：

```
RuntimeError: one of the variables needed for gradient computation has been
modified by an inplace operation...
```

规则要点：

- **对需要梯度的叶子做原地修改会报错**：
  ```
  RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.
  ```
  正确做法是 `with torch.no_grad(): w -= lr * w.grad`，或 `w.data`（见陷阱）。
- 对**非叶子**的原地修改若破坏 backward 所需数据则报版本错误。
- 有些算子在 autograd 中**支持原地形式**（如 `relu_`、`add_`），因为它们用“写覆盖”的方式等价实现，autograd 有专门处理；但 `x = x + y` 与 `x += y` 在图语义上不同，后者可能改变已保存张量的值。

```python
x = torch.randn(3, requires_grad=True)
y = x * x          # y 依赖 x 的值
y.register_hook(lambda g: g)
x.transpose(0, 0)  # 无害，仅示例
# x[0] = 100       # 若在 backward 前对 x 原地改，可能触发版本错误
```

### 7. `.data` 与绕过 autograd 的危险

`t.data` 返回一个**共享同一 storage 但脱离 autograd 追踪**的张量。对 `.data` 的原地修改**不会递增版本计数**，因此 backward 时 autograd 察觉不到，可能静默算出错误梯度。正确做法：

- 更新参数：`with torch.no_grad(): p -= lr * p.grad`
- 仅取值：`p.detach()`

`.data` 在老代码中用于手动更新参数，现代应避免。

### 8. 梯度检查点（gradient checkpointing）

`torch.utils.checkpoint.checkpoint(fn, *args)` 用**计算换显存**：

- **普通 forward** 会保存所有中间激活供 backward 使用，显存占用随层数线性增长。
- **checkpoint** 在 forward 阶段只保存函数输入（少量），前向激活不驻留；backward 时**重新执行一次 forward** 以重建激活，再做反向。
- 代价：额外一次前向计算（约增加总计算量 ~1/3 量级 [待验证]），换来显存下降至接近 `O(1)` 每段。

```python
from torch.utils.checkpoint import checkpoint

def block(x):
    return self.layer2(self.layer1(x))

out = checkpoint(block, x, use_reentrant=False)
```

注意：

- 需要 `preserve_rng_state=True`（默认）才能让 dropout 等随机层在重算时得到相同结果；否则前后向 RNG 不一致导致梯度错误。
- `use_reentrant=True`（旧默认）与 no_grad 嵌套、需要梯度的输入等有兼容性坑；新版推荐 `use_reentrant=False`。
- checkpoint 段内的参数仍需 `requires_grad=True`，但中间激活不保留。

### 9. 高阶梯度与函数式 API

`torch.autograd.grad(outputs, inputs, grad_outputs=None, create_graph=False, retain_graph=None, allow_unused=False)` 是比 `backward` 更可控的接口：

- 直接返回梯度元组，不写入 `.grad`。
- `create_graph=True` 让**反向过程本身可再求导**，用于高阶梯度（如 WGAN-GP 的梯度惩罚、二阶优化、meta-learning）。

```python
x = torch.tensor(2.0, requires_grad=True)
y = x**3
g1, = torch.autograd.grad(y, x, create_graph=True)   # 3x^2
g2, = torch.autograd.grad(g1, x)                      # 6x = 12
```

`allow_unused=True` 允许某些输入不参与图（否则报错），返回 `None` 占位。

### 10. 自定义 Function

```python
class Square(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x * x
    @staticmethod
    def backward(ctx, grad_output):
        x, = ctx.saved_tensors
        return grad_output * 2 * x

y = Square.apply(x)
```

要点：`ctx.save_for_backward` 保存张量并自动处理版本；`ctx.needs_input_grad` 判断哪些输入需要梯度；`mark_dirty` 声明对输入的原地修改；`mark_non_differentiable` 声明输出不可导。

### 11. autograd 的内存模型：saved tensors

反向传播需要的前向中间量（saved tensors）由每个 `grad_fn` 通过 `ctx.save_for_backward` 持有。这是训练显存的主要来源：

- forward 时逐算子保存激活；backward 用到后释放。
- 保存策略可被 `torch.autograd.graph.saved_tensors_hooks(pack, unpack)` 拦截，用于**把激活换出到 CPU 或做低精度压缩**，是显存优化的通用钩子。
- `retain_graph=True` 会阻止释放，导致显存不降。
- 计算量与显存常呈“保存即省算、重算即省存”的权衡；gradient checkpointing（第 8 节）是这一权衡的显式实现。

```python
from torch.autograd.graph import saved_tensors_hooks

def pack(t):   return t.to("cpu", non_blocking=True)
def unpack(t): return t.to("cuda", non_blocking=True)

with saved_tensors_hooks(pack, unpack):
    loss = model(x)
loss.backward()
```

注意：换出/换回本身是拷贝开销，是否净收益取决于激活大小与 PCIe/NVLink 带宽 [待验证]。

### 12. 梯度累加与等效 batch size

因为 `.grad` 累加，可以用多个 micro-batch 的 backward 来模拟一个大 batch，再 `step()` 一次：

```python
optimizer.zero_grad()
for i, (xb, yb) in enumerate(loader):
    loss = criterion(model(xb), yb) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

语义要点：

- 梯度在数值上是各 micro-batch 的**求和**，要等价于大 batch 的平均，需把每个 loss **除以** `accum_steps`。
- BatchNorm 的 batch 统计仍按 micro-batch 计算，与真正的大 batch 不等价；需 `SyncBatchNorm` 或更大 micro-batch。
- `zero_grad(set_to_none=True)` 把 `.grad` 置为 `None` 而非零张量，可省一次写显存并让首次累加直接赋值 [待验证：收益随版本与规模变化]。

### 13. 一个完整的 VJP 走查

以 `z = (x * y).sum()`、`x,y` 均为 shape `(3,)` 为例：

```
forward:  s = x * y          # grad_fn = MulBackward0
          z = s.sum()        # grad_fn = SumBackward0
backward: dz/dz = 1
          ds = ones_like(s)  # sum 的 VJP 是全 1
          dx = ds * y = y
          dy = ds * x = x
```

对应代码与结果：

```python
x = torch.tensor([1., 2., 3.], requires_grad=True)
y = torch.tensor([4., 5., 6.], requires_grad=True)
z = (x * y).sum()
z.backward()
x.grad   # tensor([4., 5., 6.]) == y
y.grad   # tensor([1., 2., 3.]) == x
```

若改写成带有广播的形状（如 `x` 为 `(3,1)`、`y` 为 `(4,3)`），backward 会对被广播维度做**求和归约**，把梯度形状还原到输入形状——这正是 broadcast 的 VJP 规则，也是 shape 不匹配报错的来源。

### 14. 异常检测与调试

- `torch.autograd.set_detect_anomaly(True)`：在 backward 报错时定位到具体前向算子，代价是速度大幅下降，仅调试用。
- 更细的 `torch.autograd.detect_anomaly(check_nan=True)` 可在梯度出现 NaN/Inf 时报警 [待验证：参数可用性随版本变化]。
- 检查 `requires_grad`、`grad_fn`、`is_leaf`、`grad is None` 是定位“梯度没回传”的第一步。
- 常见“梯度为 None”：输入未设 `requires_grad`；某处用了 `detach`/`no_grad`/`.data`/`.item()`；张量是整数 dtype。
- 梯度爆炸/消失：观察 `.grad` 的范数随时间的变化，配合梯度裁剪使用。

## 常见陷阱与反例

1. **忘记 `zero_grad()`**：梯度跨 step 累加，等效学习率放大。
2. **第二次 backward 不传 `retain_graph=True`**：图已释放，报 “backward through the graph a second time”。
3. **对非叶子期望 `.grad`**：默认是 `None`，需 `retain_grad()`。
4. **对标量以外调无参 `backward()`**：报 “grad can be implicitly created only for scalar outputs”。
5. **对叶子原地更新**：报 “a leaf Variable that requires grad is being used in an in-place operation”。
6. **用 `.data` 更新参数**：绕过版本计数，可能算出错误梯度且不报错。
7. **在需要梯度的张量上 `.numpy()`/`.item()`**：`numpy()` 直接报错；`item()` 等价取值不建边，但注意它返回 Python 标量、丢失梯度。
8. **`detach()` 与 `no_grad` 混用误解**：`detach` 只断一条支路，共享 storage；`no_grad` 关闭整段记录。
9. **`inference_mode` 的张量泄漏进训练图**：会报错或静默错误，务必区分推理与训练上下文。
10. **checkpoint 与 RNG**：`preserve_rng_state=False` 时 dropout 前后向不一致，梯度错。
11. **checkpoint 让输入 `requires_grad` 丢失**：`use_reentrant=True` 下某些场景需要输入带梯度，否则输出不建边。
12. **多 loss 各自 backward 未保留图**：第二个 loss 反向时图已释放。
13. **认为 `backward` 返回梯度**：它返回 `None`，梯度写入 `.grad`；要返回值用 `torch.autograd.grad`。
14. **梯度累加与 `retain_graph` 混淆**：即使不保留图，多次 forward-backward 仍会累加到 `.grad`。
15. **对整数张量设 `requires_grad=True`**：直接报错，只有浮点/复数可导。
16. **把 `loss.backward()` 写在 `no_grad` 里**：不会报错但梯度不建边，训练不更新。

## 与其他知识域的连接

- **K01 布局**：`view`/`transpose`/`expand` 的梯度需按 stride 逆映射回原张量；对布局的原地修改会触发版本计数，是 backward 报错的高频来源。
- **K03 Module**：`Parameter.requires_grad`、`Module.zero_grad()`、`Module.parameters()` 与 `.grad` 的关系；`state_dict` 不包含梯度。
- **K05 优化器**：`.grad` 的累加语义直接决定 `zero_grad(set_to_none=True)` 的必要性与显存表现。
- **K06 AMP/复现**：`autocast` 改变前向 dtype，`GradScaler` 依赖对 loss 的缩放与 `unscale_` 后再裁梯度；RNG 状态影响 checkpoint 重算一致性。
- **K09 性能**：backward 通常比 forward 更耗显存与时间，profiling 中需按 `Backward`/`AccumulateGrad` 区分节点。
- **K11 自定义算子**：自定义 `Function`/`torch.library` 需要显式提供 backward 并遵守 `save_for_backward`/版本计数约定。
