# K11 C++/CUDA 扩展与自定义算子

## 范围

schema、dispatcher、stream、autograd、ABI、构建和后端支持。

## 领域边界

**在本域内**

- Python 级自定义：`torch.autograd.Function` 的前向/反向契约、`save_for_backward`、二阶导。
- 算子注册：`torch.library`（`define`/`impl`/`custom_op`/`register_autograd`/`register_fake`）与旧式 `TORCH_LIBRARY`/`TORCH_LIBRARY_IMPL`；schema、别名与 mutation 标注。
- C++/CUDA 扩展：`torch.utils.cpp_extension`、`pybind11`、ATen、`CUDAExtension`、`BuildExtension`。
- CUDA kernel：grid/block、stream 语义、launch error 检查、device guard。
- 数值一致性：`gradcheck`/`gradgradcheck`、`opcheck`、前向反向一致性校验。
- ABI 与构建：`_GLIBCXX_USE_CXX11_ABI`、C++ 标准、JIT 与 setup.py 构建。
- 与编译/自动微分栈交互：meta/fake 注册、`torch.compile` 图捕获、`torch.func`/functorch。

**在本域外**

- 通用 CUDA 性能调优（K09）、Triton 编译器内部（K08）。
- 分布式通信算子（K07）、量化算法内部（K10）。
- autograd 引擎的调度实现（K02），本域只关心自定义节点的契约。

**边界判定规则**

- 是否“新增一个可被 dispatcher 分派、能被 autograd 求导、能被 compile 捕获的算子”——是则本域。
- 只是组合已有 aten 算子——不构成本域，属普通模型代码。

## 核心机制

### 1. `torch.autograd.Function` 前反向契约

```python
class MyMul(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, w):
        y = x * w
        ctx.save_for_backward(x, w)          # 保存给反向用
        return y

    @staticmethod
    def backward(ctx, grad_out):
        x, w = ctx.saved_tensors
        return grad_out * w, grad_out * x    # 与 forward 输入一一对应
```

契约要点：

- `backward` 必须为**每个 forward 输入**返回一个梯度，或返回 `None`（不需要梯度）。返回值个数必须与 `forward` 输入个数一致。
- `ctx.save_for_backward` 保存张量；`ctx.mark_dirty(x)` 声明原地修改；`ctx.mark_non_differentiable(y)` 声明不可导输出；`ctx.set_materialize_grads(False)` 允许 `grad_out` 为 `None`。
- `ctx.needs_input_grad` 判断某输入是否需要梯度，可跳过计算。
- 前向模式（forward-mode AD）用 `ctx.save_for_forward`。

**函数式写法**（把 ctx 相关操作与 forward 分离，更利于测试与组合）：

```python
def mymul_fwd(x, w):
    return x * w

def mymul_setup_context(ctx, inputs, output):
    x, w = inputs
    ctx.save_for_backward(x, w)

def mymul_bwd(ctx, grad_out):
    x, w = ctx.saved_tensors
    return grad_out * w, grad_out * x

MyMul2 = torch.autograd.Function.setup_context(mymul_fwd, mymul_setup_context, mymul_bwd)
```

**数学契约**：对 `y = f(x)`，反向要实现向量-雅可比积（vjp）：

```
grad_x = grad_y · J,   J = ∂y/∂x
```

多输出时，输入梯度是各输出贡献之和。

**二阶导**：若需要 double backward（`create_graph=True` 或 `gradgradcheck`），`backward` 本身必须由可微算子组成；否则用 `@torch.autograd.function.once_differentiable` 明确声明只支持一阶，二阶会报错——这比静默给出错误结果更可取。

**与 `torch.func`**：`torch.autograd.Function` 要支持 `vmap`/`grad`/`jvp`，需提供批量规则（`generate_vmap_rule=True`）并正确处理批量维度，否则报错或结果错误。`torch.func` 的 `grad`/`jacrev`/`jvp`/`hessian` 常用于替代手写 backward 做验证。

### 2. 数值一致性校验

`torch.autograd.gradcheck` 用**中心差分**近似数值梯度，与解析梯度比较。

- 中心差分：`(f(x+εe) - f(x-εe)) / (2ε)`。
- 误差来源：截断误差 `O(ε²)`，舍入误差 `O(ε_mach / ε)`；最优 `ε ≈ ε_mach^(1/3)`（float64 下量级约 `1e-6`）**[待验证，精确常数]**。
- `gradcheck` 要求输入为 `float64`、`requires_grad=True`，且函数确定（`nondet_tol` 控制随机容忍）。
- 判定：`|analytic - numeric| ≤ atol + rtol · |numeric|`。

```python
ok = torch.autograd.gradcheck(MyMul.apply, (x.double().requires_grad_(),
                                            w.double().requires_grad_()),
                              eps=1e-6, atol=1e-5, rtol=1e-3)
torch.autograd.gradgradcheck(MyMul.apply, inputs)   # 二阶
```

其他 oracle：`torch.autograd.functional.jacobian`、`vjp`、`jvp`；`torch.testing.assert_close` 做张量比较。前向模式校验用 `torch.autograd.forward_ad.dual_level`/`make_dual`。

### 3. `torch.library` 注册与 dispatcher

dispatcher 按 `(算子名, dispatch key)` 选择实现。常见 dispatch key：

| dispatch key | 含义 |
|---|---|
| `CPU` / `CUDA` | 具体设备后端 kernel |
| `Meta` | 只算形状/dtype，供 FakeTensor |
| `Autograd` | 反向节点注册 |
| `Autocast` | AMP 下的类型分派规则 |
| `CompositeImplicitAutograd` | 由其它可微算子组合，自动获得反向与 meta |
| `CompositeExplicitAutograd` | 组合但不自动推导，需显式注册 |

```python
torch.library.define("myops::mul_add(Tensor x, Tensor w, float b) -> Tensor")

torch.library.impl("myops::mul_add", "CPU", mul_add_cpu)
torch.library.impl("myops::mul_add", "CUDA", mul_add_cuda)

@torch.library.register_fake("myops::mul_add")   # meta/fake：供 FakeTensor 追踪
def _(x, w, b):
    return x.new_empty(x.shape)

def backward(ctx, gy): ...
torch.library.register_autograd("myops::mul_add", backward, setup_context=...)
```

- **schema** 决定参数/返回值签名、别名（`Tensor(a!) x` 表示原地写）与 mutation。写错别名会让 dispatcher 的版本计数、图捕获与自动微分失效。
- **`torch.library.custom_op`** 提供一个默认带 autograd/fake 组合的封装；其函数体不得修改输入，需用 `register_autograd` 提供反向。
- **`register_fake`/`impl_abstract`** 给 meta 设备一个只算形状/`dtype` 的实现，是 `torch.compile` 能捕获该算子的前提。
- **旧式 API**：

  ```cpp
  TORCH_LIBRARY(myops, m) { m.def("mul_add(Tensor x, Tensor w, float b) -> Tensor"); }
  TORCH_LIBRARY_IMPL(myops, CUDA, m) { m.impl("mul_add", &mul_add_cuda); }
  ```

- **`torch.library.opcheck(op, args)`** 运行一组检查：schema 合法性、autograd、fake/meta、别名与 mutation。是自定义算子进入生产前的标准门禁，任何一项失败都应视为阻断。

### 4. C++/CUDA 扩展构建

```python
from torch.utils.cpp_extension import load_inline
mod = load_inline(name="ext", cpp_sources=..., cuda_sources=...,
                  functions=["fwd"], with_cuda=True)
```

一个完整的 forward 骨架：

```cpp
#include <torch/extension.h>
#include <c10/cuda/CUDAGuard.h>
#include <c10/cuda/CUDAException.h>

template <typename scalar_t>
__global__ void add_kernel(const scalar_t* a, const scalar_t* b,
                           scalar_t* out, int64_t n) {
  int64_t i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < n) out[i] = a[i] + b[i];
}

at::Tensor add_cuda(const at::Tensor& a, const at::Tensor& b) {
  TORCH_CHECK(a.is_cuda() && b.is_cuda(), "inputs must be CUDA");
  TORCH_CHECK(a.scalar_type() == b.scalar_type(), "dtype mismatch");
  auto a_c = a.contiguous();
  auto b_c = b.contiguous();                       // 保证连续内存
  auto out = at::empty_like(a_c);

  c10::cuda::CUDAGuard guard(a_c.device());        // 设置当前设备
  auto stream = at::cuda::getCurrentCUDAStream();  // 用当前流，勿用默认流

  int64_t n = a_c.numel();
  int threads = 256;
  int blocks = (n + threads - 1) / threads;

  AT_DISPATCH_FLOATING_TYPES_AND_HALF(a_c.scalar_type(), "add_cuda", [&] {
    add_kernel<scalar_t><<<blocks, threads, 0, stream>>>(
        a_c.data_ptr<scalar_t>(), b_c.data_ptr<scalar_t>(),
        out.data_ptr<scalar_t>(), n);
  });
  C10_CUDA_KERNEL_LAUNCH_CHECK();                  // 检查 launch 错误
  return out;
}

PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
  m.def("add", &add_cuda, "elementwise add (CUDA)");
}
```

要点：

- `AT_DISPATCH_*` 宏在 lambda 内提供类型别名 `scalar_t`，按张量 `scalar_type()` 实例化模板；忘记覆盖 dtype（half/bfloat16/整数）会在运行到该类型时报错。
- 必须用 `at::cuda::getCurrentCUDAStream()`，在默认流上启动会与 PyTorch 其它算子乱序、竞态。
- 输入先 `.contiguous()` 再取 `data_ptr<T>()`；否则 stride 假设错误导致越界或错值。
- `C10_CUDA_KERNEL_LAUNCH_CHECK()` 把 launch 错误在调用点暴露；否则错误会延迟到某个不相关的同步点。
- 构建入口：`CppExtension`、`CUDAExtension` + `BuildExtension`（setup.py），或 `load`/`load_inline` 做 JIT 构建（依赖 ninja）。
- 异常：`TORCH_CHECK(cond, msg)` 用于用户错误，抛 `c10::Error` 并带栈。

### 5. meta/fake 注册与 `torch.compile` 交互

`torch.compile` 在 FakeTensor 上追踪图。自定义算子若没有 meta/fake 实现，会产生 graph break 或直接报 “Meta kernel not implemented” 类错误。具备 fake + autograd 的算子会作为**单个节点**留在图中，编译器可对其做内存规划与融合边界判定。

- `torch.library.custom_op` 默认给出 fake 与 autograd 骨架。
- `torch.compiler.disable` 可把不可追踪片段排除在编译外。
- 用 `make_fx`/`torch.export` 可检查算子是否被正确捕获。
- Triton 算子可用对应 `torch.library` Triton 集成注册 **[待验证，具体 API 与版本]**。
- 注册需幂等，避免命名空间冲突；异构后端要各自注册 dispatch key。

### 6. ABI、后端与版本

- **ABI**：扩展与 torch 必须使用相同的 `_GLIBCXX_USE_CXX11_ABI`，通常需 C++17，版本变化后要重编译；否则出现未定义符号或 `std::string` ABI 不匹配 **[待验证，探测方法]**。
- **后端**：每个 dispatch key（CPU/CUDA/Meta/…）需各自注册实现；新硬件后端需实现其 key。
- **版本兼容**：算子的命名空间与 schema 一旦被序列化模型或 TorchScript 使用，改变会破坏加载兼容（跨 K10）。
- **组合优先**：能用现有可微 aten 算子拼出的逻辑，优先组合而非手写 kernel，减少正确性风险。

### 7. 实现路径对比

| 路径 | 定义位置 | 反向 | meta/fake | compile 可捕获 | 适用 |
|---|---|---|---|---|---|
| 纯组合（现有 aten） | Python | 自动 | 自动 | 是 | 首选 |
| `torch.autograd.Function` | Python | 手写 | 需自行处理 | 有限（可能断裂） | 原型、特殊反向 |
| `torch.library.custom_op` | Python/C++ | `register_autograd` | 自动骨架 | 是 | 生产推荐 |
| C++/CUDA 扩展 + `TORCH_LIBRARY` | C++ | `register_autograd`/显式 | 需 `register_fake` | 是 | 性能、新硬件 |

**opcheck 覆盖的检查项**（任一失败都应阻断合入）：

- schema：参数名、类型、别名注解是否合法。
- autograd：反向是否可跑、梯度形状与 `dtype` 是否匹配。
- fake/meta：能否在 meta 设备上产出正确形状与 `dtype`。
- 别名/mutation：实际读写与 schema 声明是否一致。
- 测试覆盖：未覆盖路径会被提示补测。

**dispatcher 解析顺序**（简化）：调用算子时，引擎按 dispatch key 从优先级高的包装层回退查找实现（如 `Autograd`/`Autocast` 包装后再落到 `CUDA`/`CPU`），最终到 `CompositeImplicitAutograd` 的分解或 `BackendSelect`。注册到错误的 key 会导致反向或 meta 路径缺失。

### 8. double backward 与流同步的写法

支持二阶导的关键是让 `backward` 由可微算子组成：

```python
class Exp(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        y = x.exp()
        ctx.save_for_backward(y)
        return y

    @staticmethod
    def backward(ctx, g):
        (y,) = ctx.saved_tensors
        return g * y            # 可微表达式 → 支持 gradgradcheck
```

若不需要二阶导，用 `@once_differentiable` 明确声明；否则静默给出错误结果的代价更大。

仅在确有跨流依赖时才用事件，避免全局同步：

```cpp
at::cuda::CUDAEvent ev;
ev.record(at::cuda::getCurrentCUDAStream());
ev.block(other_stream);          // 建立流依赖，勿用 cudaDeviceSynchronize
```

### 9. 组合算子与功能化（functionalization）

在 `torch.compile`/`torch.export` 路径下，图要求函数式：算子的原地写会被功能化改写为“返回新张量 + 显式更新”。因此自定义算子应尽量无副作用，schema 中如实标注 `Tensor(a!)`（原地）或 `Tensor(a) -> Tensor(a)`（别名返回）。谎报别名的算子在功能化或 `gradcheck` 中会暴露不一致。

## 常见陷阱与反例

1. **backward 返回值不匹配**：少返回或漏 `None`，梯度错位或直接报错。
2. **backward 用不可微操作却声称支持二阶**：`gradgradcheck` 失败或给出静默错误结果。
3. **未注册 fake/meta**：`torch.compile`/`torch.export` 直接断裂或报无 meta kernel。
4. **CUDA kernel 跑在默认流**：与当前流不同步，产生竞态与不确定结果。
5. **schema 未声明 mutation/别名**：原地写不被察觉，版本检查与图捕获静默出错。
6. **ABI 不匹配**：链接或加载期未定义符号。
7. **忘记 `AT_DISPATCH` 覆盖 dtype**：half/bfloat16/整数输入直接报错或走错分支。
8. **gradcheck 未用 float64**：float32 下误差大导致假失败；或容差过松掩盖真 bug。
9. **自定义 Function 破坏 vmap/functorch**：未提供批量规则，`vmap` 报错或结果错误。
10. **不检查 kernel launch 错误**：非法配置被静默吞掉，后续在某处才崩。
11. **原地修改输入未 `mark_dirty`**：autograd 版本计数失效。
12. **在扩展里做隐式同步**：破坏流水线，性能回退。
13. **非连续输入直接取 `data_ptr`**：越界或错值，须先 `.contiguous()`。

## 与其他知识域的连接

- **K01（张量/布局）**：扩展必须处理非连续输入（先 `.contiguous()`）、dtype 与 device 分派。
- **K02（autograd）**：前反向契约、gradcheck、double backward、forward-mode 直接复用 autograd 概念。
- **K08（编译栈）**：meta/fake 注册决定算子能否被 Dynamo/FakeTensor 捕获，是图断裂的关键开关。
- **K09（性能）**：自定义 kernel 是否更快要用 profiler 验证；需区分 launch 开销与 kernel 时间。
- **K10（导出/部署）**：能否被 ONNX/TorchScript/`torch.export` 消费取决于 schema 与 fake 注册；跨版本加载依赖命名稳定。
- **K12（测试与治理）**：`opcheck`、`gradcheck`、数值一致性测试是自定义算子进入生产前的门禁。
