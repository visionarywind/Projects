# K06 AMP、Checkpoint 与可复现性

## 范围

autocast、GradScaler、快照、RNG、确定性和跨版本复现。

## 领域边界

本知识域覆盖三块彼此耦合的工程机制：混合精度训练（`autocast` 的算子精度策略、`GradScaler` 的损失缩放与动态调整）、训练状态快照（模型/优化器/调度器/scaler/RNG/进度）、以及可复现性（seed、确定性算法、cuDNN 行为、跨设备与跨版本差异）。

纳入范围的是它们对正确性、数值稳定与"能否精确续训/复现"的影响。明确排除：

- 梯度产生与计算图属于 K02；优化器公式与 step 顺序属于 K05。
- 参数序列化结构（`state_dict` 的构成规则）属于 K03；本域讨论"快照中应放哪些状态才完整"。
- 分布式 RNG 与进程组属于 K07；模型导出/部署的图序列化属于 K10。
- 具体硬件精度支持矩阵（哪些卡支持 bf16/TF32）需在目标环境核实，正文相关结论标 [待验证]。

判据：若问题涉及"降低精度的执行/缩放"、"训练状态的持久化与恢复"或"如何让两次运行一致"，属于本域。

## 核心机制

### autocast 的算子精度策略

`autocast` 是**上下文管理器**，不是全局开关。它按算子白/黑名单决定该算子本次以何精度执行：

```python
# 新版（推荐）
with torch.amp.autocast(device_type="cuda", dtype=torch.float16):
    out = model(x)
    loss = criterion(out, y)

# 旧版（逐步弃用）
with torch.cuda.amp.autocast(dtype=torch.float16):
    ...
```

典型策略（随版本变化 [待验证]）：

- **降精度**：矩阵乘（`matmul`、`linear`）、卷积、部分点积类算子 → float16/bfloat16。
- **保持 float32**：归约（`sum`/`mean`/`norm`）、`softmax`、`log_softmax`、层归一化、BatchNorm、损失函数（如 `cross_entropy`）、累积类算子。
- 这样做的原因：低精度加速来自乘加密集算子；归约与归一化对累加误差敏感，保持 fp32 更稳。

语义要点：

- autocast 是线程局部的；可嵌套，内层可覆盖外层 dtype。
- `cache_enabled=True`（默认）会缓存权重 cast 结果；训练中权重若被原地修改需注意缓存失效。
- autocast 只影响**前向中被包裹的**算子；反向的精度由 autograd 依据前向使用的 dtype 决定，无需重复包裹。
- 模型权重保持 fp32 存储，autocast 在算子入口临时 cast，属于"计算精度"而非"存储精度"。

失败模式：

- 在 autocast 外做手工 `.half()` 而错过某些 fp32 保护算子，导致数值发散。
- 自定义算子未注册 autocast 策略 → 默认走 fp32，无声地不加速；或用错精度。
- 在 autocast 内计算需要高精度的量（如 loss 归约、度量）却不 `autocast(enabled=False)` 包裹。

### bfloat16 与 float16

| 格式 | 指数位 | 尾数位 | 动态范围 | 需要 loss scaling |
|---|---|---|---|---|
| float32 | 8 | 23 | 大 | 否 |
| float16 | 5 | 10 | 窄（易上下溢） | 是 |
| bfloat16 | 8 | 7 | 与 fp32 相同量级 | 通常否 |

- fp16 指数位少，梯度中极小值会下溢为 0、极大会上溢为 inf，因此需要 **loss scaling**。
- bf16 与 fp32 指数范围一致，下溢风险低，通常**不需要** `GradScaler`；代价是尾数少、精度低。
- 选择依据：硬件是否原生支持 bf16（Ampere 及更新、部分 MUSA 架构 [待验证]）；对数值范围敏感的模型优先 bf16，追求精度且能接受缩放时可用 fp16。

### GradScaler 的损失缩放原理

核心观察：反向传播对 loss 是线性的。若用 `loss' = S * loss` 做反向，则 `grad' = S * grad`，把原本会下溢的小梯度抬到 fp16 可表示区间；在更新前再除以 `S` 还原即可。

动态流程：

```python
scaler = torch.amp.GradScaler("cuda")     # init_scale=2**16, growth_factor=2.0,
                                          # backoff_factor=0.5, growth_interval=2000

with autocast():
    loss = criterion(model(x), y)
scaler.scale(loss).backward()             # 反向前把 loss 乘 S
scaler.unscale_(optimizer)                # 可选：还原梯度以做裁剪/检查
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
scaler.step(optimizer)                    # 检查 inf/nan；有则跳过并降 S
scaler.update()                           # 根据本轮结果动态修正 S
optimizer.zero_grad(set_to_none=True)
```

状态机：

- **无 inf/nan 连续 `growth_interval` 次** → `S *= growth_factor`（默认翻倍）。
- **出现 inf/nan** → 跳过该次 `optimizer.step()`，`S *= backoff_factor`（默认减半），并重置增长计数。
- 跳过 step 的迭代，参数与优化器状态不被修改，但前向/反向的计算代价已付出。

`unscale_` 细节：

- 每个 optimizer 每个 iteration 至多调用一次，重复调用抛错。
- 若不做裁剪/自定义检查，可省略，`scaler.step` 内部会先 unscale 再检查。
- 裁剪必须在 `unscale_` 之后，否则 `max_norm` 针对的是 `S*grad`，阈值失去意义。

`inf/nan` 检测：`GradScaler` 在本 iteration 累积的 unscaled 梯度上扫描非有限值；也可手工遍历 `p.grad` 的 `torch.isfinite(...).all()` 做诊断。常见诱因：fp16 溢出、学习率过大、log(0)、除零。

### Checkpoint 应包含的状态

一个完整可续训的快照至少包含：

```python
ckpt = {
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "scheduler": scheduler.state_dict(),
    "scaler": scaler.state_dict(),        # AMP 场景必需
    "epoch": epoch,
    "global_step": global_step,
    "best_metric": best,
    # RNG 状态，保证续训采样/增强一致
    "rng_torch": torch.get_rng_state(),
    "rng_cuda": torch.cuda.get_rng_state_all(),
    "rng_python": random.getstate(),
    "rng_numpy": np.random.get_state(),
}
torch.save(ckpt, "ckpt.pt")
```

恢复：

```python
ckpt = torch.load("ckpt.pt", map_location="cpu")
model.load_state_dict(ckpt["model"])
optimizer.load_state_dict(ckpt["optimizer"])
scheduler.load_state_dict(ckpt["scheduler"])
scaler.load_state_dict(ckpt["scaler"])
start_epoch = ckpt["epoch"] + 1
torch.set_rng_state(ckpt["rng_torch"])
torch.cuda.set_rng_state_all(ckpt["rng_cuda"])
random.setstate(ckpt["rng_python"])
np.random.set_state(ckpt["rng_numpy"])
if hasattr(sampler, "set_epoch"):
    sampler.set_epoch(start_epoch)         # DistributedSampler 必需
```

易漏项与后果：

- **缺 optimizer 状态**：动量/矩估计从零开始，重启初期更新异常。
- **缺 scaler 状态**：`S` 退回初值，fp16 下可能再次溢出/下溢。
- **缺 RNG 状态**：数据增强、dropout、worker 采样与原始轨迹分叉。
- **缺 `global_step`**：按 step 的调度器与日志错位。
- **缺 `sampler.set_epoch`**：`DistributedSampler` 的 shuffle 不随 epoch 变化（见 K04/K07）。

### torch.save / torch.load 与 state_dict

- `state_dict()` 是"参数名 → 张量"的映射，**不含架构**；加载前必须已有同结构模型。
- `torch.save` 底层是 pickle + 一个未压缩/压缩的 zip 容器（`_use_new_zipfile_serialization`）；`torch.load` 需要 pickle 反序列化能力。
- `map_location` 决定张量落到哪：存于 GPU 的 checkpoint 在无 GPU 机器加载时会失败，应 `map_location="cpu"` 或 `map_location=lambda s, l: s.cpu()`。
- `load_state_dict(strict=True)` 默认严格匹配键名；`missing_keys`/`unexpected_keys` 用于定位不匹配。部分加载（如迁移学习）常 `strict=False`。
- 安全：`torch.load`/pickle 可执行任意代码；加载不可信来源须用 `weights_only=True`（默认值随版本变化 [待验证]），仅允许张量与白名单类型。
- 保存整个模型对象（`torch.save(model, ...)`）会连同类定义路径绑定，跨代码变更脆弱，生产环境应只存 `state_dict`。

### 可复现性

让"同一代码同一数据跑两次结果一致"需要显式管理：

```python
def seed_everything(seed):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    os.environ["PYTHONHASHSEED"] = str(seed)
```

- `torch.manual_seed` 同时影响 CPU 与所有 GPU 的默认生成器（具体范围随版本 [待验证]）。
- `PYTHONHASHSEED` 影响 set/dict 迭代顺序，进而影响某些依赖顺序的逻辑；需在启动前设置。

**确定性算法**：

```python
torch.use_deterministic_algorithms(True, warn_only=False)
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
# 需要时设置环境变量以给 cuBLAS 确定性工作区
os.environ["CUBLAS_WORKSPACE_CONFIG"] = ":4096:8"
```

- `use_deterministic_algorithms(True)` 会让非确定性算子报错或退化到确定性实现，可能显著变慢。
- `cudnn.deterministic=True` 关闭 cuDNN 的非确定性算法选择。
- `cudnn.benchmark=True` 会为固定输入尺寸自动选最优算法，速度快但**不保证确定**，且首次运行有 autotune 开销；追求复现时设 `False`。

**非确定性的来源**（即使 seed 固定）：

- 原子加（`atomicAdd`）导致的浮点累加顺序不定。
- 无序归约、并行扫描、多流并发。
- cuDNN autotune 与不同算法选择。
- TF32：`torch.backends.cuda.matmul.allow_tf32` / `cudnn.allow_tf32` 改变数值精度，跨设置不可复现 [待验证]。
- 数据加载的多 worker RNG（见 K04）。

**跨版本/跨设备复现**：不同 PyTorch、CUDA、cuDNN、驱动版本可能改变算子实现与累加顺序，位级复现通常不保证；工程上追求"统计等价"而非"逐位相同"。硬件精度差异（bf16 支持、TF32）也破坏位级一致 [待验证]。

### autocast 下自定义算子的精度注册

自定义 `torch.autograd.Function` 或自定义算子需要显式声明精度策略，否则不会被 autocast 正确处理：

```python
class MyFn(torch.autograd.Function):
    @staticmethod
    @torch.amp.custom_fwd(device_type="cuda", cast_inputs=torch.float32)
    def forward(ctx, x):
        ...
    @staticmethod
    @torch.amp.custom_bwd(device_type="cuda")
    def backward(ctx, g):
        ...
```

- `cast_inputs` 指定进入该算子前应 cast 到的精度；不注册时，autocast 对该算子默认按"未列出"处理（行为随版本 [待验证]）。
- 旧装饰器为 `torch.cuda.amp.custom_fwd/custom_bwd`，新 API 为 `torch.amp.custom_fwd/custom_bwd(device_type=...)`。
- 若自定义算子在内部做高精度累加，应 `cast_inputs=torch.float32`，避免 fp16 累加误差。

### CPU autocast 与 bf16

`autocast` 不限于 CUDA：

```python
with torch.amp.autocast(device_type="cpu", dtype=torch.bfloat16):
    out = model(x)
```

- CPU 上通常使用 bfloat16（CPU 普遍不具备 fp16 加速，bf16 由 AMX/AVX512-BF16 支持 [待验证]）。
- CPU bf16 与 GPU bf16 的算子覆盖名单不同，行为可能不一致，需分别验证。
- CPU autocast 与 `GradScaler` 关系类似：bf16 通常不需缩放。

### Checkpoint 工程实践

除"存哪些状态"外，还要考虑可靠性与成本：

- **原子写入**：先写临时文件再 `os.replace`，避免中断产生半截文件。
- **best/last 分离**：`last.pt` 用于续训（含全部状态），`best.pt` 只存模型用于推理。
- **周期与保留**：按 step/epoch 定期保存，滚动保留最近 K 个以控制磁盘。
- **sharding**：大模型用分片保存/加载（`state_dict` 按 rank 或按张量切分），减少单点内存峰值；相关 API 随版本演进 [待验证]。
- **加载后自检**：比较恢复后 `optimizer.state` 的 `step` 计数、`scaler.state` 的 scale、`scheduler.last_epoch` 是否与保存前一致。
- **设备放置**：`map_location="cpu"` 加载，再 `.to(device)`；或将优化器状态一并移到对应设备以免训练时设备不匹配。

### 复现检查清单

要让一次训练可被精确复现（或在同构环境下统计等价），逐项确认：

1. 进程启动前设 `PYTHONHASHSEED`，并调用统一的 `seed_everything`。
2. 多 worker：`worker_init_fn` 重置所有私有 RNG（K04）。
3. 分布式：每 rank 用统一 seed 或 `seed + rank`（明确约定），并 `sampler.set_epoch`（K07）。
4. 确定性：按需求设置 `use_deterministic_algorithms`、`cudnn.deterministic`、`cudnn.benchmark`。
5. 精度：固定 AMP 的 dtype 与 TF32 开关；记录 bf16/fp16 选择。
6. 数据：固定数据版本与 `drop_last`；记录数据集哈希。
7. 记录环境：PyTorch/CUDA/cuDNN/驱动版本、GPU 型号、并行度。
8. 验证：跑两次短训练比较 loss 曲线与随机张量抽样的逐位一致性；跨设备时接受统计等价。

## 常见陷阱与反例

| 陷阱 | 症状 | 根因 / 修正 |
|---|---|---|
| fp16 直接训练不缩放 | 梯度下溢、loss 不降 | 用 `GradScaler` |
| bf16 仍强行加 scaler | 无收益、可能干扰 | bf16 通常不需要缩放 |
| 裁剪在 `unscale_` 之前 | 阈值失效、训练不稳 | 先 `scaler.unscale_` 再裁剪 |
| `unscale_` 重复调用 | 运行期报错 | 每 optimizer 每 iter 仅一次 |
| checkpoint 只存模型 | 续训初始异常、lr 重置 | 存 optimizer/scheduler/scaler/step/RNG |
| 恢复时不设 sampler epoch | 各 epoch 数据顺序不变 | `sampler.set_epoch(start_epoch)` |
| RNG 未保存 | 增强/dropout 分叉 | 保存并恢复四类 RNG 状态 |
| `map_location` 缺失 | CPU 机加载 GPU ckpt 失败 | `map_location="cpu"` |
| 可信假设加载外部 ckpt | 反序列化执行恶意代码 | `weights_only=True` |
| `cudnn.benchmark=True` 追求复现 | 每次算法不同 | 设 `deterministic=True, benchmark=False` |
| 只设 `torch.manual_seed` | 仍不可复现 | 同时设 python/numpy/cuda seed 与哈希种子 |
| 期待跨卡/跨版本位级一致 | 结果总有微小差异 | 接受统计等价，逐位复现非保证 |
| autocast 内算度量 | 度量精度异常 | `autocast(enabled=False)` 包裹 |
| 自定义算子无 autocast 策略 | 静默不加速/精度错 | 注册对应精度策略 |
| 保存整个 model 对象 | 换代码后无法加载 | 只存 `state_dict` |

反例：只在 epoch 开头 `torch.manual_seed(epoch)`，却忽略了 `DistributedSampler` 与多 worker 的独立随机源——表面上 seed 固定，实际上每 rank 的 shuffle 与 worker 增强仍不一致，复现失败。

## 与其他知识域的连接

- **K01 张量/设备**：dtype 转换、`.to(device)`、流与 TF32 开关影响精度与复现。

- **K05 优化器**：scaler 与 `step`/`unscale_`/裁剪顺序、优化器状态完整性。
- **K07 分布式**：每 rank seed、进程组、分布式 RNG 与 `set_epoch`。
- **K09 性能分析**：AMP 的加速、`cudnn.benchmark` autotune 开销、确定性算法带来的减速。
- **K10 导出/部署**：训练 checkpoint 与推理导出格式的边界（本域只管训练态）。
