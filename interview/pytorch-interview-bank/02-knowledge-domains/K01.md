# K01 张量、dtype、device 与内存布局

## 范围

shape、stride、广播、设备、精度和存储别名。

## 学习重点

- 先建立概念和输入/输出契约，再追踪实现、状态、资源和失败路径。
- 结合对应难度题，逐步练习测试、性能、设计和专家决策。
- 版本、硬件、源码行号和实验结果按题目事实状态处理，未运行内容标为 [待验证]。

## 领域边界

本域聚焦“数据在内存中如何被描述与搬运”，即 `torch.Tensor` 作为“storage + 元数据 + dispatch”的组合体。它回答四类问题：

1. 逻辑形状与物理存储的映射：`shape`、`stride`、`storage_offset`、连续性。
2. 类型系统：`dtype`、`itemsize`、类型提升（type promotion）、精度与范围。
3. 设备与搬运：CPU/CUDA 等设备语义、`.to()`、`pin_memory`、`non_blocking`。
4. 别名与视图：哪些操作共享 storage、哪些触发拷贝，以及别名对正确性的影响。

本域**不负责**下面的内容，遇到时应转到相邻域：

- 计算图与反向传播：本域只说明视图操作如何成为 autograd 边的载体，梯度公式与图遍历属 K02。
- 模块状态管理：`Parameter`/`buffer` 的注册、`state_dict` 与 `.to()` 的模块级语义属 K03；本域只讲张量级的设备/布局迁移。
- 数据加载流水线：`DataLoader` 的多进程、`collate_fn`、`sampler` 属 K04；本域只讲 `pin_memory` 的页锁定内存语义。
- 算子实现与 kernel 调优：本域给出布局对性能的定性模型，不给具体 kernel 吞吐数字（属 K09/K11）。

与相邻域的接口：

- 向 K02 输出：`view`/`reshape`/`transpose`/`permute` 建立的“视图关系”是反向传播中梯度如何回流到原张量的依据；对布局的原地修改会触发版本计数，进而影响 backward 是否报错。
- 向 K03 输出：`Parameter` 与 buffer 的 `dtype`/`device`/`memory_format` 决定 `Module.to()`/`.cuda()` 的行为和 `state_dict` 的内容。
- 向 K04 输出：`pin_memory`、`non_blocking` 以及副本在 worker 与主进程间的传递方式。
- 向 K09/K11 输出：`contiguous`、`channels_last` 的布局选择决定访存合并（coalescing）与 tensor core 是否能被高效使用。

## 先修知识

在进入核心机制前应掌握：

- **数组的内存模型**：行优先（C 风格，最后一维连续）与列优先（Fortran）存储顺序；同一个逻辑矩阵在两种顺序下的线性地址映射不同。
- **指针/缓冲区**：一块连续字节，按类型解释切分；`data_ptr()` 是首地址，元素之间按 `itemsize` 偏移。
- **线性代数与广播**：NumPy 式的广播语义，是理解 PyTorch broadcast 与 stride-0 的前提。
- **Python 引用语义**：`b = a` 只是别名，`b = a.clone()` 才是复制；视图与拷贝的区别贯穿本域。
- **字节与位**：1 byte = 8 bit；`float32` 占 4 字节，`float16`/`bfloat16` 占 2 字节。
- **设备模型**：GPU 有独立的显存地址空间，CPU 与 GPU 之间不能直接解引用对方指针，必须显式拷贝。

## 核心机制

### 1. Tensor 的三层结构

一个 `torch.Tensor` 由三部分组成：

1. **Storage（存储）**：一块类型化的一维连续内存。`t.untyped_storage()` 返回原始字节视图，`t.storage()` 返回类型化视图。
2. **元数据（metadata）**：`sizes`（shape）、`strides`、`storage_offset`、`dtype`、`device`、`layout`、`requires_grad` 等。
3. **dispatch 信息**：记录设备类型与后端，决定算子路由到哪个 kernel（CPU、CUDA、MUSA 等）。

关键不变量：

```
numel     = prod(shape)                     # 逻辑元素个数
nbytes    = numel * itemsize                # 连续张量的存储字节数下界
storage_offset >= 0
```

逻辑索引 `(i_0, ..., i_{n-1})` 到 storage 线性下标的映射：

```
storage_index = storage_offset + sum_k( i_k * stride_k )
```

`stride` 的单位是**元素个数**而不是字节；字节偏移需再乘 `itemsize`。可通过 `t.stride()`、`t.storage_offset()`、`t.element_size()`、`t.data_ptr()` 观察。

```python
x = torch.arange(12, dtype=torch.float32).reshape(3, 4)
x.shape            # torch.Size([3, 4])
x.stride()         # (4, 1)   -> 行优先，最后一维连续
x.storage_offset() # 0
x.element_size()   # 4
x.numel()          # 12
x.untyped_storage().nbytes()  # 48
```

### 2. 视图 vs 拷贝：谁共享 storage

判断标准是“是否新建 storage”。**只改元数据、复用同一 storage 的操作返回视图**：

| 操作 | 结果 | 说明 |
|---|---|---|
| 基础索引 `x[0]`、`x[:, 1:3]`、`x[..., None]` | 视图 | int/slice/None/Ellipsis 保持视图 |
| `x.view(...)` | 视图（条件满足时） | 要求 stride 兼容目标形状 |
| `x.reshape(...)` | 视图或拷贝 | 兼容则视图，否则自动复制 |
| `x.transpose(d0, d1)` / `x.permute(...)` | 视图 | 交换 stride，不搬数据 |
| `x.squeeze()` / `x.unsqueeze()` | 视图 | 增删 size=1 维 |
| `x.expand(...)` / `x.expand_as(...)` | 视图 | 新维度用 stride=0 实现广播 |
| `x.narrow`、`x.select`、`x.flip`(部分) | 视图 | 元数据操作 |
| `x.contiguous()` | 可能拷贝 | 已连续返回 `self`，否则复制 |
| `x.clone()` | 拷贝 | 新 storage，保留 autograd 关系 |
| `x.detach()` | 视图 | 共享 storage，断开图（见 K02） |
| **高级索引** `x[idx_tensor]`、`x[[0,2]]` | 拷贝 | 布尔/整数张量索引触发 gather |
| `x.to(...)`（设备/dtype 变化） | 拷贝 | 同设备同 dtype 时返回 `self` |

验证共享靠 `data_ptr()`：

```python
a = torch.arange(6)
b = a.view(2, 3)
a.data_ptr() == b.data_ptr()   # True
c = a.clone()
a.data_ptr() == c.data_ptr()   # False
```

`as_strided(size, stride, storage_offset)` 是对该模型最底层的暴露：给定期望的 `size/stride/offset` 直接构造视图，可用于实现滑窗等技巧，但**极易越界**，越界访问是未定义行为。

### 3. 连续性、stride 计算与 memory_format

**连续（contiguous）** 指元素在 storage 中按逻辑顺序紧密排列。对行优先连续张量：

```
stride[k] = prod(shape[k+1:])
```

例如 `shape=(3,4,5)` 的连续 stride 为 `(20,5,1)`。判定规则放宽为：所有 `size[k] != 1` 的维度满足上式即可（size=1 的维度 stride 可任意），这就是 `t.is_contiguous()` 的语义。

```python
x = torch.randn(2, 3, 4)
x.is_contiguous()                 # True
y = x.transpose(1, 2)             # (2,4,3)
y.shape, y.stride()               # (2,4,3), (12,1,4)
y.is_contiguous()                 # False
y.contiguous().is_contiguous()    # True（发生拷贝）
```

**memory_format** 是比“是否连续”更强的布局约定：

- `torch.contiguous_format`：标准行优先（NCHW）。
- `torch.channels_last`：逻辑形状仍是 NCHW，物理上按 NHWC 排布。对 4D 张量 `(N,C,H,W)`，channels_last 的 stride 为 `(H*W*C, 1, W*C, C)`。
- `torch.channels_last_3d`：5D 版本 `(N,C,D,H,W)` → NDHWC。
- `torch.preserve_format`：`.to()`/`.clone()` 等的默认，保留输入布局。

```python
x = torch.randn(1, 3, 8, 8)
xc = x.to(memory_format=torch.channels_last)
xc.is_contiguous()                                  # False
xc.is_contiguous(memory_format=torch.channels_last) # True
```

channels_last 对卷积在张量核心上的访存更友好 [待验证：具体加速比依赖版本、GPU 架构与 kernel 实现]。注意 `is_contiguous()` 只判断标准连续；判断 channels_last 必须显式传 `memory_format`。

### 4. broadcast 规则与 expand

广播从**尾部维度右对齐**比较，逐维满足下列之一即可：

1. 两维相等；
2. 其中一维为 1；
3. 其中一维不存在（视为 1）。

结果的每一维取两者中的较大值。实际实现是把 size=1 的维度用 **stride=0** 扩展，因此 `expand` 不复制数据：

```python
a = torch.randn(3, 1, 5)      # stride (5, 5, 1)
b = torch.randn(   4, 5)      # stride (5, 1)
c = a + b                      # -> (3, 4, 5)
e = a.expand(3, 4, 5)         # stride (5, 0, 1)，不复制
```

stride=0 的关键推论：**在 expand 得到的张量上做原地写入是错误**，因为多个逻辑位置映射到同一内存地址。PyTorch 会报：

```
RuntimeError: unsupported operation: more than one element of the written-to
tensor refers to a single memory location. Please clone() the tensor before
performing the operation.
```

需要广播计算时优先让二元算子内部广播（无实体拷贝），而不是 `repeat`/`tile`（会真正复制）。

### 5. dtype 与 itemsize

常用 `dtype` 及其字节数（`element_size()`）：

| dtype | itemsize (bytes) | 说明 |
|---|---|---|
| `torch.bool` | 1 | 布尔 |
| `torch.uint8` | 1 | 无符号 8 位 |
| `torch.int8` | 1 | 有符号 8 位 |
| `torch.int16`/`torch.short` | 2 | |
| `torch.int32`/`torch.int` | 4 | 默认整数 dtype |
| `torch.int64`/`torch.long` | 8 | 索引默认 |
| `torch.float16`/`torch.half` | 2 | |
| `torch.bfloat16` | 2 | 8 位指数、7 位尾数 |
| `torch.float32`/`torch.float` | 4 | 默认浮点 dtype |
| `torch.float64`/`torch.double` | 8 | |
| `torch.complex64` | 8 | 两个 float32 |
| `torch.complex128` | 16 | 两个 float64 |
| `torch.float8_e4m3fn`、`torch.float8_e5m2` | 1 | 低精度训练/推理 [待验证：可用性依赖版本与硬件] |
| `torch.int4`/`torch.uint4` | 0.5（子字节打包） | 量化存储 [待验证] |

`float16` 与 `bfloat16` 都是 2 字节：前者指数 5 位、尾数 10 位（范围窄、精度高）；后者指数 8 位、尾数 7 位（范围与 `float32` 相同、精度低），因此更适合训练中以累加为主、怕溢出的场景。

内存占用估算：连续张量占用 `numel * itemsize` 字节，但**实际 storage 可能更大**：

- 视图的 storage 常大于 `numel * itemsize`；
- 分配器的缓存/对齐与最小分配粒度会放大实际显存占用；
- 切片后原张量仍被引用时，整块 storage 不会被释放（内存泄漏式占用）。

```python
x = torch.randn(1_000_000)      # float32
x.numel() * x.element_size()    # 4_000_000 bytes
x.untyped_storage().nbytes()    # 4_000_000（连续时相等）
y = x[1:2]                      # 视图，仅 1 个元素
y.untyped_storage().nbytes()    # 仍是 4_000_000
```

### 6. 类型提升（type promotion）

PyTorch 在二元算子中按类别提升 dtype，类别序：

```
bool < 整数(uint8/int8/.../int64) < 浮点(float16/bfloat16/float32/float64) < 复数
```

规则要点：

- **同类**：取更宽的类型（如 `int32 + int64 -> int64`；`float16 + float32 -> float32`）。
- **跨类**：取更高类别中的合适类型（如 `int32 + float32 -> float32`，`float32 + complex64 -> complex64`）。
- **Python 标量是“弱类型”**：与张量运算时通常不提升 dtype，只要求张量能表示该标量。例如 `torch.zeros(3, dtype=torch.float16) + 1.0` 结果仍是 `float16`。
- **0 维张量是“强类型”**：`torch.tensor(1.0)` 参与运算会按正常类型提升。

```python
torch.tensor([1, 2, 3]).dtype                 # torch.int64
(torch.tensor([1, 2, 3]) + 1.5).dtype         # torch.float32
(torch.zeros(3, dtype=torch.float16) + 1.0).dtype  # torch.float16
torch.promote_types(torch.int16, torch.float32)    # torch.float32
```

整数除法陷阱：`torch.tensor([1,2,3]) / torch.tensor([2,2,2])` 得 `float32`（`/` 是 true division）；要整除用 `//`。整数张量**不能** `requires_grad=True`（只允许浮点/复数）。

### 7. 设备语义与张量搬运

`device` 形如 `'cpu'`、`'cuda'`、`'cuda:0'`、`'mps'`，以及特定后端的 `'musa'` 等。默认设备可用 `torch.set_default_device`、`torch.set_default_dtype` 设置。

搬运 API：

```python
x = torch.randn(3)
x.to('cuda')          # 拷贝到 GPU
x.to('cuda', torch.float16)  # 同时改设备与 dtype
x.cuda()              # 等价于 x.to('cuda')
x.cpu()               # 回到主机
x.to(torch.float64)   # 只改 dtype
```

关键语义：

- `.to()` 在**设备与 dtype 都不变**时默认返回 `self`（无拷贝），除非 `copy=True`。
- `.to()` 返回新张量，不原地修改；要原地迁移需重新赋值 `x = x.to(...)`。
- 不同设备的张量参与同一算子会报错，必须在同一设备上。
- `.numpy()` 要求 CPU 且 **不参与 autograd**：GPU 张量会抛错，`requires_grad=True` 的张量需先 `.detach()`。
- `torch.from_numpy(a)` 与 `.numpy()` 是零拷贝，改一个另一个会变；`torch.tensor(a)` 总是拷贝。

### 8. pin_memory 与异步拷贝

**页锁定（pinned / page-locked）内存**是主机上一块不会被换出、支持 DMA 直接访问的内存。要点：

- 只有 CUDA/加速器场景有意义；`pin_memory=True` 在纯 CPU 环境不会带来收益。
- 从 pinned 主机内存发起 `H2D` 拷贝可以**异步**（`non_blocking=True`），从而与计算 overlap。
- 从普通可分页内存（pageable）拷贝到 GPU 时，驱动通常需要内部先拷到临时 pinned 缓冲区，`non_blocking= True` 也往往退化为同步。

```python
x = torch.randn(1024, pin_memory=True)   # 或 x.pin_memory()
x_gpu = x.to('cuda', non_blocking=True)
# 使用前需确保拷贝完成
torch.cuda.synchronize()
```

`DataLoader(pin_memory=True)` 在 worker 生成 batch 后将其放入 pinned 内存，从而让主进程的 H2D 拷贝可异步。注意 `non_blocking=True` 只是**允许**异步，正确性依赖使用者用 `torch.cuda.synchronize()` 或 stream 语义做同步，否则会出现“读到未拷完数据”的隐性 bug。显式大规模 pin 会占用不可换出的主机内存，过量会导致系统 OOM [待验证：具体阈值依赖机器配置]。

### 9. 非连续张量上的算子行为

- 大部分逐元素与归约算子支持任意 stride，可避免显式拷贝，但**访存效率**下降（相邻逻辑元素物理上不相邻，合并访存变差）。
- 部分算子（尤其需要按连续块处理的 CUDA kernel、`view`、某些卷积/矩阵乘的前处理）内部会调用 `.contiguous()`，产生**隐式拷贝**。这类拷贝在 profiling 中表现为额外的 memory copy kernel，是常见性能暗坑。
- `view` 要求“目标形状与现有 stride 兼容”，不兼容时报：

```
RuntimeError: view size is not compatible with input tensor's size and stride
(at least one dimension spans across two contiguous subspaces). Use .reshape(...) instead.
```

- `reshape` 是安全替代：能视图就视图，否则自动复制。

### 10. 布局对性能的定性模型

- **合并访存**：连续、最后一维连续的张量最容易让相邻线程访问相邻地址，从而合并成更少的内存事务。
- **channels_last**：卷积在 NHWC 下每个通道的 C 维连续，便于现代 GPU 以向量化/张量核心方式读取；NCHW 在部分框架与旧 kernel 上需要额外 transpose [待验证：收益强依赖硬件与后端]。
- **stride=0 广播**：只读场景零成本；一旦触发原地写会报错。
- **对齐**：分配器会做对齐；某些 kernel 要求 16B/128B 对齐以获得最佳带宽 [待验证]。

## 常见陷阱与反例

1. **对转置结果直接 `view`**：
   ```python
   x = torch.randn(3, 4)
   x.t().view(-1)        # RuntimeError
   x.t().reshape(-1)     # 可用，内部 copies
   x.t().contiguous().view(-1)  # 显式拷贝
   ```
2. **认为 `reshape` 一定不拷贝**：它只在兼容时是视图；否则静默复制，可能带来显存峰值。
3. **对 expand 结果原地写**：触发 “single memory location” 报错；需 `.clone()` 或 `.contiguous()` 后再写。
4. **切片后原张量未释放导致“假泄漏”**：`small = big[0]` 会让整个 `big` 的 storage 存活。
5. **高级索引与基础索引混淆**：`x[:, 0]` 是视图，`x[:, [0]]` 是拷贝；后者改原张量不影响，前者影响。
6. **`to(device)` 忘记接收返回值**：`x.to('cuda')` 不会改变 `x`，必须 `x = x.to('cuda')`。
7. **GPU 上调用 `.numpy()`**：抛 `TypeError: can't convert cuda:0 device type tensor to numpy`。先 `.cpu()`。
8. **对 `requires_grad=True` 的张量 `.numpy()`**：报 “Can't call numpy() on Tensor that requires grad”，需 `.detach().numpy()`。
9. **Python float 标量误以为会提升 dtype**：`float16` 张量 `+1.0` 仍是 `float16`，可能溢出/丢精度。
10. **`torch.tensor(np_array)` 误以为零拷贝**：它总是复制；零拷贝要用 `torch.from_numpy`/`torch.as_tensor`。
11. **stride 单位是元素不是字节**：手工算字节偏移要乘 `element_size()`。
12. **`numel * itemsize` 当作显存占用**：视图、分配器缓存、对齐会放大实际占用。
13. **`float16` 直接做累加/归约导致溢出或精度塌陷**：训练常在 `float32`/`float64` 中累加。
14. **混用 `'cuda'` 与 `'cuda:0'`**：多卡时前者取当前设备，可能与本意不同。
15. **`non_blocking=True` 忘记同步**：异步拷贝未完成就使用数据，结果不确定。

## 与其他知识域的连接

- **K02 autograd**：视图操作是 autograd 图中的“同一数据、不同坐标”的边；`view`/`transpose` 的梯度回传需按 stride 逆向映射。对布局的原地修改会递增版本计数，backward 时若发现依赖张量版本变化会报错（详见 K02）。
- **K03 Module**：`Parameter`/buffer 的 `dtype`/`device`/`memory_format` 决定 `Module.to()` 的迁移结果与显存占用；`channels_last` 通常在模块级设置并 propagate 到参数。
- **K04 数据管道**：`pin_memory`、`non_blocking`、worker 与主进程间张量的序列化/共享页（file_system/共享内存策略）共同决定搬运是否成为瓶颈。
- **K06 AMP**：dtype 提升规则与 `autocast` 的 dtype 选择（`float16` vs `bfloat16`）直接决定数值稳定性。
- **K09/K11 性能**：布局与连续性决定访存合并、是否需要隐式 `contiguous` 拷贝，是 profiling 中常见的 kernel 来源。
