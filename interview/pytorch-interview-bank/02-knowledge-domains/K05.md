# K05 优化器、训练循环与数值稳定性

## 范围

forward/backward、梯度累积、参数组、scheduler、loss 和恢复。

## 领域边界

本知识域覆盖"一次参数更新"及其周边：训练循环的顺序契约、`torch.optim` 优化器更新公式（SGD、Adam、AdamW 等）、参数组、学习率调度器、梯度裁剪与累积、优化器状态的生命周期，以及性能相关的 `foreach`/融合实现。

纳入范围的是这些机制对收敛、数值稳定与恢复正确性的影响。明确排除：

- autograd 引擎与计算图本身（叶张量、`retain_graph`、`detach` 语义）属于 K02。
- `nn.Module` 的参数注册与 `state_dict` 结构属于 K03；本域只讨论优化器状态如何序列化。
- 混合精度的 `autocast`/`GradScaler` 细节单独在 K06，本域只讨论"optimizer 与 scaler 的交互顺序"。
- 分布式优化器（`ZeroRedundancyOptimizer`、DDP 梯度同步、FSDP）属于 K07。
- 具体调度策略的调参经验属于工程实践，不属于机制边界。

判据：若问题涉及"参数如何根据梯度改变"或"更新步如何编排"，属于本域；若涉及"梯度如何被计算出来"，属于 K02。

## 核心机制

### 训练循环的标准顺序

一个最小正确循环的固定顺序：

```python
model.train()
for x, y in loader:
    optimizer.zero_grad(set_to_none=True)   # 1. 清空/置空旧梯度
    out = model(x)                          # 2. forward
    loss = criterion(out, y)                # 3. loss
    loss.backward()                         # 4. 反向，写入 .grad
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)  # 4.5 裁剪
    optimizer.step()                        # 5. 更新参数
    scheduler.step()                        # 6. 推进学习率（多数调度器）
```

顺序错误的典型后果：

- **忘 `zero_grad`**：梯度跨迭代累加，等价于梯度累积但无 `1/N` 缩放，更新量被放大。
- **裁剪放在 `step` 之后**：裁剪对本次更新无效，只影响下一次。
- **`scheduler.step()` 放在 `optimizer.step()` 之前**：学习率比预定晚/早一步，产生 off-by-one（不同调度器约定不同）。
- **`optimizer.step()` 放在 `loss.backward()` 之前**：`.grad` 为空或为旧值。

### 优化器更新公式

记参数 `p`、梯度 `g`、学习率 `lr`、权重衰减 `wd`、时间步 `t`。

**SGD**（含 momentum/dampening/nesterov）：

```text
if wd != 0: g = g + wd * p                 # L2 正则，耦合进梯度
if momentum != 0:
    if buf is None: buf = g
    else:           buf = momentum * buf + (1 - dampening) * g
    d = g + momentum * buf if nesterov else buf
else:
    d = g
p = p - lr * d
```

注意 `wd` 在 SGD 中是"加到梯度上"，因此与 momentum 相互作用（被 momentum 平滑）。

**Adam**（PyTorch 语义）：

```text
if wd != 0: g = g + wd * p                 # 注意：这是耦合 L2
m = beta1 * m + (1 - beta1) * g            # 一阶矩
v = beta2 * v + (1 - beta2) * g^2          # 二阶矩
m_hat = m / (1 - beta1^t)                  # 偏差修正
v_hat = v / (1 - beta2^t)
p = p - lr * m_hat / (sqrt(v_hat) + eps)
```

- `betas=(0.9, 0.999)`、`eps=1e-8` 为默认。
- 偏差修正解决初始时刻 `m`、`v` 被拉向 0 的问题：`t` 从 1 开始。
- `amsgrad=True` 时额外维护 `v_max = max(v_max, v)` 并用 `v_max` 做分母。

**AdamW**：解耦权重衰减。梯度里**不加** `wd*p`，而是单独衰减参数：

```text
m = beta1*m + (1-beta1)*g
v = beta2*v + (1-beta2)*g^2
m_hat = m/(1-beta1^t); v_hat = v/(1-beta2^t)
p = p - lr * ( m_hat/(sqrt(v_hat)+eps) + wd * p )
```

区别（面试高频）：Adam 的 `weight_decay` 是 L2，与自适应分母耦合，衰减被逐参数缩放；AdamW 的解耦衰减对所有参数以 `lr*wd` 均匀作用，正则效果与学习率解耦。详见 [Loschilov & Hutter, 2017]。

**其他**：`RMSprop`（用二阶矩均方根归一）、`Adagrad`（累积平方梯度、学习率单调衰减）、`LBFGS`（拟牛顿、可多次 `closure`）。`SparseAdam` 仅支持稀疏梯度。

### 参数组（param_groups）

`optimizer = SGD([{'params': backbone.parameters(), 'lr': 1e-4},
                  {'params': head.parameters(), 'lr': 1e-3}], momentum=0.9)`

- 每组可有独立 `lr`、`weight_decay`、`momentum` 等超参。
- `optimizer.param_groups` 是可变列表；运行期改 `group['lr']` 即可手工调参（调度器正是这么做）。
- 常见做法：对 `bias` 与 `norm` 参数设 `weight_decay=0`。
- 失败模式：把同一个参数重复加入多个组 → 每步被更新多次且动量状态不一致；`add_param_group` 在训练中途调用会立即生效但状态从零开始。

### 学习率调度器

调度器只修改 `param_groups` 中的 `lr`（或动量等），不参与更新公式。常见：

- `StepLR(step_size, gamma)`：`lr = base * gamma^(epoch // step_size)`。
- `MultiStepLR(milestones, gamma)`：每到 milestone 乘一次 `gamma`。
- `ExponentialLR(gamma)`：`lr = base * gamma^epoch`。
- `CosineAnnealingLR(T_max, eta_min)`：`eta_min + (base-eta_min)*(1+cos(pi*T_cur/T_max))/2`。
- `OneCycleLR(max_lr, total_steps)`：单周期超收敛，先线性升温到 `max_lr`，再余弦/线性降到 `eta_min`；**按 step 调用**。
- `LambdaLR(fn)`、`MultiplicativeLR(fn)`：任意函数。
- `ReduceLROnPlateau(metric)`：由指标触发，`mode`/`patience`/`factor`，**不是**按 epoch 盲调；需 `scheduler.step(val_loss)`。
- `CosineAnnealingWarmRestarts(T_0, T_mult)`：带热重启。

约定与陷阱：

- epoch 级调度器一般放在 `optimizer.step()` 之后；step 级调度器（`OneCycleLR`）放在每个 iteration。混用会导致步数错配。
- `LambdaLR`/`MultiplicativeLR` 的 `last_epoch` 语义决定第 0 步是否已经改变 lr，跨框架移植时常有 off-by-one。
- 断点续训必须同时恢复 `optimizer` 与 `scheduler` 的 `state_dict`，否则 `last_epoch`/`base_lrs` 不连续。

### 梯度裁剪

```python
torch.nn.utils.clip_grad_norm_(parameters, max_norm=1.0, norm_type=2.0)
torch.nn.utils.clip_grad_value_(parameters, clip_value=0.5)
```

`clip_grad_norm_` 计算所有参数梯度的全局范数 `total_norm`（默认 L2），若 `total_norm > max_norm`，则乘以 `max_norm / (total_norm + 1e-6)`。它是**对整个参数集合**做一致缩放，而非逐张量裁剪。`clip_grad_value_` 逐元素 clamp 到 `[-v, v]`。

- 必须在 `backward()` 之后、`step()` 之前。
- 与 AMP 合用时必须先 `scaler.unscale_(optimizer)` 再裁剪，否则裁剪作用于被放大的梯度（见 K06）。

### 梯度累积

当显存放不下目标 batch 时，用多个 micro-batch 累积：

```python
for i, (x, y) in enumerate(loader):
    loss = criterion(model(x), y) / accum_steps
    loss.backward()
    if (i + 1) % accum_steps == 0:
        optimizer.step()
        optimizer.zero_grad(set_to_none=True)
        scheduler.step()
```

等价性边界（易错）：

- **数学上**等价于大 batch 的梯度求和，前提是损失对每个样本是均值且按 `1/accum_steps` 缩放。
- **BatchNorm** 不成立：BN 用每个 micro-batch 的统计量，与真正大 batch 的统计量不同。
- **Dropout/RNG**：等价性也依赖随机性处理；缩放 loss 只缩放梯度，不改变前向噪声。
- **DDP**：默认每次 `backward` 都会 all-reduce 梯度，需要 `model.no_sync()` 包住非末尾的 micro-batch，否则既慢又错（见 K07）。
- 调度器若按 step 触发，累积时 step 数变为 `total_iters/accum_steps`，`OneCycleLR` 的 `total_steps` 必须按 optimizer step 计。

### optimizer state 的结构与生命周期

`optimizer.state_dict()` 返回：

```python
{
  'state': {param_id: {'momentum_buffer': ..., 'exp_avg': ..., 'exp_avg_sq': ..., 'step': ...}},
  'param_groups': [{'lr':..., 'weight_decay':..., 'params': [param_id, ...]}, ...]
}
```

- `state` 以参数在 `param_groups` 中的索引为键；`load_state_dict` 依赖参数顺序与数量一致。
- `state` 通常是惰性创建的：首次 `step()` 才分配动量/矩缓冲。
- 保存/加载必须与模型 `state_dict` 配对：先构建模型并（可选）移动到设备，再 `optimizer.load_state_dict`，最后可 `to(device)` 迁移状态以便 GPU 上继续训练。

### foreach 与融合优化器

`torch.optim` 的 `foreach`/`fused` 是性能路径：

- `foreach=True`：把一组参数的操作批量化（内部用 `torch._foreach_*`），减少 Python/算子启动开销。
- `fused=True`：用单个融合 CUDA kernel 完成更新，通常最快；约束是全部参数在同一 CUDA 设备、同 dtype，且不支持稀疏梯度；CPU 上不可用。
- 二者语义应与默认逐参数路径一致；不一致属实现 bug，遇到需上报。
- 收益幅度随参数量、dtype、硬件变化，必须实测 [待验证]。

### 混合精度下 optimizer 与 scaler 的顺序

```python
with autocast():                     # 见 K06
    loss = criterion(model(x), y)
scaler.scale(loss).backward()        # 梯度被放大 S 倍
scaler.unscale_(optimizer)           # 还原为真实梯度（供裁剪）
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
scaler.step(optimizer)               # 若发现 inf/nan 则跳过本次 step
scaler.update()                      # 动态调整 S
optimizer.zero_grad(set_to_none=True)
```

关键点：`scaler.step` 会检查梯度是否含 inf/nan；若含则**不更新参数**并降低 S，因此调用方无需手工判断。`unscale_` 每个 optimizer 每个 iteration 只能调用一次；重复调用会报错。若不裁剪，可省去显式 `unscale_`，由 `scaler.step` 内部处理。

### 优化器选型速查

| 优化器 | 状态大小 | 适用场景 | 关键超参 | 易错点 |
|---|---|---|---|---|
| SGD(+momentum) | 每参数 1 buffer | 视觉、有良好调参预算 | `lr`、`momentum`、`nesterov` | wd 与 momentum 耦合 |
| SGD(+nesterov) | 每参数 1 buffer | 同上，常更优 | 同上 | dampening 语义 |
| Adam | 每参数 2 buffer | 通用、稀疏/Transformer | `betas`、`eps` | wd 是耦合 L2 |
| AdamW | 每参数 2 buffer | Transformer、大模型 | `weight_decay` 解耦 | 误以为是 L2 |
| RMSprop | 每参数 1 buffer | RNN、非平稳目标 | `alpha`、`momentum` | 学习率敏感 |
| Adagrad | 每参数 1 累加 buffer | 稀疏特征 | `lr` | lr 单调衰减到 0 |
| LBFGS | 历史 + 线搜索 | 小规模、二阶拟合 | `history_size` | 需 `closure` |

选择依据核心是：参数规模、稀疏性、是否需要自适应步长、正则如何施加。Adam 系内存是 SGD 的 2 倍（一阶+二阶矩），大模型需权衡。

### 数值稳定性

优化器的稳定性由梯度与更新量共同决定：

- **梯度爆炸**：`total_norm` 持续增大，参数一步跨太大 → 裁剪（K05 上文）或调小 `lr`。
- **梯度消失**：低精度下溢、`sigmoid`/深链乘 → 换激活/归一化、用 AMP 缩放。
- **Adam 分母为 0**：`v_hat=0` 时靠 `eps` 兜底；`eps` 太小在 fp16 下会失效。
- **二阶矩精度**：`exp_avg_sq` 若以 fp16 存储，长期累积误差大，通常保持 fp32。
- **loss 直接 NaN**：`log(0)`、除零、`sqrt(负数)`；用 `log_softmax`/`logsumexp` 数值稳定形式。
- **混合精度叠加**：fp16 需要 `GradScaler`（K06）；bf16 通常不需要。

诊断顺序：先定位是前向 NaN（在 loss 处查 `torch.isnan`）还是反向 NaN（在各层 `grad` 查），再决定是数据、数值还是 lr 问题。

### closure 与 LBFGS

LBFGS 及部分二阶方法需要 `closure`：一个"清梯度→前向→loss→反向"的可重入函数。

```python
def closure():
    optimizer.zero_grad()
    loss = criterion(model(x), y)
    loss.backward()
    return loss
optimizer.step(closure)
```

- `closure` 内不要调用 `scheduler.step()`。
- LBFGS 内部可能多次调用 `closure`，中间会暂存/恢复参数；这与 `foreach`/AMP 的假设不同，通常需 `autocast(enabled=False)`。
- 大多数 Adam/SGD 场景无需 closure；`ReduceLROnPlateau` 的 `step` 不是 closure。

### 关键超参速查

| 超参 | 常见默认 | 作用 | 调整方向 |
|---|---|---|---|
| `lr` | 依赖优化器 | 步长 | 过大震荡/NaN，过小不收敛 |
| `momentum` | 0.9 | 一阶平滑 | 增大更平滑但更易过冲 |
| `weight_decay` | 0 | 正则 | 增大抑制过拟合 |
| `betas` | (0.9,0.999) | 矩衰减 | 增大更平滑、响应更慢 |
| `eps` | 1e-8 | 数值兜底 | fp16 下考虑增大 |
| `max_norm` | 1.0 | 裁剪阈值 | 小则更稳、可能欠拟合 |
| `accum_steps` | 1 | 梯度累积 | 生效时损失需除以此值 |

### 训练循环诊断清单

1. 打印首个 iteration 的 `loss`、`grad` 的 `total_norm`、当前 `lr`，确认非 NaN、非全零。
2. 检查 `zero_grad` 位置与 `set_to_none` 语义是否与累积逻辑一致。
3. 单 batch 过拟合测试：固定一个 batch，关正则，看能否把 loss 打到接近 0——验证前向/反向/优化器无 bug。
4. 确认 scheduler 的调用频率（epoch/step）与 `total_steps` 一致。
5. AMP 场景确认 `unscale_`/`step`/`update` 顺序且 `unscale_` 未重复。
6. 续训时对比"连续训练"与"中断恢复"的 loss 轨迹，验证状态完整性。
7. 用 `foreach`/`fused` 前后对比数值一致性，排除实现差异。

## 常见陷阱与反例

| 陷阱 | 症状 | 根因 / 修正 |
|---|---|---|
| 忘 `zero_grad` | loss 爆炸、梯度累加 | 每步清梯度；`set_to_none=True` |
| 裁剪在 `step` 之后 | 裁剪无效 | 移到 backward 与 step 之间 |
| scheduler.step 次序错 | lr 曲线整体偏移一步 | 明确 epoch 级/step 级约定 |
| Adam 当 AdamW 用 | 正则效果与预期不符 | `weight_decay` 语义不同，改用 `AdamW` |
| 参数重复入组 | 单步多次更新、状态错乱 | 确保参数只出现一次 |
| 梯度累积未缩放 | 有效学习率放大 N 倍 | `loss / accum_steps` |
| 梯度累积 + BN | 与大 batch 不等价 | 换 SyncBN 或接受差异 |
| 梯度累积 + DDP | 重复 all-reduce、报错或变慢 | `no_sync()` 包非末尾 micro-batch |
| OneCycleLR 按 epoch 调用 | 总步数错、收敛差 | 按 iteration 调用并给 `total_steps` |
| AMP 下先裁剪后 unscale | 裁剪作用在放大梯度上 | `scaler.unscale_` 后再裁剪 |
| 恢复只存模型 | 续训 lr/动量从零重置 | 保存 optimizer+scheduler+scaler+step |
| 用 SGD 期望 AdamW 的泛化 | 结果不符 | 先确认优化器选择 |
| `foreach`/`fused` 混 dtype | 运行期报错 | 统一 dtype/device，或退回默认路径 |

反例：把 `scheduler = CosineAnnealingLR(opt, T_max=epochs)` 建在梯度累积循环之外、却按 `optimizer.step()` 次数推进——由于每次 step 只行进一个 micro-batch，`T_max` 应改为 optimizer 总步数而非 epoch 数，否则余弦在第一个 epoch 内就走完。
