# K12 测试、调试、故障排查与工程治理

## 范围

oracle、证据、日志、故障注入、回滚、质量门禁和事故复盘。

## 领域边界

**在本域内**

- 测试：单元测试、数值梯度校验（`gradcheck`）、确定性测试、回归/golden 测试、property/fuzz 测试。
- CI 集成：版本矩阵、硬件矩阵、门禁、标记与跳过、覆盖率、flake 治理。
- 类型检查：`mypy`/`pyright`、类型 stub、TorchScript 类型注解。
- 代码审查：形状/dtype/device 契约、原地写、stream、数值稳定、错误处理、BC。
- 版本升级兼容性：BC 策略、弃用、默认值变化、升级与回滚流程。
- 实验追踪：种子、配置、环境、制品、血缘、可复现清单。
- 调试与故障排查：异常检测、日志与追踪、故障注入、根因定位、事故复盘。

**在本域外**

- 具体框架的内部测试实现（可作为参考）、产品级 SRE（除非影响 PyTorch 行为）。
- 模型精度/业务指标本身（本域的 oracle 针对**代码契约**，而非模型效果）。
- 各知识域的具体机制（K01–K11），本域是贯穿它们的横向治理层。

**边界判定规则**

- 问题是“如何证明某行为正确 / 如何防止回退 / 如何定位失败 / 如何安全升级”——是则本域。
- 问题是“某机制如何工作”——归对应 K01–K11。

## 核心机制

### 1. 测试结构与 oracle

**oracle** 是判断“正确”的权威依据，可以是精确值、golden 输出、解析关系或数值容差比较。测试要断言**性质**而非“没崩溃”：

```python
import torch, pytest

# 参数化：边界形状（空张量、单元素、广播）
@pytest.mark.parametrize("shape", [(2, 3), (0, 4), (5, 1)])
def test_softmax_sums_to_one(shape):
    x = torch.randn(*shape)
    y = torch.softmax(x, dim=-1)
    if x.numel() and x.size(-1):
        assert torch.allclose(y.sum(-1), torch.ones(shape[:-1]))
```

- `torch.testing.assert_close(a, b, rtol=..., atol=..., equal_nan=...)` 是张量比较标准；旧 `assert_allclose` 已弃用。
- 测试辅助：`torch.testing.make_tensor`（构造覆盖 dtype/device 的输入）、`torch.testing.suppress_warnings`。
- 测试分层：单元（单算子）、集成（模块/流程）、回归（golden）、property-based（如 hypothesis）、fuzz。
- 容差要按 dtype 选定；比较前固定 `dtype`/`device`，避免隐式提升掩盖差异。
- 每个断言都要能在实现出错时失败：先让测试在“错误实现”下变红，再让正确实现变绿。

### 2. 数值梯度校验

`torch.autograd.gradcheck` 用中心差分与解析梯度比较：

- 数值梯度：`(f(x+εe) - f(x-εe)) / (2ε)`，截断误差 `O(ε²)`，舍入误差 `O(ε_mach/ε)`。
- 判定：`|analytic - numeric| ≤ atol + rtol · |numeric|`；随机函数用 `nondet_tol`。
- 要求 `float64` 输入，否则误差过大导致假失败；容差不合理会掩盖真 bug。

```python
def test_custom_op_grad():
    x = torch.randn(5, dtype=torch.float64, requires_grad=True)
    assert torch.autograd.gradcheck(MyOp.apply, (x,), eps=1e-6, atol=1e-5, rtol=1e-3)
    assert torch.autograd.gradgradcheck(MyOp.apply, (x,))   # 需要二阶导时
```

- `torch.autograd.functional.jacobian`/`vjp`/`jvp` 提供额外 oracle；`torch.func.jacrev`/`jacfwd` 也是常用对照。
- forward-mode 校验用 `torch.autograd.forward_ad` 与 `jvp`。

### 3. 确定性与可复现性测试

```python
def set_seed(seed: int):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)

torch.use_deterministic_algorithms(True)          # 无确定性实现的算子会报错
# 需设环境变量 CUBLAS_WORKSPACE_CONFIG=:4096:8（CUDA>=10.2）
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

- DataLoader 多进程：用 `worker_init_fn` 和 `generator` 为每个 worker 设种子，否则批顺序/增广不确定。

  ```python
  g = torch.Generator().manual_seed(0)
  loader = DataLoader(ds, shuffle=True, generator=g,
                      num_workers=4, worker_init_fn=lambda w: set_seed(0 + w))
  ```

- 检查点要保存 RNG 状态（`torch.get_rng_state`、`torch.cuda.get_rng_state_all`）与 scaler 状态，才能续训复现。
- 确定性测试：同种子跑两次 → 逐位或 `assert_close` 一致；不同种子 → 结果不同（否则说明该变化未被使用）。
- 注意：确定性模式会禁用/替换部分非确定 kernel，可能带来性能回退 **[待验证，具体幅度]**；`warn_only=True` 只警告不报错，适合渐进迁移。

### 4. 回归与 golden 测试

- **数值 golden**：保存期望张量/指标，用容差比较；golden 要版本化，更新需走评审并记录原因。
- **结构 golden**：断言图结构（op 数量、graph break 数、FX 图快照），防止编译/导出行为回退。
- **性能 golden**：延迟/吞吐阈值，但受硬件与负载影响，须固定机器、warmup、取中位数，结果标 `[待验证]`。

```python
def test_forward_golden():
    out = model(INPUT)
    expected = torch.load("golden/out.pt")
    torch.testing.assert_close(out, expected, rtol=1e-4, atol=1e-5)
```

反模式：为了让测试通过而**盲目更新 golden**（掩盖回归）；应先在固定输入上确认差异来源，再决定是修代码还是更新基线。

### 5. CI 集成

- **矩阵**：Python 版本 × PyTorch 版本（最低支持版本与最新/夜间）× CPU/GPU。仅测最新会漏掉最低版本兼容问题。
- **门禁顺序**：lint → 类型检查 → 单元测试 → 集成测试 → （可选）性能回归。

```yaml
# GitHub Actions 示意
jobs:
  test:
    strategy:
      matrix:
        python: ["3.10", "3.12"]
        torch: ["min-supported", "latest"]
    steps:
      - uses: actions/checkout@v4
      - run: pip install -e ".[dev]"
      - run: ruff check . && black --check .
      - run: mypy src
      - run: pytest -m "not slow" --cov=src --cov-fail-under=85
```

- **标记与跳过**：`pytest -m "not slow"`；`@pytest.mark.skipif(not torch.cuda.is_available())`、`@requires_cuda` 等装饰器；无 GPU 时优雅跳过而非失败。
- **覆盖率**：设阈值防裸奔，但覆盖率≠正确性，需与 oracle 结合。
- **flake 治理**：隔离重试、记录不稳定性、sharding；不稳定性本身是缺陷信号。
- **环境固定**：容器/镜像钉版本，减少“在我机器上能过”。

### 6. 类型检查

- `mypy`/`pyright` + torch 类型 stub（`*.pyi`）；`torch.Tensor`、`torch.dtype`、`torch.types`（如 `Number`）、`Callable`。

  ```toml
  # pyproject.toml（示意）
  [tool.mypy]
  disallow_untyped_defs = true
  no_implicit_optional = true
  warn_unused_ignores = true
  ```

- 严格度配置应逐步提高，避免全用 `Any` 绕过。
- TorchScript 注解（`@torch.jit.script`）是另一套静态检查：类型不匹配在编译期报错，适合脚本化模块。
- 局限：高度动态的 Python、装饰器与元编程难被精确建模，需局部放宽并注释原因。

### 7. 代码审查要点

- **契约**：函数是否文档化 shape/dtype/device、取值范围、是否原地修改、是否连续。
- **原地与视图**：`in-place` 是否破坏 autograd 版本计数；返回值是否与输入共享存储（别名）。
- **设备与流**：CUDA 代码是否有 device guard、是否在当前流启动、是否检查 launch 错误。
- **数值稳定**：除零/sqrt 的 `eps`、`log-sum-exp`、softmax 稳定性、混合精度下溢出。
- **autograd**：自定义前反向是否 `gradcheck` 通过；`detach` 是否正确。
- **推理路径**：eval 是否用 `no_grad`/`inference_mode`；是否误用 `empty_cache` 当 OOM 修复。
- **安全与 BC**：`weights_only` 加载；公共 API 变更是否走弃用流程。
- 反模式：审查只盯风格不盯契约；改动默认值时未评估下游影响。

### 8. 版本升级兼容性

- **BC 承诺**：公共 API 与 `state_dict` 键尽量稳定；`_` 前缀为私有，可任意变化。
- **典型升级风险**：`torch.load` 的 `weights_only` 默认收紧、默认 dtype、`torch.load` 行为、`torch.export`/`torch.compile` API 演进、弃用 API 移除、RNG 行为变化、`state_dict` 键变化 **[均待验证，具体版本]**。
- **升级流程**：钉住版本 → 跑 golden + 确定性 + 兼容测试 → 对比输出与键 → canary → 保留回滚。
- **版本探测**：`torch.__version__`、`torch.version.cuda`、`torch.backends.cudnn.version()`、`torch.__config__.show()`，记录进环境清单。

### 9. 实验追踪

- 必须记录：配置/超参、代码版本（git commit + dirty diff）、环境（`torch.__config__.show()`、依赖 `pip freeze`）、种子、数据集/模型制品哈希、运行 ID。
- 可复现清单模板：

  ```
  run_id: 2026-10-13-001
  git_commit: abc1234 (dirty: no)
  torch: 2.14.0  cuda: 12.x  cudnn: 9.x  [待验证]
  seeds: {python: 0, numpy: 0, torch: 0, cuda: 0}
  data_hash: sha256:...
  config: {lr: 1e-3, bs: 64, ...}
  metrics: {val_loss: ..., acc: ...}
  artifacts: [ckpt.pt, logs/]
  ```

- 工具：`torch.utils.tensorboard.SummaryWriter`、wandb、MLflow；统一记录 metrics/logs/artifacts/lineage。
- 目的：任意一次运行可重建、可对比、可回滚；区分实验与生产制品。
- 反模式：只记 loss 曲线，缺配置与种子 → 不可复现。

### 10. 调试工具与故障排查流程

- **NaN/Inf 定位**：`torch.autograd.set_detect_anomaly(True)` 在前向中定位产生异常的算子（代价高，仅调试用）。
- **同步调试**：`CUDA_LAUNCH_BLOCKING=1` 让 kernel 报错在其调用点暴露；`TORCH_SHOW_CPP_STACKTRACES=1` 显示 C++ 栈。
- **日志**：`TORCH_CPP_LOG_LEVEL`、`TORCH_DISTRIBUTED_DEBUG`。
- **工具链**：`compute-sanitizer`（访存/竞态）、`nsys`（时间线）、`ncu`（kernel 计数）、PyTorch profiler（K09）。
- **流程**（与 `root-cause-analysis` 一致）：症状分层 → 假设树 → 最小复现与证据 → 根因 → 复发防护（加测试/断言）。
- **故障注入**：mock CUDA OOM、kill 某个 rank、注入延迟/丢包，验证降级与恢复路径。

**事故复盘模板**（对应 debugging-cases.md 的条目）：

```
现象：        DDP hang / 梯度为零 / OOM / compile 回退
直接原因：    如 collective 顺序不一致 / loss mask 全零
根因：        如不同 rank 分支导致通信错配
证据：        rank 日志、profiler trace、allclose 差异
止损：        回滚 / 降级 / 关闭某优化
复发防护：    新增 smoke test + 断言 + 告警
```

### 11. 测试类型、oracle 与工具速查

| 测试类型 | oracle | 典型工具 | 失败含义 |
|---|---|---|---|
| 单元 | 解析值/不变量 | `assert_close` | 算子实现错误 |
| 梯度 | 数值差分 | `gradcheck`/`gradgradcheck` | 反向公式错误 |
| 确定性 | 同种子一致性 | `use_deterministic_algorithms` | 引入非确定来源 |
| 回归 | golden | golden 文件 + 容差 | 行为漂移 |
| 结构 | op 数/graph break | FX 图快照 | 编译/导出回退 |
| 性能 | 阈值/中位数 | profiler + 基准 | 性能回退 `[待验证]` |
| property | 生成性质 | hypothesis | 边界未覆盖 |

property-based 示例（让测试自己找边界）：

```python
from hypothesis import given, strategies as st
from hypothesis.extra.numpy import arrays

@given(arrays(np.float32, shape=st.tuples(st.integers(0, 8), st.integers(1, 8))))
def test_softmax_range(a):
    y = torch.softmax(torch.as_tensor(a), dim=-1)
    assert torch.all(y >= 0) and torch.all(y <= 1)
```

测试替身与故障注入示例：

```python
def test_cuda_oom_handling(monkeypatch):
    def boom(*a, **k):
        raise torch.cuda.OutOfMemoryError("simulated")
    monkeypatch.setattr(torch.Tensor, "cuda", boom)   # 注入故障
    with pytest.raises(torch.cuda.OutOfMemoryError):
        train_step(device="cuda")
```

`torch.testing` 常用工具：`assert_close`、`make_tensor`、`suppress_warnings`；设备/平台分支可用 PyTorch 内部装饰器（如 `onlyCUDA`、`skipIfRocm`、`slowTest`）或自定义 `pytest.mark`。

## 常见陷阱与反例

1. **测试只断言“没报错”**：无 oracle，回归无法被发现。
2. **容差过松或过紧**：过松掩盖真 bug，过紧在正常数值噪声下假失败。
3. **gradcheck 用 float32**：误差过大，结论不可信。
4. **种子不全**：漏设 DataLoader worker / cuDNN，确定性测试间歇性失败。
5. **盲目更新 golden**：把回归“修”成通过，问题进入生产。
6. **CI 只跑最新版本**：最低支持版本兼容问题漏网。
7. **类型检查形同虚设**：到处 `Any`，mypy 无约束力。
8. **审查漏掉设备/流**：CUDA 代码默认流竞态，结果不确定。
9. **升级不做 BC 回归**：默认值静默变化导致线上行为漂移。
10. **用 `torch.cuda.empty_cache()` 治 OOM**：不解决峰值分配，只是治标。
11. **异常检测默认开启**：`set_detect_anomaly` 常开会让训练显著变慢 **[待验证，幅度]**。
12. **实验只记结果不记环境**：结论不可复现。
13. **性能测试不做 warmup/取中位数**：混入编译与冷启动噪声，误判回退。
