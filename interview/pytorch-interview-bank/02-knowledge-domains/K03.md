## 领域边界

本域聚焦“模型的结构、可学习状态与运行时状态如何被组织、遍历、保存和迁移”，即 `nn.Module` 这棵参数/模块树的管理机制。它回答：

1. 结构如何组织：`__setattr__` 如何把子模块和参数注册进 `_modules`/`_parameters`。
2. 状态如何分类：`Parameter`、buffer、普通属性三者的注册与迁移差异。
3. 状态如何持久化：`state_dict`/`load_state_dict` 的键、严格模式与赋值语义。
4. 模式如何切换：`train()`/`eval()` 对 dropout、BatchNorm 等的影响。
5. 如何观察与干预：`named_parameters`、hooks、`_apply`、参数共享。

本域**不负责**：

- 自动求导的图机制：`requires_grad`、`grad_fn`、backward 属 K02；本域只讲参数上 `requires_grad` 的配置与冻结。
- 优化器与训练循环：属 K05；本域只讲参数枚举与 `optimizer` 引用的一致性。
- 数据加载：属 K04。
- 分布式包装与模型并行切分：属 K07；本域只讲单进程内的模块树与状态语义。
- 序列化格式与跨框架导出：`torch.save`/`torch.export` 属 K10；本域聚焦 `state_dict` 语义本身。

与相邻域的接口：

- 依赖 K01：`Parameter`/buffer 是 Tensor，其 `dtype`/`device`/`memory_format` 由 `Module.to()` 统一迁移。
- 依赖 K02：`Parameter.requires_grad` 决定是否进入 autograd；`zero_grad` 与 `.grad` 的生命周期。
- 向 K05 输出：`model.parameters()` 生成的对象身份必须与 `optimizer` 创建时一致，否则更新失效。
- 向 K07 输出：`distributed` 的 `DDP` 包装依赖 `named_parameters` 顺序与 `state_dict` 一致性。
- 向 K10 输出：`state_dict` 是 checkpoint 与导出的事实标准格式。

## 先修知识

- **Python 对象模型**：`__setattr__`/`__getattr__`/`__call__`、继承、`OrderedDict`、`super().__init__()` 的作用。
- **K01 张量与布局**：`Parameter` 是 `Tensor` 子类；`.to()`、`.data`、`dtype`/`device` 语义。
- **K02 autograd**：`requires_grad`、`.grad`、`no_grad`。
- **训练基本流程**：forward → loss → backward → step → zero_grad。
- **序列化的直觉**：键→张量的映射如何跨进程/跨版本保持兼容。

## 核心机制

### 1. nn.Module 的树形结构与注册机制

`nn.Module` 的本质是**一个容器 + 一个钩子化的 `__setattr__`**。当你在 `__init__` 里给模块赋值属性时，`__setattr__` 会拦截：

- 值类型是 `nn.Parameter` → 存入 `self._parameters`（`OrderedDict`）。
- 值类型是 `nn.Module` → 存入 `self._modules`（`OrderedDict`）。
- 其他类型（含普通 `torch.Tensor`）→ 走普通属性（`object.__setattr__`），**不注册**。
- `nn.Module.__getattr__` 在普通属性找不到时，回退到 `_parameters`、`_modules`、`_buffers` 查找。

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()                 # 必须先调用
        self.fc = nn.Linear(4, 8)          # -> _modules['fc']
        self.weight = nn.Parameter(torch.zeros(8))  # -> _parameters['weight']
        self.register_buffer("steps", torch.zeros(1))  # -> _buffers['steps']
        self.plain = torch.zeros(3)        # 普通属性，不注册、不迁移
```

遍历 API（均基于这棵树）：

```python
model.children()            # 直接子模块
model.named_children()      # (name, module)
model.modules()             # 递归所有模块（含自身）
model.named_modules()       # (dotted_name, module)
model.parameters()          # 递归所有 Parameter
model.named_parameters()    # (dotted_name, param)
model.buffers() / model.named_buffers()
model.state_dict()          # 参数 + persistent buffer 的扁平字典
```

`named_parameters()` 默认 `remove_duplicate=True`，对**同一对象**（共享参数）只返回一次，名字取首次出现者。

### 2. Parameter vs buffer vs 普通属性

| 类别 | 注册方式 | 进 `parameters()` | 进 `state_dict` | 随 `.to()` 迁移 | 被优化器更新 |
|---|---|---|---|---|---|
| `nn.Parameter` | 赋值 / `register_parameter` | 是 | 是 | 是 | 是（若 `requires_grad`）|
| buffer | `register_buffer` | 否 | 是（`persistent=True`）| 是 | 否 |
| 普通 tensor 属性 | 直接赋值 | 否 | 否 | **否** | 否 |

要点：

- `Parameter` 默认 `requires_grad=True`，是“可学习权重”。
- buffer 是“随模型迁移但不学习”的状态，典型如 BatchNorm 的 `running_mean`/`running_var`/`num_batches_tracked`。
- buffer 的 `persistent=False` 表示**不写入 `state_dict`**（如某些临时统计），但仍随 `.to()` 迁移。
- 普通张量属性既不迁移也不持久化，是“模块迁移后发现张量还在 CPU”的常见根因。

容器类型：

- `nn.ModuleList`/`nn.ModuleDict`：正确注册一系列子模块；普通 `list`/`dict` 不会注册。
- `nn.ParameterList`/`nn.ParameterDict`：注册一组参数。

### 3. state_dict 与 load_state_dict 语义

`state_dict()` 返回一个 `OrderedDict[str, Tensor]`，键名是**点分路径**（如 `"features.0.weight"`），值是参数或 persistent buffer 的**引用**（不是拷贝）。

`load_state_dict(state_dict, strict=True, assign=False)` 的语义：

- **默认严格模式 `strict=True`**：当前模块与 `state_dict` 的键集合必须**完全一致**，否则报错。
  ```
  RuntimeError: Error(s) in loading state_dict for Net:
      Missing key(s) in state_dict: "fc.bias"
      Unexpected key(s) in state_dict: "fc.extra"
  ```
- `strict=False`：只加载匹配的键，返回 `_IncompatibleKeys(missing_keys, unexpected_keys)`，需自行检查。
- **默认写入是原地拷贝**：对每个参数执行 `param.data.copy_(loaded)`，保留原 `Parameter` 对象身份。因此**先建模型和优化器、再 load 是安全的**。
- `assign=True`：用 `state_dict` 里的张量**替换**模块中的张量（保留 `requires_grad` 等属性来自 state_dict 侧的元数据）。当 state_dict 由 `torch.load(..., map_location=...)` 得到且设备/dtype 需整体替换时有用 [待验证：行为随版本演进]。
- **键名必须匹配**：一旦你给子模块改名或用 `nn.Sequential` 改变层级，旧 checkpoint 可能加载失败。可用 `load_state_dict` 前重写键，或使用 `strict=False` 排查。

```python
sd = model.state_dict()
torch.save(sd, "ckpt.pt")
model2 = Net()
model2.load_state_dict(torch.load("ckpt.pt"))   # strict=True
```

### 4. train()/eval() 的语义

`train(mode=True)`/`eval()` **只做一件事**：递归设置每个子模块的 `self.training` 布尔标志。它**不改变**设备、dtype、`requires_grad` 或梯度记录。

各模块对 `self.training` 的反应：

- **Dropout**：`training=True` 时按概率 `p` 置零，并把保留的元素**除以 `1-p`**（inverted dropout，推理无需缩放）；`training=False` 时恒等。
- **BatchNorm**：`training=True` 时用当前 batch 的均值/方差归一化，并更新 `running_mean`/`running_var`（动量）、递增 `num_batches_tracked`；`training=False` 时用固定的 `running_mean`/`running_var`。
- 其他如 `Dropout2d`、部分正则化层同理；普通 `Linear`/`Conv` 不受模式影响。

```python
model.eval()
with torch.no_grad():
    out = model(x)     # 关闭 dropout、BN 用 running stats、不建图
```

### 5. to()/cuda()/float() 的迁移语义

`Module.to(device=None, dtype=None, non_blocking=False)`：

- 通过内部 `_apply(fn)` 递归访问 `_parameters` 与 `_buffers`，对每个张量调用 `fn`（如 `t.to(...)`）。
- 对参数**原地替换其数据**（`param.data = ...`），因此 `Parameter` 对象身份不变，`optimizer` 持有的引用仍然有效。
- **普通张量属性不会被迁移**（不在 `_parameters`/`_buffers` 中）。
- 返回 `self`，支持链式调用 `model.to(dev).to(dtype)`。
- `.cuda()`/`.cpu()`/`.float()`/`.double()`/`.half()` 都是 `.to(...)` 的便捷封装。

```python
model = model.to("cuda")
assert next(model.parameters()).is_cuda
```

自定义 `_apply` 或实现 `_apply` 未覆盖的张量（如存在自定义容器里）不会迁移，需手动处理。

### 6. Hooks

Hook 是注册在模块上的回调，用于观察/干预前向反向：

- `register_forward_pre_hook(fn(module, args))`：forward **前**执行，可原地改 `args`。
- `register_forward_hook(fn(module, args, output))`：forward **后**执行，可改 `output`。
- `register_full_backward_hook(fn(module, grad_input, grad_output))`：反向时触发。
- `register_backward_hook`：旧接口，语义有坑，建议用 `full_backward_hook`。
- `register_state_dict_pre_hook`/`_post_hook`、`load_state_dict_pre_hook` 等控制序列化前后。

Hook 返回一个 `handle`，调用 `handle.remove()` 注销；不注销会在长生命周期对象上**累积并泄漏**。全局 hook 有 `torch.nn.modules.module.register_module_forward_hook`。

### 7. 参数共享与权重绑定

把**同一个 `Parameter` 对象**赋给多个模块，即共享参数（weight tying，如输入/输出 embedding）：

```python
emb = nn.Embedding(vocab, d)
head = nn.Linear(d, vocab, bias=False)
head.weight = emb.weight          # 共享同一 Parameter
```

- `named_parameters()` 默认按对象身份去重，只出现一次。
- `state_dict()` 会出现**两个键指向同一张量**；`load_state_dict` 时两个键都可能被写入，需保证值一致或接受最后写入。
- 共享参数在 optimizer 中只应出现一次，避免重复更新。

### 8. 初始化与 apply

- `model.apply(fn)`：递归对每个子模块调用 `fn`，常用于统一初始化。
- `nn.init.*`（`kaiming_normal_`、`xavier_uniform_`、`zeros_`、`constant_`）对参数原地初始化。
- 初始化应在 load 之前的“从零训练”场景执行；load 会覆盖参数值。

### 9. 冻结与 requires_grad

- 冻结某层：`for p in layer.parameters(): p.requires_grad_(False)`。
- 冻结后 `optimizer` 若仍包含这些参数，它们因无 `.grad` 而不更新（但可能仍占显存/有额外开销）；更彻底是构造 optimizer 时过滤。
- `Module.requires_grad_(False)` 递归设置。
- 冻结参数**仍会参与 forward 计算**，只是不建 autograd 边；对推理/微调场景可省反向显存。是否真正省显存取决于算子是否仍需保存激活 [待验证]。

### 10. Module 的可调用协议与 forward

`nn.Module` 覆写了 `__call__`，因此 `model(x)` 并不直接等于 `model.forward(x)`：

- `__call__` 会依次触发 forward pre-hook、`forward`、forward hook，并处理一些编译/追踪相关的簿记。
- 因此**不要**在外部调用 `model.forward(x)`（会绕过 hooks），自定义模块应实现 `forward` 而不要覆写 `__call__`。
- hooks 的执行顺序与嵌套：外层模块的 pre-hook 先于内层，post-hook 后于内层。

### 11. 惰性模块与参数化

- `nn.LazyLinear`/`nn.LazyConv2d` 在第一次 forward 时根据输入形状推断 `in_features`，并把 `Parameter` 从 `UninitializedParameter` 实体化。实体化后 `state_dict` 才可稳定保存。
- `torch.nn.utils.parametrize` 与 `weight_norm`/`spectral_norm` 通过“参数化”把原始参数变换成有效权重；被移除/重参数化的张量会改变 `state_dict` 键名（常见 `parametrizations.weight.original`），升级旧 checkpoint 时需注意 [待验证：键名随版本演进]。

### 12. checkpoint 保存与恢复的常见模式

- **只存 `state_dict`**（推荐）：文件小、跨代码结构灵活；恢复时需先构造同结构模块。
- **存整个模块**（`torch.save(model, ...)`）：依赖类定义与目录结构，类改名/移动会反序列化失败，不推荐。
- 训练完整恢复：除 `model.state_dict()`，还要存 `optimizer.state_dict()`、`lr_scheduler.state_dict()`、epoch/step、以及 `torch.get_rng_state()`/各设备 RNG 状态；否则不可复现（详见 K06）。
- 加载时用 `map_location` 控制设备（如 `map_location="cpu"` 再 `.to(dev)`），避免在无 GPU 机器上反序列化失败。
- `load_state_dict` 返回 `_IncompatibleKeys`，在 `strict=False` 时应显式打印/断言其内容。

```python
ckpt = {
    "model": model.state_dict(),
    "optim": optimizer.state_dict(),
    "epoch": epoch,
    "rng": torch.get_rng_state(),
}
torch.save(ckpt, "train.pt")
```

### 13. 模块树的调试与可视化

- `print(model)` 会递归打印子模块与参数形状，但**不显示 buffer** 与共享关系。
- `dict(model.named_modules())`、`dict(model.named_parameters())` 用于快速核对键与设备。
- 统计参数量：`sum(p.numel() for p in model.parameters())`；可训练参数量加 `if p.requires_grad` 过滤。
- 检查设备一致性：`{p.device for p in model.parameters()}` 应只有一个（除有意分片），多于一个是“部分参数没迁移”的信号。

### 14. 常用容器模块对比

| 容器 | 存什么 | 是否注册 | 支持索引/键 | 进 state_dict |
|---|---|---|---|---|
| `nn.Sequential` | 子模块（有序） | 是 | 整数索引 | 是，键为 `0.weight` 等 |
| `nn.ModuleList` | 子模块列表 | 是 | 整数索引 | 是 |
| `nn.ModuleDict` | 子模块字典 | 是 | 字符串键 | 是 |
| `nn.ParameterList` | 参数列表 | 是 | 整数索引 | 是 |
| `nn.ParameterDict` | 参数字典 | 是 | 字符串键 | 是 |
| 普通 `list`/`dict` | 任意 | **否** | 任意 | **否** |

`nn.Sequential` 的键是数字字符串，因此**调整顺序会改变 checkpoint 键名**，破坏向后兼容；若需稳定键名，用带命名的 `nn.ModuleDict` 或显式 `OrderedDict`。

### 15. state_dict 键名与结构映射

键名由**属性名路径**拼接而成，直接反映模块树：

```python
class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Conv2d(3, 8, 3)

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = nn.Conv2d(1, 3, 3)
        self.blocks = nn.ModuleList([Block(), Block()])

print([k for k in Net().state_dict()])
# ['stem.weight', 'stem.bias',
#  'blocks.0.conv.weight', 'blocks.0.conv.bias',
#  'blocks.1.conv.weight', 'blocks.1.conv.bias']
```

由此可得加载兼容性规则：**只要属性名与层级路径不变，参数值就能正确对上**；重命名属性、把 `ModuleList` 换成 `Sequential`、插入/删除层都会改变键集合，从而在 `strict=True` 下失败。跨版本升级时常见做法是写一个“键名重映射”函数，把旧键批量改写成新键后加载。

### 16. 状态一致性问题排查清单

遇到“加载后精度不对 / 参数没更新 / 设备不匹配”时按序检查：

1. `model.training` 是否在推理时被设成 `False`（`model.eval()`）。
2. `state_dict` 键集合是否与模块匹配（`strict`、`missing_keys`、`unexpected_keys`）。
3. 是否在 `load_state_dict` **之后**又 `apply` 了初始化，把加载的值覆盖掉。
4. optimizer 是否在参数对象被替换**之后**才创建（顺序反了就更新旧对象）。
5. 所有参数/buffer 是否在同一设备（`{p.device ...}`）。
6. 是否有张量存在普通属性里而未随 `.to()` 迁移。
7. 共享参数是否在 optimizer 中出现多次。

## 常见陷阱与反例

1. **忘记 `super().__init__()`**：`_parameters`/`_modules` 未初始化，赋值参数/子模块时报 “cannot assign module/parameter before Module.__init__() call”。
2. **用普通 `list` 存子模块**：`self.layers = [nn.Linear(...), ...]` 不注册，`parameters()`/`state_dict()`/`.to()` 都漏掉。应改用 `nn.ModuleList`。
3. **先建 optimizer，再 `load_state_dict` 之外替换参数对象**：默认 `load_state_dict` 是原地拷贝、安全；但若手动 `model.fc = nn.Linear(...)` 换了新对象，optimizer 仍指向旧参数，更新失效。改结构后须重建 optimizer。
4. **`strict=True` 下键不匹配**：改名/改层数后加载报错；用 `strict=False` 并检查 `missing_keys`/`unexpected_keys`。
5. **推理忘记 `model.eval()`**：dropout 仍随机、BN 用 batch 统计，导致结果不稳定且不可复现。
6. **用 `.data` 或普通属性存 buffer**：不会被 `.to()` 迁移，也不会进 `state_dict`。
7. **BatchNorm + batch size 1（train 模式）**：batch 方差为 0，报错或数值爆炸；需 `eval()` 或同步 BN/足够大的 batch。
8. **共享参数在 `state_dict` 里出现两次导致加载顺序问题**：若两键值不一致，后写者覆盖。
9. **hook 不注销导致内存/回调泄漏**：长训练循环里每次注册不 remove。
10. **`model.parameters()` 是生成器**：遍历一次就耗尽；需要复用时应 `list(model.parameters())`。
11. **认为 `eval()` 会关梯度**：它不关；推理仍需 `with torch.no_grad()`。
12. **`to(device)` 返回新模块的错觉**：它是原地迁移并返回 `self`，与张量 `.to()` 语义不同。
13. **在 `__init__` 里对参数做依赖输入形状的初始化**：需要用 `LazyLinear` 等惰性模块或显式 `reset_parameters`。
14. **`persistent=False` 的 buffer 没进 `state_dict`**：跨设备/跨进程恢复后值丢失，需要时改成 `persistent=True`。
15. **多个模块共享同一子模块但误以为独立**：共享模块的 `training` 标志与参数是同一份。

## 与其他知识域的连接

- **K01 布局**：`Module.to()` 只迁移注册的张量与 buffer；`memory_format`/`dtype` 的批量迁移通过 `_apply` 完成，普通张量属性是漏网之鱼。
- **K02 autograd**：`Parameter.requires_grad` 决定是否建边；`zero_grad`、`retain_grad` 与模块参数的关系；hook 可在 backward 中观察梯度。
- **K04 数据管道**：BatchNorm 的 batch 统计与数据分布、`drop_last` 影响训练稳定性。
- **K05 优化器**：optimizer 持有的是 `Parameter` 引用，必须与 `model.parameters()` 一致；参数冻结与分组学习率。
- **K06 复现**：`train()`/`eval()` 决定 dropout/BN 行为，是复现性的关键开关。
- **K07 分布式**：`DDP` 依赖 `named_parameters` 顺序与 `state_dict` 键一致；`SyncBatchNorm` 替换 BN。
- **K10 导出部署**：`state_dict` 是 checkpoint 标准；导出前需确认 buffer 与 `training` 状态。
