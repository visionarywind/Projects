## 1. 题目与约束

给定整数数组 `nums` 与整数 `k`，统计并返回数组中和恰好为 `k` 的**连续子数组**个数。子数组指下标区间 `[i, j]`（`0 <= i <= j < n`），要求 `sum(nums[i..j]) == k`。

约束：`1 <= nums.size() <= 2·10^4`；元素取值为 `-1000` 到 `1000`（可正、可负、可为零）；`-10^7 <= k <= 10^7`；计数结果可超出 `int`，用 64 位返回更安全。返回值是个数（`long long`），不是区间列表。元素可重复，负数存在，这一点决定了本题的解法选择。

## 2. 面试思路

先给暴力解：枚举所有 `[i, j]` 并求和，`O(n^2)` 枚举区间、内层累加可做到 `O(n^2)` 总时间、`O(1)` 额外空间，`n=2·10^4` 时约 `4·10^8` 次操作，能过但常数吃紧。

面试里最容易踩的坑是**下意识套滑动窗口**：以为"子数组"就天然适合双指针收缩窗口。但滑动窗口的正确性依赖单调性——当右指针右移时，窗口和必须单调不减，左指针收缩才能"补回"。本题元素含负数，窗口和随右指针扩张并非单调，收缩会破坏已满足的区间，因此滑动窗口在此**不成立**。

正确切入点是前缀和：令 `pre[0]=0`，`pre[j] = nums[0]+...+nums[j-1]`（`pre` 长度为 `n+1`）。则区间和 `sum(i..j-1) = pre[j] - pre[i] = k`，等价于 `pre[i] = pre[j] - k`。于是问题转化为：对每个右端 `j`，统计有多少个**更早出现**的前缀和等于 `pre[j] - k`。这正是 B001 的"查找历史补数"结构，用哈希表把查找降到平均 `O(1)`。

面试表达顺序建议：**先证伪滑动窗口（讲清单调性为何不满足）→ 再给出前缀和等式变形 → 最后说明哈希表存"历史前缀和出现次数"为何覆盖所有区间**。

## 3. 算法与正确性

步骤：初始化哈希表 `cnt`，令 `cnt[0] = 1`（前缀和为 0 在"空前缀"处出现过一次）；令 `pre = 0`、`ans = 0`。从左到右遍历 `nums`：

1. `pre += nums[i]`（此时 `pre` 即 `prefix[i+1]`）；
2. 查 `cnt[pre - k]`，把其计数累加到 `ans`（这些是满足 `prefix[i] - k == pre_left` 的更早位置）；
3. `cnt[pre] += 1`（把当前前缀和登记为后续可用的"历史"）。

**循环不变量**：处理完下标 `i` 的步骤 2 之前，`cnt` 恰好记录了下标 `0..i`（即所有长度 `<= i+1` 的前缀，含空前缀）的前缀和出现次数。

正确性：任意合法区间 `[i, j-1]`（`i <= j-1`）满足 `prefix[j] - prefix[i] = k`，即 `prefix[i] = prefix[j] - k`。当外层处理到 `j` 时，`i < j`，故 `prefix[i]` 已在步骤 2 之前登记进 `cnt`，会被计入一次；反之每个被计入的项都对应一个 `prefix[i] = pre - k` 且 `i < j` 的位置，构成合法区间。故计数恰好等于合法区间总数。

**两个关键顺序**：`cnt[0]=1` 保证 `i=0`（空前缀）这一侧的区间被计入；"先查后插"保证 `i` 与 `j` 之间严格 `i < j`，不会把当前前缀和与自身配对产生长度为零的伪区间。

## 4. C++17 实现

```cpp
#include <bits/stdc++.h>
using namespace std;

long long subarraySum(vector<int>& nums, int k) {
    unordered_map<long long, long long> cnt;   // 前缀和 -> 出现次数
    cnt.reserve(nums.size() * 2);
    cnt.max_load_factor(0.7f);
    cnt[0] = 1;                                // 空前缀，覆盖 i=0 的情形
    long long pre = 0, ans = 0;
    for (int x : nums) {
        pre += x;                              // prefix[i+1]
        auto it = cnt.find(pre - k);           // 先查
        if (it != cnt.end()) ans += it->second;
        ++cnt[pre];                            // 后插
    }
    return ans;
}
```

实现细节：前缀和与计数都声明为 `long long`，避免 `pre` 溢出以及计数超出 `int`；`reserve` 与 `max_load_factor` 降低哈希冲突常数；键用 `long long` 而非 `int`，因为 `pre` 在 `n=2·10^4`、每项 `1000` 时最大约 `2·10^7`，虽仍在 `int` 范围内，但用 64 位可省略溢出论证。若 OJ 要求 `class Solution`，把函数搬进类中并去掉 `using namespace std` 依赖的写法。

## 5. 复杂度

- 时间：平均 `O(n)`。每个元素做一次 `find` 与一次 `+=`，平均 `O(1)`。最坏 `O(n^2)`：哈希表全冲突时线性探测退化，实际因 `reserve` 几乎不出现。
- 空间：`O(n)`。哈希表最多存 `n+1` 个不同前缀和（最坏每步新和都不同）。
- 与暴力对比：暴力 `O(n^2)` 时间、`O(1)` 空间；本解法用 `O(n)` 空间换掉一个数量级的时间。二者在 `n` 较小时差距不明显，`n >= 10^4` 时哈希法优势显著。
- 关键前提：元素可比较相等且可哈希（`long long` 满足）；前缀和范围不溢出所声明的类型。

## 6. 例子推演

`nums=[1,1,1], k=2`：

`prefix = [0,1,2,3]`。需要 `prefix[j] - prefix[i] = 2`：`(i,j)=(0,2)` 与 `(1,3)` 两对，答案为 2。

| i | x | pre | 查 cnt[pre-k]=cnt[pre-2] | ans | cnt 更新后 |
|---|---|---|---|---|---|
| 0 | 1 | 1 | cnt[-1]=0 | 0 | {0:1, 1:1} |
| 1 | 1 | 2 | cnt[0]=1 | 1 | {0:1, 1:1, 2:1} |
| 2 | 1 | 3 | cnt[1]=1 | 2 | {0:1, 1:1, 2:1, 3:1} |

再验证含负数与零：`nums=[1,-1,0], k=0`。合法区间有 `[1,-1]`、`[0,0]`、`[1,-1,0]`，共 3 个。前缀 `prefix=[0,1,0,0]`，`prefix[j]-prefix[i]=0` 的对：`(0,2)`、`(0,3)`、`(2,3)`，共 3 个，与推演一致。该例也直观说明为什么不变量里"次数"而非"是否存在"是必需的——同一个前缀和 0 出现了三次。

## 7. 测试与调试

建议用例：
- `[1,1,1], 2`：仅正数，答案 2，验证基本计数；
- `[1,-1,0], 0`：含负数与零，答案 3，验证前缀和重复计数；
- `[1,2,3], 3`：答案 2（`[3]` 与 `[1,2]`），验证单元素与多元素区间并存；
- `[1], 0`：无解，答案 0，验证空前缀不产生伪区间；
- `[0,0,0], 0`：答案 6（三个长度 1、两个长度 2、一个长度 3 的区间），验证全零退化与计数上界；
- `[-1000]*10000, -1000`：验证大负数与计数规模，检查是否溢出。

调试切入点：打印每一步的 `pre`、`pre-k` 的查表值与更新后的 `cnt`；用 `O(n^2)` 暴力枚举作为 oracle，对随机数据（含负数）做差分测试。若结果偏小，优先怀疑 `cnt[0]=1` 或"先查后插"次序；若结果偏大，优先怀疑用了滑动窗口思路或重复累加同一前缀。

## 8. 面试追问

1. **若改为"乘积恰好为 K 的子数组"个数，怎么做？** 前缀积 + 哈希在一般整数下失效：前缀积会溢出，且 0 使除法不可逆、负号使"补数"不唯一。仅当所有元素为正整数（或可保证 `pre != 0`）时，才能用 `pre[j] / pre[i] = k` 的哈希（需整除），并特殊处理 0 的连续段；更稳妥是分段处理 0 与约数分解，复杂度分析需重做。
2. **若改为"元素之和能被 K 整除的子数组"个数？** 需要记录前缀和**对 K 取模**的余数频次（`pre[i] == pre[j] (mod K)`），哈希键换成 `pre % K`（注意 C++ 负数取模需 `((x % K) + K) % K` 归一化），复杂度仍是平均 `O(n)`，但正确性论证从"相等"变为"同余"。
3. **若扩展为"和恰好为 K 的二维子矩阵"个数？** 固定上下边界（`O(n^2)` 对行），把列方向压成一维数组，对每个行区间调用本题的一维算法（`O(m)`）；总复杂度 `O(n^2·m)`，空间 `O(m)`。题干从一维升到二维后，必须显式讨论压维的正确性与复杂度乘积。

## 9. 易错点与反例

- **反例**：用滑动窗口，`nums=[1,-1,1], k=1`。右指针到下标 1 时窗口和 0，下标 2 时窗口和 1；但合法区间还包含 `[1]`（下标 2 单独）与 `[1,-1,1]`，窗口收缩逻辑会漏计——因为负数使"和是否超 k"不再是收缩信号。
- **易错**：忘记 `cnt[0] = 1`。此时 `nums=[1,1], k=2` 会得 0 而非 1，因为漏掉 `i=0` 这一侧。
- **易错**：先插入后查询，导致 `i==j` 的零长度区间被计入（`k=0` 时尤其明显，答案会虚高）。
- **易错**：计数用 `int`。`[0,0,...,0]`（`n` 个 0）且 `k=0` 时答案是 `n(n+1)/2`，`n=2·10^4` 时约 `2·10^8`，仍小于 `2^31`，但把 `n` 放大或换题面即可能溢出；用 `long long` 一劳永逸。
- **易错**：把"和为 K 的子数组"与"和为 K 的子序列"混淆。子序列不要求连续，前缀和等式不成立，解法完全不同。

## 10. 变体与迁移

- 同域迁移：`A001` 的"前缀和差值 = K"结构直接迁移到"和为 K 的最长子数组"（哈希存**最早**下标而非次数）、"和为 K 的区间和查询"（前缀和 + 二分）、"k 倍区间"（前缀和同余）。
- 结构迁移：B001 两数之和 是"存在一个历史补数"；本题是"统计历史补数个数"。区别在哈希表存"下标"还是"次数"，也决定了返回"一条路径"还是"全部方案数"。
- 约束迁移：一旦引入负数，滑动窗口失效，前缀和成为主线；一旦要求输出区间本身而非计数，复杂度受输出规模影响，最坏 `O(n^2)`。
- 维度迁移：二维子矩阵和计数（见追问 3）展示"压维后套用一维算法"的通用套路，可与 K06 分治思路结合优化。
