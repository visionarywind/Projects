## 1. 题目与约束

给定整数数组 `nums` 和目标值 `target`，返回两个不同下标 `[i, j]`，使 `nums[i] + nums[j] == target`。若不存在答案，返回空数组。

约束：`2 <= nums.size() <= 10^5`；元素可为负、零或正且可重复；同一元素不能使用两次；保证至多一对答案（或允许返回任意一对）。返回值是下标，不是元素值。

## 2. 面试思路

先给暴力解再优化：枚举所有二元组是 `O(n^2)`，`n=10^5` 时约 `5·10^9` 次比较，超时。

优化切入点：扫描到 `nums[i]` 时，只需要知道"已扫描的前缀里是否存在 `target - nums[i]`"。把"查找历史补数"从线性降到平均 `O(1)` 的手段是哈希表（键为元素值，值为其下标）。

面试表达顺序建议：**先定义状态（哈希表存前缀元素）→ 再证明为什么它覆盖所有答案 → 最后处理重复值与自配对边界**。

## 3. 算法与正确性

步骤：从左向右遍历；对 `nums[i]`，先查 `target - nums[i]` 是否在哈希表中；若在则返回 `{pos[need], i}`；否则把 `nums[i] -> i` 存入哈希表。

**循环不变量**：处理下标 `i` 之前，哈希表恰好保存所有下标 `< i` 的元素及其（一个）下标。

正确性：若存在答案 `(p, q)` 且 `p < q`，当循环到 `q` 时，`p < q` 已在哈希表中，`need = target - nums[q] = nums[p]` 命中，算法返回 `(p, q)`。若循环结束仍未返回，则不存在任何合法对。

**先查后插入**是关键：它保证不会用同一元素自配对（例如 `nums=[3], target=6` 不会返回 `[0,0]`）。

## 4. C++17 实现

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> pos;
    pos.reserve(nums.size() * 2);          // 预留桶，减少 rehash
    pos.max_load_factor(0.7f);
    for (int i = 0; i < (int)nums.size(); ++i) {
        int need = target - nums[i];
        auto it = pos.find(need);
        if (it != pos.end()) return {it->second, i};
        pos[nums[i]] = i;                  // 先查后插
    }
    return {};
}
```

实现细节：`reserve` 与 `max_load_factor` 用于降低哈希冲突；返回 `{p, q}` 保持 `p < q`。若 OJ 要求 `class Solution`，把函数移入类中即可。

## 5. 复杂度

- 时间：平均 `O(n)`（每次 find/insert 平均 `O(1)`）；最坏 `O(n^2)`（哈希全部冲突，实际几乎不出现）。
- 空间：`O(n)` 存哈希表。
- 关键前提：元素可哈希（本题 `int` 满足）；若元素是自定义大对象需先定义哈希函数。

## 6. 例子推演

`nums=[2,7,11,15], target=9`：

| i | nums[i] | need | 哈希表 | 动作 |
|---|---|---|---|---|
| 0 | 2 | 7 | {} | 未命中，存入 2→0 |
| 1 | 7 | 2 | {2:0} | 命中，返回 [0,1] |

边界样例 `nums=[3,3], target=6`：`i=0` 存 3→0；`i=1` need=3 命中，返回 [0,1]（正确使用两个不同下标）。

## 7. 测试与调试

建议用例：
- `[3,3], 6`：重复值，验证先查后插；
- `[-1,-2,-3,-4], -6`：负数；注意不要用元素值当排序假设；
- `[0,4,3,0], 0`：含 0，验证 0 值也能正确入表；
- `[1,2], 5`：无解，应返回空。

调试切入点：打印每步的哈希表与 `need`；若用暴力解作为 oracle，可随机生成数据做差分测试。

## 8. 面试追问

1. **若数组已排序，能否用双指针把空间降到 `O(1)`？** 可以，但返回下标时需额外记录原始位置；排序会打乱下标。
2. **若要返回所有满足的对（含重复值）？** 哈希表需存值到下标列表，复杂度受输出规模影响，最坏 `O(n^2)` 对。
3. **若数据是流式、内存放不下？** 需要外排或分块；哈希表方法不再适用，改用排序+双指针的外存版本。

## 9. 易错点与反例

- **反例**：先插入后查询，`nums=[3], target=6` 时用自己配自己，返回 `[0,0]`——错误。
- **易错**：用 `unordered_map` 却把元素值当键、下标当值搞反，导致返回元素而非下标。
- **易错**：忘记 `reserve`，在 `n=10^5` 且哈希冲突时被卡常数。
