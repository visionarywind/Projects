# 代码审查与调试

面向本题库 C++17 代码的审查清单与调试方法。清单按“正确性—边界—类型—资源—表达”组织，方法部分给出从编译到差分的排错流程。

## 代码审查清单

### 1. 正确性与不变量

- [ ] 每个循环/递归都能写出一句循环不变量，且初始化、保持、终止三处都成立。
- [ ] B001/A001：是否“先查后插”？`cnt[0]=1` 是否设置？（错误实现会导致自配对或漏计空前缀区间）
- [ ] I002：`left` 更新是否带 `last[c] >= left` 判断或 `max`？`left` 是否单调不减？
- [ ] I003：合并处是否用 `max(curR, it[1])`？重叠判定是否为 `<=`？循环末尾是否封存最后一段？
- [ ] A003：`mid` 取法（偏左/偏右）与分支（`hi=mid` / `lo=mid+1`）是否自洽？能否证明不死循环？
- [ ] E003：去重条件是否含 `&& !used[i-1]`？`res` 是否存 `path` 的拷贝？

### 2. 边界条件

- [ ] 空输入：`""`、空数组、空网格、`k=0`；对 I001 空串按定义视为有效。
- [ ] 最小规模：`n=1`、单元素、`capacity=1`。
- [ ] 下标范围：区间 `[l,r]` 与 `pre[r+1]-pre[l]` 是否混用两套下标（最高频 off-by-one）。
- [ ] 边界比较：`<=` 与 `<` 是否与题目“相接/半开”定义一致（I003、I001 追问、A003）。
- [ ] 遍历边界：A002 的 `nr < 0 || nr >= m` 是否在访问 `grid[nr][nc]` 之前完成。

### 3. 类型与溢出

- [ ] 前缀和、计数、`sum(weights)` 是否用 `long long`（A001、A003）。
- [ ] `int` 是否足够：B002 的 `n<=45` 安全，放大后需 `long long` 或取模；E003 阶乘 `n>=13` 溢出。
- [ ] `char` 作数组下标是否转 `unsigned char`（I002 的 `last[256]`）。
- [ ] `long long` 键与值是否一致，避免隐式窄化。

### 4. 资源与数据结构

- [ ] `unordered_map` 是否 `reserve` 并设置 `max_load_factor`（B001、A001、E001、E002）。
- [ ] E001：删除是否用哨兵避免空指针？是否先复制 `value` 再移动节点？节点是否复用？
- [ ] A002：DFS 递归深度是否可能达 `O(mn)`？考虑改 BFS 或显式栈。
- [ ] 是否区分“原地标记修改输入”与“只读输入”，必要时改用 `visited`。

### 5. 表达与工程

- [ ] 是否用 `vector` 而非 `std::stack` 模拟栈以获得更好的缓存局部性（I001）。
- [ ] 排序比较函数是否显式写出、是否满足严格弱序（I003，`a[0]!=b[0]?a[0]<b[0]:a[1]<b[1]`）。
- [ ] 是否避免无必要的动态分配与拷贝（E003 中 `path.reserve(n)`）。
- [ ] 命名与常量数组是否清晰（方向表 `dirs`、映射表 `static const`）。

## 调试方法

### 编译期

- 用 `g++ -std=c++17 -Wall -Wextra -Wshadow -O2` 编译，先清掉所有警告再谈逻辑。
- 抽取题目代码块单独编译，避免依赖 OJ 的 `class Solution` 包装差异。

### 打印与断言

- 在关键步骤打印状态：B001/A001 打印 `need`/`pre`/`cnt`，I002 打印 `left/right/last`，I003 打印排序后序列与 `cur`，A003 打印 `lo/hi/mid/canShip(mid)`。
- 用 `assert` 固化不变量，例如 E001 检查 `idx_[heap_[i]] == i`、链表节点集合与哈希键集合一致。
- 对不变量断言失败，优先定位是“初始化错”还是“更新遗漏”。

### 二分与死循环定位（A003）

- 若程序不终止，打印每轮 `lo/hi/mid` 观察区间是否严格缩小。
- 记住口诀：偏左中值 `mid=(lo+hi)/2` 配 `hi=mid`；偏右中值配 `lo=mid+1`；改错一侧必死循环。

### 小规模手推

- 用题目“例子推演”一节的手算表格逐步对照程序输出，首个不一致处即 bug 位置。
- 构造正文反例（如 I003 的 `[[1,10],[2,3]]`、I002 的 `"abba"`）验证错误实现确实失败。

### 差分测试

- 写暴力 oracle，固定随机种子，小规模随机跑数百次比对（详见 `test-data-and-oracles.md`）。
- 结果偏大/偏小的方向本身是线索：A001 偏大常因先插后查，偏小常因漏 `cnt[0]=1` 或误用滑动窗口。

### 段错误与未定义行为

- I001 的 `st.back()` 空容器、A002 的越界读、I002 的负下标、E001 的空指针，都属常见 UB；用 `-fsanitize=address,undefined` 复现定位。
- A002 大网格上一运行就崩、无逻辑错误，优先怀疑 DFS 爆栈，换 BFS 验证。

### 复盘模板

对每个 bug 记录：题目 ID、错误类别（下标/类型/初始化/分支/资源）、最小复现输入、根因、修复、如何在下一次审查清单中提前拦截。
