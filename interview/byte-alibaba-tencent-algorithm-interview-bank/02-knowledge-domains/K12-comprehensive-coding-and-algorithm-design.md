# K12 综合编码、算法设计与约束变化

## 核心问题

- **约束变化分析**：同一个问题，`n` 的规模、元素取值范围、是否允许负数、是在线还是离线，都会改变最优解。会读约束是设计算法的第一步。
- **算法选择决策**：从"输入规模"反推可接受的复杂度，再匹配数据结构与算法范式。
- **边界与退化**：空输入、单元素、全相同、极值、溢出、不连通，是面试评测的重点。
- **规模估算**：用运算次数与内存量级快速判断方案是否可行。
- **工程落地**：把解法拆成可测试的模块，处理健壮性、复用与可读性；面试中能把思路讲清、把边界说全，比写出花哨代码更值钱。
- **面试表达**：先定义问题与约束，再给暴力解与复杂度，然后优化并证明，最后主动列边界与追问。

学习目标是面对陌生题能快速判断题型、选择算法、给出正确且边界完备的 C++17 实现，并清楚说明取舍。

## 训练顺序

1. 先用"规模 → 复杂度"对照表训练读约束反射（`10^5` 想到 `O(n log n)`，`10^2` 才敢用 `O(n^2)`/`O(n^3)`）。
2. 再练约束变化：同一题面下把元素从非负改成含负数、从静态改成流式，观察解法如何变。
3. 然后系统性过一遍边界清单（空、单元素、重复、极值、溢出、不连通）。
4. 最后做表达训练：用"定义 → 暴力 → 优化 → 证明 → 边界 → 追问"六段式复述已做过的题。
5. 高级和专家题用于训练多模式组合、工程边界与开放追问。

## 核心模式

### 1. 规模到算法的映射（决策表）

| 输入规模 `n` | 可接受的复杂度 | 典型算法 / 范式 |
|---|---|---|
| `n ≤ 10` | `O(n!)` | 全排列、暴力回溯 |
| `n ≤ 20` | `O(2^n)`、`O(2^n·n)` | 子集枚举、状态压缩 DP |
| `n ≤ 500` | `O(n^3)` | Floyd、区间 DP、矩阵链乘 |
| `n ≤ 5000` | `O(n^2)` | 线性 DP、双重循环、简单图算法 |
| `n ≤ 10^6` | `O(n log n)` | 排序、堆、二分、树状数组、线段树 |
| `n ≤ 10^8` | `O(n)` | 哈希、前缀和、双指针、一次扫描 |
| `n` 很大（`≤ 10^18`） | `O(log n)`、`O(√n)` | 快速幂、矩阵快速幂、二分答案、数论 |

用法：先看最紧约束确定复杂度上界，再看"每次操作能做什么"，最后匹配范式。`[经验]` 评测机每秒约能完成 `10^8` 量级的简单运算，据此折算。

### 2. 约束变化示例：子数组求和

```cpp
// 情形 A：元素全为正整数，求"和 ≥ target 的最短子数组"
// 单调性成立 -> 滑动窗口 O(n)
int minLenPositive(const vector<int>& a, int target) {
    int n = (int)a.size(), left = 0, best = INT_MAX;
    long long sum = 0;
    for (int right = 0; right < n; ++right) {
        sum += a[right];
        while (sum - a[left] >= target) sum -= a[left++];  // 收缩仍满足条件
        if (sum >= target) best = min(best, right - left + 1);
    }
    return best == INT_MAX ? 0 : best;
}
```

```cpp
// 情形 B：元素含负数，求"和恰好为 k 的子数组个数"
// 单调性失效 -> 前缀和 + 哈希计数 O(n)
long long countSumK(const vector<int>& a, long long k) {
    unordered_map<long long, long long> cnt;
    cnt.reserve(a.size() * 2);
    cnt[0] = 1;                                 // 空前缀
    long long pre = 0, ans = 0;
    for (int x : a) {
        pre += x;
        auto it = cnt.find(pre - k);
        if (it != cnt.end()) ans += it->second;
        ++cnt[pre];
    }
    return ans;
}
```

对比：**一旦引入负数，滑动窗口的正确性前提（窗口和随右端点单调）被破坏**，必须换前缀和 + 哈希。这就是"约束变化改变最优解"的典型。类似地：值域小而密集可用计数桶替代排序；要求在线输出时无法先排序，需换有序容器。

### 3. 数据流 TopK（在线 + 工程约束的代表）

```cpp
vector<int> topKFrequent(vector<int>& nums, int k) {
    unordered_map<int, int> cnt;
    cnt.reserve(nums.size() * 2);
    for (int x : nums) ++cnt[x];                 // 一次计数
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;  // 小顶堆
    for (auto& [val, f] : cnt) {
        pq.emplace(f, val);                      // (频率, 值)
        if ((int)pq.size() > k) pq.pop();        // 挤掉当前最小
    }
    vector<int> res;
    res.reserve(k);
    while (!pq.empty()) { res.push_back(pq.top().second); pq.pop(); }
    return res;
}
```

取舍：`k ≪ m`（不同元素数）时堆最优 `O(m log k)`；`k` 与 `m` 同阶时直接排序或计数桶更好；内存受限的流式场景只能用近似算法（Misra-Gries / Count-Min Sketch）。**精确流式 TopK 无法做到 `O(k)` 内存**，因为必须区分全部 `d` 个元素。

### 4. 复杂度与内存的规模估算

- **运算量估算**：`n=10^5` 时 `O(n log n)` 约 `1.7×10^6` 次，`O(n^2)` 约 `10^10` 次（超时）；用这个量级快速否掉方案。
- **整数范围**：`int` 约 `±2.1×10^9`；求和、乘积、计数容易溢出，先按上界估算再决定 `long long` 或取模。
- **内存估算**：`10^8` 个 `int` 约 400 MB，通常已超限；`10^6` 个 `int` 约 4 MB，安全。递归深度也吃栈空间，深搜索要防爆栈。
- **常数因子**：哈希表、线段树、递归回溯的常数量级差异很大；同复杂度下优先选实现简单、缓存友好的方案。

### 5. 面试六段式表达模板

1. **复述与澄清**：确认输入范围、返回值、是否允许修改输入、有无重复/负数。
2. **暴力解**：给出朴素算法与其复杂度，作为正确性基线。
3. **瓶颈分析**：指出暴力解慢在哪里，找到可优化的结构（单调性、重叠子问题、连通性……）。
4. **优化与证明**：给出目标算法，用不变量或归纳证明正确性。
5. **复杂度**：给出时间与空间，说明关键前提（如元素非负、`mod` 为质数）。
6. **边界与追问**：主动列出空/单元素/极值/溢出，并预判面试官会问的变体。

### 6. 边界与退化清单（编码前逐项核对）

- 空输入、长度 1、`k` 为 0 或等于 `n`。
- 全部相同、严格有序、完全逆序。
- 含 0、含负数、含极值（`INT_MIN`、`INT_MAX`、大质数）。
- 求和/乘积/计数是否溢出；除法与取模的负数语义。
- 图是否连通、是否可有自环/重边/多分量。
- 目标不存在时返回什么（空、`-1`、`0`、`INF`）。
- 是否允许修改输入；否则先深拷贝。

## 常见陷阱

- **只看样例不看约束**：用 `O(n^2)` 解 `n=10^5` 的题必然超时；约束是解法选择的第一依据。
- **默认输入合法**：空数组、单元素、`k > n`、无解，都需显式处理。
- **溢出**：中间累加用 `int`，或在 `INF` 上继续加；`INF` 应取"上限 + 1"并防相加溢出。
- **负数取模**：C++ 的 `%` 对负数返回负值，同余类题需归一。
- **在线/离线互串**：流式输入不能先排序；离线多次查询可预处理的却重复计算。
- **修改输入副作用**：原地标记（如岛屿问题把 `'1'` 改 `'0'`）在需要复用输入时造成 bug。
- **哈希表最坏退化**：不设 `reserve` 或自定义哈希易被构造冲突，复杂度从 `O(n)` 退化到 `O(n^2)`。
- **递归爆栈**：深递归（`10^5` 层）应改显式栈或转递推；评测机栈通常远小于堆。
- **一次性追求最优**：面试中先给可运行的正确解，再优化；直接卡在最优解上常得不偿失。
- **复杂度分析漏项**：输出规模、哈希最坏、`vector` 扩容、复制成本都可能改变实际复杂度，需一并说明。

## 复杂度速查

| 度量 | 快（可接受） | 边缘 | 慢（超时风险） |
|---|---|---|---|
| `n=10^5` | `O(n)`、`O(n log n)` | `O(n√n)` | `O(n^2)` 及以上 |
| `n=10^3` | `O(n^2)` | `O(n^2 log n)` | `O(n^3)` 及以上 |
| `n=100` | `O(n^3)` | `O(n^4)` | `O(2^n)`（`n` 大时） |
| `n=20` | `O(2^n)`、`O(2^n·n)` | `O(3^n)` | `O(n!)` |
| 大 `n`（`10^18`） | `O(log n)`、`O(√n)` | `O(n^{1/3})` | 线性及以上 |

内存量级：`int` 数组 `10^6` 项约 4 MB、`10^8` 项约 400 MB；`long long` 翻倍。递归深度受栈限制，通常在 `10^4`~`10^5` 量级。
