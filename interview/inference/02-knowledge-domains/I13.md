# I13 Disaggregation 与 KV Transfer

## 范围与定位

本域覆盖 prefill/decode 分离部署（PD disaggregation）的架构动机、KV cache 在实例间的传输契约，以及传输层与控制层的协同恢复机制。核心问题是：**为什么要把同一请求的生命周期拆到不同实例**、**KV 如何在实例间可靠流转**、**传输失败时系统如何降级**。

边界：与 I06（prefill/decode 双阶段）是"为什么拆"与"怎么传"的关系；与 I15（长上下文与容量）是"横向拆角色"与"纵向加层级"的区别——HiCache 在单实例内加 host/storage 层，PD 在多实例间拆角色，两者可组合但不能混写为同一 cache。与 I08（KV Cache 管理）是"单实例 allocator 语义"与"跨实例所有权协议"的差异。

证据边界：PD 架构动机来自 arXiv PDF 解析 [已确认，PDF]；KV transfer 公共契约来自 SGLang M13 静态源码 [已确认]；真实跨机 RDMA/D2D 传输未运行 [待验证]。

## 核心概念与机制

### 1. 为什么分离：P/D 资源模型的互斥

- **定义**：PD disaggregation 把 prefill 与 decode 放到不同实例，各自用不同的 batch 配置和资源配置。
- **原理**：prefill 是 compute-bound 的大矩阵运算，适合高算力、大并行度；decode 是 bandwidth-bound 的小步反复，适合高带宽、低延迟 [已确认] `sglang/01-modules/M04-scheduler-batching/README.md:12`。混合部署时，长 prefill 会挤压同节点其他请求的 decode 进度，互相干扰。分离后各自优化：prefill 节点追求吞吐/token，decode 节点追求低 TPOT 和高并发。
- **不变量**：PD 比例与 workload 分布相关——workload 估计不准会造成 P/D 比例失调和迁移问题 [已确认，PDF] `insights/03-arxiv-reading-notes.md:111-114`。
- **例子**：请求到达先进入 prefill 队列，完成 KV 计算后将 KV 传输到 decode 实例；decode 实例从 radix 命中或直接接收后继续生成。

### 2. KV Transfer 契约：所有权从单进程到跨实例

- **定义**：prefill owner 产生 KV，decode owner 消费 KV，transfer layer 负责两者之间的可靠流转。
- **原理**：SGLang M13 定义 `StateType`、`KVTransferMetric`、`KVArgs`、`KVPoll` 以及 `BaseKVManager/BaseKVSender/BaseKVReceiver/BaseKVBootstrapServer`。公共方法是 `init`、`poll`、`clear`、`abort`；receiver 还通过 `send_metadata` 建立目标布局 [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:31-41`。
- **不变量**：KV ownership 从单进程 allocator 变成跨实例协议，transfer layer 必须支持 **幂等**、**backpressure** 和**错误恢复** [已确认] `insights/03-arxiv-reading-notes.md:118`。控制元数据与 payload 可走不同通道，两者成功不能互推 [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:60-61`。
- **例子**：正常状态机是 `registered → metadata/transfer → poll DONE → commit`；异常是 `poll FAILED/TIMEOUT → record_failure → abort/clear` [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:59-60`。

### 3. Staging 与 HiCache 组合

- **定义**：decode 实例在接收 KV 时不直接写入 GPU pool，而是经过 staging buffer 中转；HiCache 在 GPU KV 外增加 host/storage 层。
- **原理**：`StagingBuffer/StagingAllocator` 管理指针、offset、alloc id、水位线与释放；`staging_handler.py` 的 `DecodeStagingContext/DecodeStagingHandler` 管理 room、chunk、watermark 和 transfer。HiCache 的 prefetch 完成后才把结果提交给 request；restore 失败、超时或请求 abort 时必须调用 `_clean_hicache_prefetch_resources`，不能让 staging room 永久占用 [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:43-48`。
- **不变量**：HiCache 是纵向加层（GPU 外加 host/storage，做 prefetch/restore/eviction），P/D 是横向拆角色（prefill/decode 分实例）。两者可组合但故障模型完全不同 [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:21`。

### 4. 流控与恢复

- **定义**：传输层必须处理速率不匹配、网络抖动和实例故障。
- **原理**：`CommonKVSender.send / CommonKVReceiver.poll` 建立心跳、超时、abort acknowledgement 和 endpoint cleanup [已确认] `sglang/01-modules/M13-disaggregation-hicache/README.md:41-43`。`FakeKVSender/Receiver` 作为逻辑测试替身，不依赖真实网络。
- **不变量**：集群级 RDMA 上固定 block 的 D2D KVCache transfer 难以达到理想利用率 [已确认，PDF] `insights/03-arxiv-reading-notes.md:114`。传输失败恢复分两级——可恢复的请求 abort/clear 并重新入队；不可恢复的请求设置 abort finish reason。
- **例子**：P/D 节点失联时，路由应回退到聚合实例或重算 prefill，不能无限等待 [已确认] `insights/04-design-decision-and-validation.md:108`。

## 常见误区

1. **"PD 分离等于两个独立服务"**。PD 不是解耦为两个无状态服务——KV transfer 是有状态的跨实例协议，必须维护 ownership 和生命周期。
2. **"传输成功等于 decode 可用"**。control metadata 与 payload 走不同通道，poll DONE 后还需 commit 到本地 KV pool。
3. **"HiCache 可以替代 PD disaggregation"**。HiCache 是纵向加层（单实例内 GPU→host→storage），PD 是横向拆角色。两者解决的问题不同，可组合使用。
4. **"D2D 传输总能打满带宽"**。在 tens of thousands 设备规模下，block-fixed D2D KVCache transfer 难以达到理想利用率 [已确认，PDF]。
5. **"传输失败就是系统故障"**。传输层有独立的 abort/clear 和重试机制，不应当把传输失败直接上升为进程级崩溃。
