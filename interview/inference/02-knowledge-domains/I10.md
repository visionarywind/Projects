# I10 TP / PP / 分布式执行

## 范围与定位

I10 处理推理系统中的并行与分布式执行：单个 GPU 装不下或算不够时，如何将模型和数据分布到多卡/多节点。它覆盖 TP（Tensor Parallel，切分线性层与 attention head/hidden 维度）、PP（Pipeline Parallel，按 Transformer layer range 切分）、DP（Data Parallel）、DP Attention、CP（Context Parallel，切分长序列 attention）、DCP（Decode Context Parallel）、EP（Expert Parallel，切分 routed experts）、MoE DP/TP，以及 collective 通信执行。本域决定了推理服务的规模上限、吞吐/延迟权衡和硬件利用率。

与相邻域的边界：I10 不定义 KV cache 组织（I08），但 TP 分片直接影响 KV head 的本地数量；不定义 attention kernel 选择（I07），但 attention TP 可能使用 `_ATTN_TP` 而非全 `_TP`；不定义采样（I09），但 sampler 在 TP all-reduce 后的 logits 上执行。证据结构上，建组逻辑、rank 坐标、并行宽度约束有源码级文档支撑；真实 GPU/多进程/跨节点通信、checkpoint 加载、性能未验证。

## 核心概念与机制

### 1. 四层心智模型：拓扑、张量布局、通信执行、调度优化

定义：并行不是单一开关，应始终分开观察四个层次——哪些 global rank 在一起（拓扑/ProcessGroup）、每个 rank 持有什么（张量布局）、如何交换聚合（collective 类型）、何时切 batch/padding/capture（调度优化）。[C] `sglang/01-modules/M20-parallel-strategies/README.md:26-51`

原理：`ServerArgs` 中的 `tp_size`、`pp_size`、`dp_size`、`attn_cp_size`、`moe_dp_size`、`ep_size` 等宽度在建组前经过整除性校验。[C] `sglang/01-modules/M20-parallel-strategies/README.md:54-69`

关键不变量：关闭 custom all-reduce 改变通信实现但不改变 TP 成员；启用 DP Attention 不意味着所有层都使用同一组 DP rank。[C] `sglang/01-modules/M20-parallel-strategies/README.md:52-53`

### 2. TP group 的连续切分与 PP group 的跨区间步长

定义：TP group 按连续 global rank 创建；PP group 按跨区间步长构造。[C] `sglang/01-modules/M20-parallel-strategies/README.md:72-84`

原理：world_size=8, tp_size=4 时 TP groups 为 `[0,1,2,3]`、`[4,5,6,7]`。tp=2, pp=4, world=8 时 PP groups 为 `[0,2,4,6]` 和 `[1,3,5,7]`——不是连续的。[C] `sglang/01-modules/M20-parallel-strategies/README.md:72-83`

模型消费：PP 的 `get_pp_indices`/`make_layers` 只实例化当前 stage 的 layer range；first rank 持有 embedding，last rank 持有 norm/lm head，中间 rank 通过 proxy tensors 传递 hidden/residual。[C] `sglang/01-modules/M20-parallel-strategies/README.md:82-84`

### 3. DP Attention 改变 attention 宽度

定义：DP Attention 开启后采用 `(dp, cp, tp)` 布局，TP 是最快变化维度，attention weights/head 按更小的 attention-TP 宽度分片。[C] `sglang/01-modules/M20-parallel-strategies/README.md:87-109`

原理：`tp=8, dp=2, cp=1` 时，每个 attention DP replica 使用 4-way attention TP，而非继续 8-way。attention rank 由 `compute_dp_attention_world_info` 和 `initialize_dp_attention` 建立。[C] `sglang/01-modules/M20-parallel-strategies/README.md:89-99`

collective 路径可能包含 TP all-gather、attention-TP reduce-scatter 及 WORLD/TP all-gather，作用是把各 DP rank 的 local token 聚合成 global token buffer。[C] `sglang/01-modules/M20-parallel-strategies/README.md:102-105`

### 4. EP/MoE DP/MoE TP 是专家维度的三套坐标

定义：MoE 的并行在 `tensor_model_parallel_size` 中进一步切分为 `moe_ep_size × moe_dp_size × moe_tp_size`。[C] `sglang/01-modules/M20-parallel-strategies/README.md:135-146`

原理：`initialize_model_parallel` 派生三套坐标后构造或复用 `_MOE_DP`、`_MOE_EP`、`_MOE_TP`。满足宽度条件时 group 可能直接复用 `_TP` 或 `_ATTN_CP`。[C] `sglang/01-modules/M20-parallel-strategies/README.md:140-146`

MoE forward 边界是 dispatcher/runner：router/top-k → logical expert id → local/physical expert mapping → TP gather 或 A2A dispatch → local expert GEMM → combine。[C] `sglang/01-modules/M20-parallel-strategies/README.md:147-159`

关键约束：MoE DP 与 attention DP 的 token ownership 不一定一致。`attn_cp_size != moe_dp_size` 只有在 `moe_dp_size==1` 时支持。[C] `sglang/01-modules/M20-parallel-strategies/README.md:160-162`

### 5. collective 实现与 group 复用

定义：`GroupCoordinator` 根据 tensor 所在设备和注册的 communicator 执行 collective——GPU 走 device group/custom op，CPU 走 shared-memory 或 PyTorch distributed。[C] `sglang/01-modules/M20-parallel-strategies/README.md:163-166`

原理：排查 hang/shape mismatch 时需同时记录 group members、rank-in-group、输入/输出 shape、padding mode 和 collective 次序；只确认 world size 不足以证明拓扑正确。[C] `sglang/01-modules/M20-parallel-strategies/README.md:174-176`

group 复用风险：`_MOE_DP` 可能复用 `_ATTN_CP` 或 `_TP`，destroy 时按对象身份避免重复销毁。[C] `sglang/01-modules/M20-parallel-strategies/README.md:218-220`

## 关键参数与公式

| 参数/公式 | 含义 | 状态 |
|---|---|---|
| `world_size` | 总 GPU 数 = tp × pp（基础约束） | [C] M20:60 |
| TP group | 连续 global rank 分组 | [C] M20:73 |
| PP group | 跨区间步长分组 | [C] M20:80-81 |
| attention TP rank | `tp_rank % attn_tp_size` | [C] M20:95-96 |
| attention DP rank | `tp_rank // (attn_tp_size × attn_cp_size)` | [C] M20:97 |
| MoE 派生 | `moe_tp_size = tp_size / moe_ep_size / moe_dp_size` | [C] M20:140-143 |
| PP 中间 rank | 通过 proxy tensors 传递 hidden/residual | [C] M20:83 |
| A2A | All-to-All 是通信执行方式，不是额外切分维度 | [C] M20:21 |

## 常见误区

- **"SPTD/CPTD 是 SGLang 内置并行策略"**——错。当前 checkout 无精确匹配的 SPTD/CPTD 类或标志；必须用 TP/PP/DP/CP/EP 等实际维度描述。[C] M20:9-11
- **"PP group 是连续的 rank 编号"**——错。PP group 按跨区间步长构造，如 tp=2,pp=4,world=8 时 PP groups 为 `[0,2,4,6]` 和 `[1,3,5,7]`。[C] M20:80-81
- **"DP Attention 就是把 TP 加了一维 DP"**——不准确。DP Attention 开启后 attention 维度按 `(dp,cp,tp)` 重组，attention-TP 宽度缩小，collective 路径也不同于纯 TP。[C] M20:91-105
- **"MoE EP 和 attention TP 一定独立"**——不一定。满足宽度条件时 `_MOE_EP` 可能复用 `_TP`，group 名称不代表对象独立。[C] M20:144-146
- **"world size 够大并行就一定正确"**——错。必须校验 TP×PP 整除、DP Attention 宽度、MoE DP/EP/TP 整除、`attn_cp_size != moe_dp_size` 等约束；只看 world size 不足。[C] M20:59-68
