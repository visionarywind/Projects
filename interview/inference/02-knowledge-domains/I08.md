# I08 KV Pool / Paged Attention / Radix Cache

## 范围与定位

I08 处理推理系统中"KV 数据放在哪、谁拥有、如何复用、何时淘汰"的全生命周期。它覆盖三层：request-to-token 映射（请求行管理）、slot/page allocator（物理索引分配）、RadixCache（前缀索引复用），以及PagedAttention 的 page 抽象与淘汰策略。本域是推理系统的资源核心——admission、retraction、prefix hit、eviction 全部围绕这三层的所有权闭环展开。

与相邻域的边界：I08 不定义 attention kernel 怎么读 KV（I07），只保证 KV 物理地址有效；不定义采样/停止逻辑（I09）；不定义多卡间 KV 分布（I10）。证据结构上，SGLang 三层池模型、allocator free protocol、RadixCache 淘汰有源码级文档支撑；PagedAttention/vLLM 的 block table 与 copy-on-write 有 PDF 解析支撑；真实 GPU 显存峰值、prefix hit、eviction 未验证。

## 核心概念与机制

### 1. 三层池模型：row、index、物理 tensor 必须分清

定义：SGLang 的"池"至少分三层，各有独立 owner 和生命周期。`ReqToTokenPool` 保存 request row 到 token location 的 int32 映射；`TokenToKVPoolAllocator`/`PagedTokenToKVPoolAllocator` 管理可分配的 slot/page 索引；`MHATokenToKVPool`/`MLATokenToKVPool` 等才真正持有 GPU tensor。[C] `sglang/90-cross-module/pooling-and-resource-management.md:13-19`

原理：三层之间通过索引传递——allocator 把 slot index 写入 request row，RadixCache 再把已有 slot index 挂在 radix node 上。请求完成、未完成分块、retraction 和 eviction 必须同时更新 request row、allocator free list、radix node 引用和物理 cache 四者。[C] `sglang/90-cross-module/pooling-and-resource-management.md:20-38`

例子：row 不足 ≠ KV slot 不足。`ReqToTokenPool.alloc` 返回 None 是 admission 停止；allocator 返回 None 触发 scheduler retraction/abort。两者必须分开诊断。[C] `sglang/90-cross-module/pooling-and-resource-management.md:136-137`

### 2. PagedAttention：逻辑 block → block table → 物理 block

定义：借鉴 OS virtual memory with paging，将 request 的 KV cache 划分为固定大小的 block，block table 记录 logical block 到 physical block 的映射。[C] `insights/03-arxiv-reading-notes.md:24-31` [PDF] `insights/arxiv-pdf/2309.06180-pagedattention-vllm.md`

原理：逻辑与物理 block 分离使系统可按需增长请求 KV，不要求物理连续。小 block 和按需分配缓解 internal fragmentation，不连续物理 block 避免 external fragmentation。Parallel sampling/beam search 通过 block-level sharing 和 copy-on-write 共享 prefix block。[PDF] `insights/03-arxiv-reading-notes.md:25-29`

关键类比："blocks as pages, tokens as bytes, requests as processes"。[C] `insights/03-arxiv-reading-notes.md:28`

参数：block/page size 决定 page 内浪费与外部碎片的权衡。vLLM 论文报告 memory waste 仅来自最后一个 block 的未使用位置。[PDF] `insights/03-arxiv-reading-notes.md:30`

### 3. RadixCache：前缀索引的共享与保护

定义：RadixCache 不拥有独立 KV 数据副本，而是把已有 slot 索引挂在 radix node 上，用 `lock_ref` 将仍被请求使用的节点从可淘汰集合中保护。[C] `sglang/90-cross-module/pooling-and-resource-management.md:84-86`

原理：请求完成后 `cache_finished_req` 把 page-aligned KV indices 插入树，allocator 释放重复部分；未完成请求 `cache_unfinished_req` 插入当前 fill ids 后重新 match，更新 `cache_protected_len` 和 node lock。[C] `sglang/01-modules/M08-kv-cache/README.md:40-72`

淘汰：`evict(num_tokens)` 只从无 child 且 `lock_ref==0` 的 leaf heap 中选节点，先归还 allocator，再删除树节点，父节点无 child 且未锁定时重新进入候选堆。[C] `sglang/90-cross-module/pooling-and-resource-management.md:96-98`；`sglang/01-modules/M08-kv-cache/README.md:109-123`

### 4. Page 对齐与 partial page 生命周期

定义：paged allocator 以 page_size 为单位分配，未对齐的尾部成为 partial page——它可能属于请求工作集但不能作为完整 radix node 共享。[C] `sglang/01-modules/M08-kv-cache/README.md:66-72`

原理：`cache_protected_len` 与 `len(req.prefix_indices)` 可能不同。page_size>1 时 partial page 仍在请求工作集而不在树节点中，必须留到下一次 cache/完成路径再释放，否则泄漏。[C] `sglang/01-modules/M08-kv-cache/README.md:68-72`；`sglang/01-modules/M08-kv-cache/README.md:125-128`

例子：page_size=16、sequence_length=35 时，full pages 为 [0..15]、[16..31]，partial tail [32..34] 不能作为完整 radix node。[C] `insights/02-kv-pool-lifecycle-and-ownership.md:87-93`

### 5. Eviction Policy 是可插拔的优先级策略

定义：`EvictionStrategy` 只要求为 node 返回可比较的 priority，当前提供 LRU、LFU、FIFO、MRU/FILO、priority-aware、SLRU 等策略，但不绕过 `lock_ref` 和 page ownership 约束。[C] `sglang/01-modules/M08-kv-cache/README.md:129-133`

原理：priority-aware eviction 中较小请求 priority 先被驱逐；SLRU 的 protected 是策略分段，不等同于 Radix node 的 device lock protection。[C] `sglang/01-modules/M08-kv-cache/README.md:131-133`

| 参数/公式 | 含义 | 状态 |
|---|---|---|
| `max_total_tokens` | 物理 KV 总容量（token 数），profile 显存后投影得到 | [C] pooling:80 |

## 常见误区

- **"RadixCache 存了 KV 数据的另一份拷贝"**——错。RadixCache 只持有对已有 slot 索引的引用，不复制 K/V 数据；请求行和物理 pool 才是真实 owner。[C] pooling:18-19
- **"page_size 越大越好"**——错。大 page 减少外部碎片但增加 page 内部浪费和 partial page 生命周期复杂度；还影响 prefix sharing 粒度和 KV transfer 粒度。[I] pooling:39; K03 类比
- **"evict 的 num_tokens 等于实际释放 token 数"**——错。返回值 `num_tokens_evicted` 按 page-aligned node 长度计算，与请求的目标数可能不同。[C] M08:123
- **"finished request cache 只是放进字典"**——错。`cache_finished_req` 需组合 token ids、构造 page-aligned key、释放重复/未插入范围、释放未对齐 tail、dec_lock_ref，是多对象协同操作。[C] M08:52-66
- **"allocator free list 就是可用容量"**——错。`need_sort` 模式下释放的 indices 先进 `release_pages`，只有分配不足时才合并排序；`available_size` 计入 deferred release，但可立即取出的连续页还取决于 merge 时机。[C] M08:90-93
