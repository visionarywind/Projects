# I09 Sampling / Grammar / 停止

## 范围与定位

I09 处理模型前向之后的输出决策：logits 如何经过惩罚、约束、采样变成 `next_token_ids`，以及何时停止生成。它位于模型执行（M05）之后、结果处理（M04 result processor）之前，是"模型说每个 token 有多合适"到"实际选哪个 token"的变换层。本域覆盖 temperature/top-k/top-p 采样、logit bias、grammar 约束（结构化输出）、repetition/presence/frequency penalty，以及 EOS/stop token/stop string/max_new_tokens 等停止条件的组合。

与相邻域的边界：I09 不定义模型 forward（M05/I07），只消费其输出 logits；不定义 KV cache 组织（I08）；不定义多卡通信（I10），但 TP 要求 sampler 在 all-reduce 后的 logits 上执行，且 seed 行为在 TP ranks 间需一致。证据结构上，logits 变换顺序、grammar mask 编译、sampler backend 路径有源码级文档支撑；真实约束输出、logprob、custom processor 的 GPU 行为未验证。

## 核心概念与机制

### 1. logits 变换顺序：penalty → grammar mask → logit bias

定义：模型输出的原始 logits 需经多层变换后才送入 sampler，顺序直接影响采样分布。[C] `sglang/01-modules/M10-sampling-constraints/README.md:59-72`

原理：`apply_logits_bias` 按 pre-grammar transforms → grammar mask → post-grammar logit bias 的顺序执行。pre 阶段含 additive/scaling penalty 或非 overlap penalizer；grammar mask 把非法 token 概率置零或负无穷；post 阶段加入用户指定的 logit bias。[C] `sglang/01-modules/M10-sampling-constraints/README.md:59-72`

关键不变量：这是 device logits 的原地/近原地变换，mask、penalty、batch 行顺序都属于执行正确性的一部分，不能当作纯 Python 后处理。[C] `sglang/01-modules/M10-sampling-constraints/README.md:71-72`

### 2. Grammar mask：结构化输出的编译时约束

定义：grammar 把 JSON schema、regex、structural tag 编译成 vocab mask，在采样前屏蔽所有不满足当前语法状态的 token。[C] `sglang/01-modules/M10-sampling-constraints/README.md:79-84`

原理：grammar backend 通过 `allocate_vocab_mask`、`fill_vocab_mask_batched`、`move_vocab_mask` 约定提供 mask。编译采用 cache + future 模式——首次到达提交 `_init_value_dispatch` future，命中缓存返回 `value.copy()` 让每个请求拥有独立 matcher 状态。[C] `sglang/01-modules/M10-sampling-constraints/README.md:97-107`

失败传播：future 超时进入 failed 集合，在 DP/TP 组内取 ready 交集、failed 并集；编译失败转 `InvalidGrammarObject`，通过 `req.set_finish_with_abort` 转为请求级失败，而非把异常留在 sampler 内。[C] `sglang/01-modules/M10-sampling-constraints/README.md:99-103`

### 3. Sampler backend 路径：greedy / flashinfer / pytorch

定义：sampler 按 batch 中是否存在非 greedy 请求分为 argmax 直接输出和概率采样两条主路径。[C] `sglang/01-modules/M10-sampling-constraints/README.md:109-128`

原理：全 greedy batch 直接 `argmax`。标准概率路径按 temperature 缩放后选 flashinfer 或 pytorch backend：PyTorch fallback 先排序、按 top-k 和累计 top-p 置零、按最大保留概率乘 min-p 过滤，最后 `torch.multinomial` 或带 seed 的 `multinomial_with_seed`。[C] `sglang/01-modules/M10-sampling-constraints/README.md:111-117`

seed 行为：flashinfer 复杂路径要求 seed 为空；PyTorch 带 seed 路径把过滤后概率转 float64 log-probability 后调用 `multinomial_with_seed`，明确承认过滤后未重新归一化的数值限制。[C] `sglang/01-modules/M10-sampling-constraints/README.md:125-127`

### 4. Sampling batch info 的过滤与 overlap 生命周期

定义：continuous batching 会动态加入/移除请求，`SamplingBatchInfo.filter_batch` 必须同步过滤所有采样字段。[C] `sglang/01-modules/M10-sampling-constraints/README.md:133-137`

原理：filter_batch 同步过滤 penalty orchestrator、custom processor、temperature/top-p/top-k/min-p、seed、logit bias 和 return mask；custom processor 的 mask 全 False 时清除对应 processor。[C] `sglang/01-modules/M10-sampling-constraints/README.md:135`

overlap 下 sampling 被包装为 delay closure，捕获 logits/forward batch；scheduler 处理完成后必须释放 closure 和 logits tensor，否则 grammar mask 和 logits 延迟释放。[C] `sglang/01-modules/M10-sampling-constraints/README.md:136-137`

### 5. 停止条件是协作结果，非 sampler 单独决定

定义：sampler 只产生 token id；是否遇到 EOS、stop token、stop string、max_new_tokens、grammar termination，以及 token 如何转输出文本，由 M04 result processing + 请求状态 + M03 detokenization 协作完成。[C] `sglang/01-modules/M10-sampling-constraints/README.md:139-150`

原理：新增停止条件需检查 SamplingParams normalize/verify、scheduler-side Req finish 判断、grammar 是否 rollback/terminate、`BatchStrOutput.finished_reasons`、M03 ReqState 删除五个层次。[C] `sglang/01-modules/M10-sampling-constraints/README.md:143-149`

## 关键参数与公式

| 参数 | 含义 | 状态 |
|---|---|---|
| temperature T | logits 缩放因子：`logits / T`；T→0 趋 greedy，T→∞ 趋均匀 | [C] M10:114 |
| top-p (nucleus) | 累积概率阈值，保留最小 token 集使累计概率 ≥ p | [C] M10:115-116 |
| top-k | 保留概率最高的 k 个 token | [C] M10:115 |
| min-p | 相对过滤：保留概率 ≥ max_prob × min_p 的 token | [C] M10:117 |
| repetition_penalty | 已出现 token 的 logits 缩放（>1 抑制重复） | [C] M10:60-62 |
| presence/frequency_penalty | 基于出现次数/频率的加法惩罚 | [C] M10:60-62 |
| grammar mask | vocab 大小的 bool tensor，true 表示当前语法允许 | [C] M10:48-49,80 |
| max_new_tokens | 最大生成 token 数（停止条件之一） | [C] M10:32 |
| seed | 采样随机数种子（flashinfer 复杂路径不支持） | [C] M10:125-127 |

## 常见误区

- **"grammar 约束等于生成后修正文案"**——错。grammar mask 在 logits 层面就把非法 token 屏蔽掉，不是生成后再检查修正。[C] M10:28-29
- **"sampling 是纯 Python 后处理"**——错。mask、penalty 和 batch 行顺序都在 device 上执行，是执行正确性的一部分，overlap 下还涉及 tensor 生命周期。[C] M10:71-72
- **"sampling mask 等于 grammar mask"**——错。sampling mask 描述实际采样分布/观测结果，grammar mask 描述语法允许集合；生命周期不同，`_preprocess_logits` 清空 grammar mask 不代表 sampling mask 已完成传递。[C] M10:131
- **"flashinfer 采样支持任意 seed"**——错。flashinfer 复杂采样路径要求 seed 为空，只有 PyTorch 带 seed 路径支持可复现采样。[C] M10:125-126
- **"停止条件由 sampler 判断"**——错。sampler 只产出 token id；停止是 M04 result processing、请求状态、M03 detokenization 协作结果。新增条件必须同时检查五个层次。[C] M10:139-149
