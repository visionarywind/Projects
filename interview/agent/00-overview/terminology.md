# 术语表

| 术语 | 本题库中的工作定义 | 易混概念 |
|---|---|---|
| Agent | 在约束下由模型选择下一行动并读取反馈的系统 | workflow、chatbot |
| run / task / turn / step | 一次任务、一次执行实例、模型回合和单个状态推进 | 不应混为同一生命周期 |
| observation | 工具、检索或环境返回给模型的结果 | 最终用户答案 |
| tool call | 带名称和结构化参数的外部动作请求 | 普通文本中的函数名 |
| tool schema | 描述参数类型、必填项和约束的机器可校验契约 | 仅供人看的 API 文档 |
| planner / executor | 规划下一步与实际执行的逻辑角色 | 不一定是两个进程 |
| workflow | 由代码预先定义步骤/分支的流程 | 开放式 Agent loop |
| memory | 跨回合保留、可检索并影响未来决策的状态 | 原始上下文、RAG 文档 |
| grounding | 将回答绑定到可核验外部证据 | 只生成引用格式 |
| trace / span | 一次 run 及其子操作的关联观测记录 | 普通日志行 |
| oracle | 判定输出或轨迹是否符合要求的规则/参考 | LLM judge 分数本身 |
| idempotency | 同一业务操作重复执行的效果等同于执行一次 | retry |
| prompt injection | 不可信内容改变系统行为或指令优先级的攻击 | 正常用户需求 |
| indirect injection | 注入藏在网页、文档、工具结果或记忆中 | 直接用户注入 |
| human-in-the-loop | 在高影响动作前由人确认、拒绝或接管 | 事后人工抽检 |
| compaction | 压缩历史上下文以继续长任务 | 永久长期记忆 |

术语会随版本和框架变化；题目使用的是机制层定义，具体 API 必须附版本和来源。
