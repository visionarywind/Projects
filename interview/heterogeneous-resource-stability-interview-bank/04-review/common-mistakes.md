# 常见误区与反例

1. **设备 ID 等于可用能力**：忽略型号、版本、dtype、拓扑和动态资源。
2. **提交返回成功等于执行完成**：忽略 Driver/设备异步边界。
3. **超时等于未执行**：超时通常只能证明观察窗口内没有完成证据。
4. **超时后立刻释放内存**：可能仍被设备任务引用。
5. **无限重试可以提高可用性**：可能重复副作用并放大拥塞。
6. **总显存等于可分配容量**：忽略碎片、对齐、池、模块和并发竞争。
7. **不同厂商同名 API 语义相同**：上下文、队列、事件和错误码必须查目标实现。
8. **平均延迟代表稳定性**：应看尾延迟、错误率、恢复时间和资源水位。
9. **重启是完整恢复方案**：可能丢证据，且设备/驱动残留状态仍未知。
10. **监控字段越多越好**：字段要能关联设备、Context、任务、资源和时间线，并控制开销。
