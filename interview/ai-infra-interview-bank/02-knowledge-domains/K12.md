# K12 MLOps、发布与平台演进

## 范围与定位

本域覆盖"代码与模型从改动到上线"的链路：配置与权重兼容性、测试与变体矩阵、灰度与回滚、平台能力的逐轴演进。它是把 K07–K11 串成流程的一层——数据、并行、调度、性能、可靠性最终都要通过一次可回滚的发布落地。

证据边界：本仓库对 MLOps **没有成型方法论文档**，可支撑的是三类硬事实——加载/兼容的失败语义、CI 测试的证据等级、部署状态机的分支；灰度比例、审批门禁、回滚时限、模型注册表与血缘工具链一律 [待验证]。贯穿全篇的元规则是：**测试文件存在只证明入口存在，suite 被注册只证明配置存在，只有实际日志和结果才证明某次运行成功** [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:72`。

## 核心概念与机制

### 1. 加载链与兼容判定：发布物的第一道闸门

- **定义**：一次发布要同时说清运行参数、模型能力、权重怎么读进来，以及旧 checkpoint 能否复用。
- **原理**：加载链 `ServerArgs → ModelConfig/LoadConfig → architecture resolution → get_model_loader → 实例化 → 遍历 checkpoint 权重 → PP filter/remap/weight_loader → post-load + quant → barrier / LoadedModel` [已确认] `sglang/01-modules/M06-model-loading/README.md:22-32`；三层配置必须分开——raw server arguments、`ModelConfig`（HF config 与能力解析）、`LoadConfig`（load format、device、cache、remote/presharded 策略）[已确认] `sglang/01-modules/M06-model-loading/README.md:38-44`。checkpoint 侧由 `check_checkpoint_args` 拒绝或警告关键结构参数不匹配，**异步保存与 non-persistent/local checkpoint 的清理恢复语义尚未实测** [已确认] `megatron-lm/01-modules/M05-optimizer-checkpointing/README.md:45`。
- **不变量**：完成边界是 `dist_barrier_after_load`（TP CPU group `monitored_barrier`），某 rank 异常时超时转为说明性 `ValueError`，**阻止一个 rank 单独推进到 ready** [已确认] `sglang/01-modules/M06-model-loading/README.md:125`；失败分四类：architecture 不支持、shape/dtype/TP 不匹配、load format/依赖不可用、单 rank 失败 [已确认] `sglang/01-modules/M06-model-loading/README.md:218-222`。TP/PP/CP 改变归约顺序，**只保证数学等价、不保证逐位一致**，验收用梯度范数、loss 曲线与层参数 diff [已确认] `insights/05-megatron-architecture.md:1244`。
- **例子**：presharded 路径只有 `READY` 文件存在**且** `checksum.json` 的 shard config 完全匹配才命中；加载计划带版本号与 `rank_to_reads`，**版本不匹配或参数缺失会失败，而不是把旧 cache 当兼容格式继续用** [已确认] `sglang/01-modules/M06-model-loading/README.md:160`，并行拓扑、量化或 expert placement 变化都会产生新的 presharded 子目录 [已确认] `sglang/01-modules/M06-model-loading/README.md:162`。TP 从 8 改到 4 后若只警告不拒绝，可能带着错位 shard 上线 [推断]。

### 2. 测试分层与变体矩阵：发布门禁的构成

- **定义**：把测试按"能证明什么"分层，并明确每层覆盖的变体维度。
- **原理**：registered 测试适合稳定可入 CI 的行为；manual 需要特定模型、GPU、网络或人工环境；**benchmark 衡量吞吐/延迟/显存/kernel 性能，不能作为 correctness 测试** [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:35`。变体矩阵五维：backend/device、API、execution（eager/CUDA Graph/speculative/chunked prefill）、model/input（text/多模态/MoE/quant/LoRA）、deployment（单进程/多进程/分离/gateway）[已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:52-60`。
- **不变量**：调度侧自动分片用历史 `est_time` 做贪心 LPT 并以文件名打破平局保证确定性 [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:33`；**修改 suite filter、环境变量或分片逻辑会造成"绿色但未执行目标测试"**，须同步更新注册、估时与报告 [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:72`。数值不一致的隔离序是 `单卡 eager → 多卡 → graph 开关 → TP/PP → DP/CP → EP/A2A → 推测量化`，该矩阵是排查建议、**不代表已执行** [已确认] `insights/07-parallel-and-backend-capability-matrix.md:228-242`。
- **例子**：改 sampling penalty 后先用最小 suite 验证普通 eager 路径，**随后才**比较 `benchmark/` 中的吞吐；改 IPC payload 则先看 tokenizer manager 与 `SGLANG_USE_PICKLE_IPC` 变体，而不是直接跑完整 nightly [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:64`。

### 3. 发布状态机：滚动更新、健康检查与回滚

- **定义**：发布不是替换二进制，而是有目标态、观测与回退的控制器循环。
- **原理**：Ray Serve 链路 `Deployment.bind → serve.run → Controller.deploy_applications → DeploymentState target/reconcile → replica start/health → router → DeploymentHandle.remote`；滚动更新、autoscaling、health check、backpressure 都是改变状态机的分支，部署或 replica 失败时 controller 可重试、替换或标记 unhealthy [已确认] `ray/01-modules/M12-serve/README.md:14-33`。
- **不变量**：每个分支必须补齐五项——容量边界、owner、失败恢复、指标、**回滚方式**；缺回滚方式的分支等于没设计完 [已确认] `insights/04-design-decision-and-validation.md:65`。灰度比例、观察窗口与自动回滚阈值本仓库无文档 [待验证]。
- **例子**：`serve.shutdown/delete` 的真实时序未验证 [已确认] `ray/01-modules/M12-serve/README.md:33`——"有优雅关闭入口"不等于"关闭耗时可预测"，回滚窗口必须实测。

### 4. 平台演进：逐轴迁移与证据纪律

- **定义**：能力扩张（单机→多卡→集群→混合负载）必须按可隔离的轴推进，每次只改一个变量。
- **原理**：能力矩阵把拓扑/布局、通信/交换、计算/执行、调度/隔离分开描述，`world_size = tp × pp` 等整除约束是硬门槛 [已确认] `insights/07-parallel-and-backend-capability-matrix.md:8-57`；推荐形态是从 GPU-only baseline 起步，逐项加入分片 offload、异步 prefetch、partial recompute，每步单独测量 [已确认] `insights/04-design-decision-and-validation.md:96`。
- **不变量**：环境先固定再改——CANN 调试第一步是"固定版本、SoC、Toolkit、Driver/Firmware 和构建选项" [已确认] `cann/99-roadmap/debugging-guide.md:16`；性能结论一律标注环境与开关状态，热路径新增日志/断言/锁要在关观测开关的构建下复测 [已确认] `musa/99-roadmap/performance-guide.md:87-88`。
- **例子**：从 eager 演进到 CUDA Graph 会同时改变 shape、KV 与状态生命周期 [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:58`；应先关 graph 跑 correctness，再开 graph 跑同一组测试，最后才比 benchmark——一次同时改 graph 与 batch 策略会失去归因能力 [推断]。

## 常见误区

1. **"目录里有 checkpoint 就能加载"**。presharded 要求 `READY` + 指纹完全匹配，版本不匹配必须失败而非兼容降级 [已确认] `sglang/01-modules/M06-model-loading/README.md:160-162`。
2. **"测试全绿说明改动没问题"**。改 filter、环境变量或分片逻辑会造成"绿色但未执行目标测试" [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:72`。
3. **"benchmark 可以当唯一门禁"**。benchmark 不能替代 correctness，且无上下文的 benchmark 结果不可比较 [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:35,50`。
4. **"逐位一致才叫没回归"**。改并行度后浮点顺序变化，逐位比较必然失败 [已确认] `insights/05-megatron-architecture.md:1244`。
5. **"一次改 graph、batch、并行度，效果好就上"**。同时改多变量会失去归因能力，execution 维度自带独立风险 [已确认] `sglang/01-modules/M18-testing-benchmark-ci/README.md:58`。
