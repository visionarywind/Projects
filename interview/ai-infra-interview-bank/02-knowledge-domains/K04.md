# K04 PCIe、NVLink、RDMA 与网络

## 范围与定位

K04 处理数据如何离开一块 GPU：互联拓扑的分层（片上/机内 NVLink 域、PCIe 域、跨机 RDMA 域）、各层带宽量级、集合通信在这些域上的路径选择，以及推理侧 PD 分离中 Prefill 到 Decode 的 KV 传输。它上游接 K01 的带宽上限与 K02 的 stream/event 依赖表达，下游接 K06 的拓扑感知调度与放置策略。

与相邻域的边界：K01 只把互联带宽当作 roofline 的一个输入数字，不讲算法；K03 只讲 KV 数据的所有权与分页粒度，不讲它怎么跨卡移动；K06 讲"任务放到哪台机器"，K04 讲"放好之后数据走哪条链路"。两者以拓扑域为接口。

**证据薄弱声明：本仓库在 RoCE/网卡队列、PCIe 通道协商、GPUDirect 驱动细节上无源码沉淀，下面相关小节均为通用机制说明，版本与型号相关行为标 [待验证]，不编造具体带宽数值与版本参数。** 仓库有硬证据的部分集中在 Ring AllReduce 的通信量推导与拓扑感知排布法则。

## 核心概念与机制

### 1. 拓扑域与带宽分层

定义：把 GPU 之间的可达路径按物理介质分域——NVLink/NVSwitch 域（同节点高带宽）、PCIe 域（经 root complex 或 PCIe switch）、RDMA 域（跨机网卡）。

工作原理：通信量最大的轴应当落在带宽最高的域。MT-NLG 的排布法则是：**TP > DP > PP** 的通信量排序，因此 TP 组放同节点（NVLink），DP 尽量同节点或近邻，PP 可跨节点 [已确认] `insights/05-megatron-architecture.md:867-869`。

关键不变量：高通信量的轴优先靠近物理拓扑高带宽的域 [推断] `insights/05-megatron-architecture.md:871`；EP 组一旦跨节点且 NVLink 不全覆盖，all-to-all 走到 IB/RDMA，延迟显著上升 [已确认] `insights/05-megatron-architecture.md:1003`。

例子：TP(+SP) 每层 4 次 allreduce 标为"高"体积并绑定同节点 NVLink；PP 的 stage 边界 P2P 标为"低"体积并允许跨节点 [已确认] `insights/05-megatron-architecture.md:891-897`。

### 2. Ring AllReduce 的通信量

定义：Ring 算法把 N 个 rank 排成环，分两阶段走 2(N−1) 步：reduce-scatter 收集部分和，all-gather 摊平结果。

工作原理：每步每 rank 只收发 `S/N` 字节（S 为数据总量），共 2(N−1) 步，故单 rank 通信量为 `2·(N−1)/N · S`；当 N→∞ 时趋近 2S，**与参与方数量弱相关**。仓库原话是"通信体积随 t 变化但 ring allreduce 的带宽消耗与 t 弱相关（约 2·(t-1)/t · 数据量）" [已确认] `insights/05-megatron-architecture.md:599`，逐条公式见 [已确认] `insights/05-megatron-architecture.md:604`。

关键不变量：ring all-reduce 本质 = reduce-scatter + all-gather 两步，因此"4 次 all-reduce"与"4 次 all-gather + 4 次 reduce-scatter"在带宽维度等价 [已确认] `insights/05-megatron-architecture.md:698`。

例子：TP 规模为 t、激活为 `s·b·h` 时，每层四个原语合计约 `8·s·b·h·(t-1)/t` 个元素 [已确认] `insights/05-megatron-architecture.md:605`。

### 3. 集合通信的链路选择

定义：同一个 allreduce/all-to-all 原语，选择在哪个物理域、由哪些链路并行承载。

工作原理：域内（NVLink/NVSwitch 全互联）ring 的每一步都能跑满双向带宽；跨域时 ring 的一段退化成 PCIe 或 NIC 路径，成为整条环的短板。仓库把这表达为"axis order + 节点映射共同决定谁跟谁共享通信域"，若把 DP 放最内、TP 放最外，同样 16 个 rank 会得到完全不同的通信组划分 [已确认] `insights/05-megatron-architecture.md:913-929`。

关键不变量：axis order 决定 rank 坐标解码，通信域划分不能只看并行度数值。

例子：`axis order = [TP, PP, DP]`、world=16 时 rank 5 解码为 `tp=1, pp=0, dp=1`；换序后同一 rank 归属的 TP 组完全不同 [已确认] `insights/05-megatron-architecture.md:917-927`。

### 4. PD 分离中的 KV 传输

定义：Prefill 与 Decode 部署在不同实例，中间要把 prefill 产出的 KV 交给 decode 实例消费。

工作原理：P/D-Serve 指出 prefill 的 intermediate data 即 KVCache 需在 P/D 之间传输，且在数万 xPU 规模下可靠性能面临挑战；三个挑战是请求/prefix 多样性、workload 估计不准导致 P/D 比例与迁移问题、cluster-level RDMA 上 block-fixed D2D 传输难达理想利用率 [已确认] `insights/03-arxiv-reading-notes.md:111-114`。

关键不变量：P/D 把 KV ownership 从单进程 allocator 扩展为跨实例协议，transfer layer 必须 idempotent、有 backpressure 和错误恢复 [已确认] `insights/03-arxiv-reading-notes.md:118`；"pool management"不能简单等同于一个全局共享内存池 [已确认] `insights/03-arxiv-reading-notes.md:122`。

例子：KVPR 说明 offload 后瓶颈会转移到 CPU-GPU PCIe 带宽，导致恢复 KV 时 GPU 空转；其解法是传一部分就先算一部分，让 PCIe 传输与计算 overlap [已确认] `insights/03-arxiv-reading-notes.md:90-92`。

### 5. GPUDirect 路径的收益与耦合（通用机制）

定义：GPUDirect 类路径允许设备内存与远端设备/网卡直接交换，绕过 host 内存中转。

工作原理（通用原理，本仓库无 GPUDirect 源码）：省掉的是一次"device→host staging→device"的往返拷贝与对应的 pinned buffer 管理；代价是生命周期耦合——参与传输的显存区在网卡/DMA 完成前不可释放、不可迁移，且注册（pin/register）本身成为新的失败点与串行化点。

关键不变量：没有完成证据（event/completion）之前，被 DMA 引用的 buffer 既不能复用也不能卸载注册 [推断] 由 K02 完成语义与 K03 生命周期不变量导出。

例子：K03 中 `rtFreeWithDevSync` 必须先同步设备再释放 [已确认] `cann/90-cross-module/memory-and-resource-lifecycle.md:101`——去掉 host 中转并不会改变这条约束，只是把"同步"的对象从计算队列扩展到传输队列。

## 常见误区

- **"参与方越多，AllReduce 越慢越多"** —— 错。ring 的每步只搬 `S/N`，总步数 2(N−1)，单 rank 通信量是 `2(N−1)/N·S`，N 翻倍后该系数只从 1.0 涨到 1.75 而不是翻倍；真正的成本来自延迟项 `原语次数 × 延迟` 和跨域短板 [已确认/推断] `insights/05-megatron-architecture.md:599,1096`。
- **"把 all-reduce 拆成 all-gather + reduce-scatter 一定更贵"** —— 错。ring all-reduce 本来就是这两步，拆开只是重排位置，带宽维度等价，这正是 sequence parallel 不引入额外通信开销的依据 [已确认] `insights/05-megatron-architecture.md:698`。
- **"NVLink 和 PCIe 差不多，拓扑不用管"** —— 错。排布法则直接建立在"TP 最好同节点"上；一旦高通信量轴被放到低带宽域，增加卡数只会放大差距 [已确认] `insights/05-megatron-architecture.md:608,622`。
- **"GPUDirect 消除了所有拷贝和所有等待"** —— 错。它省的是 host 中转拷贝，不省设备端读写；同时把 buffer 生命周期与传输队列绑死，完成前不可复用。
- **"PD 分离只要把 KV 发过去就行"** —— 错。ownership 跨实例后，传输层必须自带幂等、backpressure 与错误恢复，否则 P/D 比例调整与迁移会放大失败面 [已确认] `insights/03-arxiv-reading-notes.md:113,118`。
