## 核心概念与机制

### 1. lease 与 spillback：Ray 的调度单元

Raylet 不是抽象调度器，而是由 NodeManager、WorkerPool、资源管理器、local/cluster lease manager 协作完成节点内匹配、集群 spillback、worker 生命周期与任务派发 [已确认] `ray/01-modules/M04-raylet-scheduling/README.md:7-19`。

代表链 [已确认] `ray/01-modules/M04-raylet-scheduling/README.md:10-19`：

```
NormalTaskSubmitter::RequestNewWorkerIfNeeded
→ lease policy 选目标节点
→ NodeManager/ClusterLeaseManager RequestWorkerLease
→ 本地资源/worker 可用匹配
→ WorkerPool grant/register
→ PushNormalTask → task execution
```

spillback 规则 [已确认] `ray/01-modules/M04-raylet-scheduling/README.md:39`：本地资源充足时优先本地 lease；否则按 locality 与集群策略 spillback/redirect 到远端节点。

### 2. Gang scheduling 的必要性

分布式训练（TP/PP）要求一组 worker **全部启动**才能开始计算。若只启动部分——如 8 卡 PP 只调度到 7 张卡，第 8 张被另一个任务占用——结果不是"慢一点"，而是整个作业 deadlock 等卡。Gang scheduling 要么一次性分配全部资源，要么一个不分配 [推断]。

工程影响：gang 分配放大了调度失败率——尤其是碎片化的集群，少量大块请求就能把剩余 GPU 切成无法服务任何 gang 的碎片 [推断]。

### 3. Continuous batching 调度

SGLang 的 scheduler 主循环每轮先收新请求，再看 running 资源，然后从等待队列挑选新任务交错执行 prefill/decode——不等一个请求结束才接下一个 [已确认] `sglang/01-modules/M04-scheduler-batching/README.md:13-15`。

关键结构 [已确认] `sglang/01-modules/M04-scheduler-batching/README.md:17`：
- `Req`：单个请求的调度态（input ids、output_ids、KV 信息、finish 状态）。
- `ScheduleBatch`：一次 forward 的调度快照（请求池、KV allocator、prefix cache、forward mode、device tensor）。

资源不足时的降级 [已确认] `sglang/01-modules/M04-scheduler-batching/README.md:34`：`retract_decode` 释放/备份或 abort 低优先级请求。

## 常见误区

- "资源够分就能调度"：gang 调度要求全部满足，部分满足反而浪费资源并可能死锁。
- "连续 batching 等于动态 padding"：前者是请求级交错（不同请求 prefill/decode 混批），后者是 batch 内补齐；两者正交。
- "preemption 就是 kill 任务"：推理 preemption 通常 retract 低优先级请求并保留可恢复状态（KV/Req 元数据），不是简单 kill。
