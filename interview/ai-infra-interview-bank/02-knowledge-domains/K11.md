# K11 可靠性、安全与供应链

## 范围与定位

本域处理三类"不正常"：**错误如何被记录与传播**、**出错后如何定位与恢复**、**外部代码如何把风险带进来**。与 K10 的分工是本域解释"错"与"能不能信"。四个代码库的表述一致：错误必须**分层传播并保留最底层上下文**——CANN 的错误流是 `设备/驱动 → Runtime rtError_t → ACL aclError 或 GE graphStatus → 日志/回调/返回值` [已确认] `cann/00-overview/global-error-model.md:14-23`，其诊断原则第二条是"不以 `ACL_SUCCESS`/`GRAPH_SUCCESS` 推断任务完成，异步路径必须同步或等事件" [已确认] `cann/00-overview/global-error-model.md:39-43`；Ray 则写"有 fault-tolerance 文档 ≠ 每条路径自动重试" [已确认] `ray/00-overview/global-error-model.md:21-23`。

证据边界：本仓库**没有**供应链/SBOM/依赖与权重扫描文档，也没有安全边界实测，相关内容一律 [待验证]。

## 核心概念与机制

### 1. 错误分类与分层传播

- **定义**：错误模型是"从哪层产生、经哪些转换、被谁看到"的地图，分类决定处理动作。
- **原理**：CANN 六类各配动作——参数错误改参数不重试、状态错误按生命周期补齐、资源错误记录后按策略清理/重试、设备驱动查固件、编译模型回编译配置、异步错误等完成通知并保留原始错误 [已确认] `cann/00-overview/global-error-model.md:30-37`；Ray 按边界分七类：API 输入、序列化、调度、用户代码、对象、控制面、环境 [已确认] `ray/00-overview/global-error-model.md:11-19`。
- **不变量**：分层转换必须是可逆的证据链，Runtime 门面、ACL 映射、GE 异步回调三个转换点都保留原始错误码 [已确认] `cann/90-cross-module/error-boundaries.md:14-24`；Megatron 边界表覆盖 7 类且自述"没有实测异常输出" [已确认] `megatron-lm/90-cross-module/error-boundaries.md:15-25`。
- **例子**：异步提交返回成功只说明当前阶段未被拒绝，错误可能在设备执行或 callback 才暴露，顶层 `ACL_ERROR` 不足以复盘 [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:388`。
- **资源路径的两个窗口**：每条路径有"提交前/本地失败"与"跨层失败窗口"，清理语义不同——KernelMemoryPool 要求池对象与 Driver backing 成对释放；`rtMalloc` 失败保留 device/size/policy 与原始错误；SOMA async malloc 失败可能把 BUSY 段转成 CACHED；**async free 的 Driver V3 free ioctl 失败明确不回滚**，本地与设备侧状态可能暂不对称 [已确认] `cann/90-cross-module/error-boundaries.md:26-34`；`MemPoolTrimImplicit` 直接成功返回，**不能把调用点当成实际回收** [已确认] `cann/90-cross-module/error-boundaries.md:34`。

### 2. 异步失败的三态 SUCCESS / FAILURE / UNKNOWN

- **定义**：超时或进程崩溃后任务真实结果未知，不能二值化。
- **原理**：先标 `UNKNOWN`，完成成功才归一化为成功，完成失败则保留原始错误、按幂等性决定重试或降级 [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:407-418`。**不变量：`UNKNOWN` 不得直接转 `FAILURE` 并重试（可能已产生外部副作用），也不得直接转 `SUCCESS` 并释放资源** [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:424`；未证明完成前不复用其 Memory、Model、Stream 与 callback data [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:420`。
- **例子**：训练 job 在写 checkpoint 时被 kill，若假设"上次没写成"直接覆盖，可能把半写文件当完整状态；应靠 tracker 的最终提交标记判定，而非进程是否存活。

### 3. 诊断方法：先分类，再采证，最后落到第一个失败边界

- **定义**：可复现的诊断 = 分类 → 固定证据 → 最小定位 → 单变量验证。
- **原理**：MUSA 调试指南第一步是"先分类"（库加载、初始化、context、地址与异步 free、卡住与顺序、模块加载、capture/拓扑共 7 类），第二步采证——保留 commit、配置、设备 ordinal、context/stream id、API/correlation id、MUresult 和同步点，并写明"不要用未执行命令的预期输出替代日志" [已确认] `musa/99-roadmap/debugging-guide.md:12-24`；CANN 的 5 步法强调第一个失败边界，按 ACL → Runtime → HAL → SDK 下钻 [已确认] `cann/99-roadmap/debugging-guide.md:14-31`。
- **不变量**：`Find` 返回 `nullptr` 而 `Get` 返回"最近节点"，语义不同；`FindPool` 处源码直接 `->m_Value` 无空检查 [已确认] `musa/99-roadmap/debugging-guide.md:41`；根因要走到结构层并验证 [已确认] `musa/99-roadmap/rca-splaytree-memmgr.md:14-84`。症状是"某类分配偶发返回错误指针"时，只补空检查会在下一个调用点复发。

### 4. 供应链与安全边界

- **定义**：供应链风险指代码、模型权重、数据、镜像与第三方依赖进入系统时带入的未知性。
- **原理**：本仓库能支撑的只有边界原则——第三方源码不复制、profiling 输出与生成物不纳入知识库、git submodule 不算本项目实现 [已确认] `LeetCUDA/01-modules/M11-triton-cutlass-profiling/README.md:15-17`；Ray 把 dependency/runtime_env/image 失败单列为一类边界 [已确认] `ray/00-overview/global-error-model.md:19`；日志与 DFX 是旁路设施，**不改变资源所有权** [已确认] `cann/00-overview/global-error-model.md:43`。能力快照有时间属性，只能作为提交前准入检查，静态能力与动态水位必须分离并在真正分配处再次验证 [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:183`。
- **边界 [待验证]**：本仓库无 SBOM、依赖版本锁定、权重签名、数据来源校验与镜像扫描文档，相关机制须在真实环境另行建立。

## 常见误区

1. **"API 返回成功 = 任务完成"**。诊断原则明确禁止用返回码推断异步完成 [已确认] `cann/00-overview/global-error-model.md:42`。
2. **"只记录最上层错误码就够"**。丢掉设备、Context、阶段与原始码就无法复盘 [已确认] `cann/90-cross-module/error-boundaries.md:47-49`。
3. **"超时就当失败，直接重试"**。`UNKNOWN` 可能已写文件、改状态或占资源，盲目重试会放大损害 [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:424`。
4. **"有容错配置就等于每条路径都会重试"**。Ray 把这条明确写成反例 [已确认] `ray/00-overview/global-error-model.md:23`。
5. **"加资源就能恢复"**。若根因是 Context/Stream 生命周期用错，加设备只会扩大泄漏范围 [已确认] `interview/heterogeneous-resource-stability-interview-bank/01-question-bank/beginner.md:99`。
