# K02 分布式初始化与通信组

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。

## 范围

本域回答"一张 GPU 集群如何被切成正交的通信域，以及每个 rank 在哪个域上做哪种 collective"。核心对象是 `process group`（可独立做 collective 的 rank 子集）、`parallel_state` 的 accessor、`ProcessGroupCollection`，以及 `RankGenerator` 的 rank 坐标映射。

本域**不负责**：模型层如何消费通信域（见 K04/K06/K07）、优化器是否分片（K08 决定，本域只提供通信域）、NCCL 实际算法与带宽（`U`）。

## 先修知识

- `torch.distributed` 的 group 语义与 `new_group`。
- 集合通信三种原语：`all-reduce`、`reduce-scatter`、`all-gather`。
- 并行轴的基本含义（K04/K05/K06 各展开一层）。

## 核心机制

### 1. 从 global group 到正交通信域

训练不是"一个程序跑在多卡"，而是一组通信域上的协同（`C`，`M02-parallelism/README.md` 并行轴表）：

```text
torch.distributed.init_process_group()        # global group, world_size
  -> initialize_model_parallel(...)
       RankGenerator(axes) -> get_ranks(mask) -> list[rank]
       torch.distributed.new_group(ranks, backend)   # 每轴一组
  -> parallel_state 保存 accessor
  -> layer: get_tensor_model_parallel_group()
            -> dist.all_reduce(tensor, group=that_group)
```

| 轴 | 作用 | 主要状态 |
|---|---|---|
| TP | 切分单个权重/算子（hidden/head 维） | tensor model parallel group |
| PP | 切分层与 stage，P2P 传激活 | pipeline group、P2P |
| VP | 每个 PP rank 持有多个虚拟 chunk | virtual pipeline rank/world size |
| DP | 复制模型并归约梯度 | data parallel group |
| CP | 切分序列激活，梯度归约复用 DP 域 | context parallel group |
| EP | 切分 routed experts | expert model/data groups |
| GTP | 权重 rematerialization 轴 | GTP weight remat group |

（`C`，`M02-parallelism/README.md` 并行轴表与 `insights §8/§9/§10`。）

模型层不自行推导全局 rank，而是通过 `parallel_state` 的 accessor（如 `get_tensor_model_parallel_group()`）或显式 `ProcessGroupCollection` 拿到"我该在哪个组通信"（`C`，`M02-parallelism/design.md:14-19`）。新代码倾向显式传组，旧的全局 MPU/`parallel_state` 兼容接口仍在并存（`C`，`architecture.md` 关键边界）。

### 2. `initialize_model_parallel`

函数首先校验 distributed 状态与并行参数，计算模型规模与 data parallel size；随后分别创建 decoder/expert 两个 `RankGenerator`，按固定顺序创建 DP/CP、partial-DP、GTP、TP、PP、embedding、position-embedding 等 group，并可创建 Gloo group、应用 NCCL 配置、SHARP 与高优先级 stream 配置（`C`，`parallel_state.py:600-1029`）。

注意：`world_size` 的可整除约束并非只看 TP——CP、PP、GTP 与 expert 侧尺寸都会改变约束。初始化还会保存当前 rank 对应的全局 ranks 供 accessor 返回。

### 3. `RankGenerator` 的正交生成

`RankGenerator(tp, ep, dp, pp, cp, order, rank_offset, gtp_remat)` 把未参与计算的轴压缩为 1，并**拒绝 order 中缺失的非 1 轴**。`get_mask` 决定哪些轴形成一个 group，`get_ranks` 生成 rank 列表；核心组合算法是 `generate_masked_orthogonal_rank_groups`（`C`，`parallel_state.py:269-570`）。

`order` 决定哪些轴优先、哪根轴权重最高，直接影响通信是否落在同一节点（`I`）。`axis order` 与 stride 编码一旦不一致，同一个 rank 可能同时被当作 TP rank 与 CP rank，产生**隐式**错误而非显式报错（`I`，`insights §16.5`）。

### 4. 集合原语的语义与分解

三种原语的语义必须分清（`C`，`insights §2A.3/§7.3`）：

```text
all-reduce(D)        : 每 rank 得到 Σ_i D_i
reduce-scatter(D)    : 每 rank 得到 (Σ_i D_i) 的第 r 片
all-gather(D_shard)  : 每 rank 得到 [D_0 | D_1 | ... | D_{N-1}]

ring all-reduce ≈ reduce-scatter + all-gather
volume ≈ (t-1)/t·D + (t-1)/t·D = 2(t-1)/t·D
```

"用 reduce-scatter 代替 all-reduce"不是省带宽，而是省"每个 rank 不需要的那部分"；两者体积之和与一次 all-reduce 等价。选型看消费方需要什么：

- DP + 本地优化器：每 rank 更新全量参数，需要完整梯度 → `all-reduce`。
- DP + 分布式优化器：每 rank 只更新自己分片 → 梯度 `reduce-scatter`，更新后参数 `all-gather`。
- SP：forward 需要完整序列 → `all-gather`；backward 把完整梯度按序列切回 → `reduce-scatter`（g）；反向算子 ḡ 相反。

### 5. 梯度 finalize 与 no_sync

无 pipeline 调度逐 microbatch 调用 `forward_step` 与 backward，除最后一个 microbatch 外使用 `no_sync_func` 让梯度同步延迟到最后一次；结束后统一调用 `config.finalize_model_grads_func`（`C`，`schedules.py:723-928`）。该函数既计算 loss，也承担 schedule 级的同步边界。

`finalize_model_grads` 把 DP/CP/SP 各域的梯度归约齐，具体按是否分布式优化器选择 reduce-scatter 或 all-reduce（`C/I`，`insights §3.4`）。三个维度要分清：

| 维度 | 归约时机 | 原语 |
|---|---|---|
| microbatch | 最后一次 backward | no_sync 累积 |
| DP | finalize / backward | all-reduce 或 reduce-scatter |
| TP 行切 | 层内 f/g | all-reduce |
| TP 列切 | 无需跨 rank | — |
| CP | 复制权重梯度 | 复用 DP 域归约 |

（`C/I`，`M02-parallelism/implementation.md`、`design.md`。）

### 6. 多轴组合的显存/通信账

一阶估算（`I`，量级演示）：

```text
per_gpu_weight   ≈ P · 2B / (TP · PP)
per_gpu_optstate ≈ P · 12B / (TP · PP · DP)      # distributed optimizer 时
per_gpu_act      ≈ f(s, b, hidden) / (TP · CP) · (在飞 MB 数)
约束：weight + grad + optstate + act_peak ≤ GPU_mem

PP 气泡：efficiency ≈ 1 - (PP - 1) / (MB + PP - 1)
TP 每层通信：4 次 all-reduce，与 TP 规模无关（次数恒定）
DP 每步通信：2·(DP-1)/DP · P · 2B（ring all-reduce）
```

决策顺序（`I`）：先 DP 打满 → 装不下加 TP（同节点 NVLink）→ 层多且 batch 大加 PP → 序列过长加 CP → 仍紧张用 SP + selective recompute/FSDP。TP 通信量最大，优先放同节点；PP 通信量最小，可跨节点；CP 的梯度归约复用 DP 域（`C`）。

### 7. EP 通信与 dispatcher

EP 把 experts 分布到多个 rank，token 通过 all-to-all 派发。可用 dispatcher 有 `allgather`（简单、通信量大）、`alltoall`（直接交换、较省）、`flex`（DeepEP/HybridEP，去冗余、跨节点融合）（`C`，官方 MoE 文档）。A2A 体积量级约 `num_tokens · topK · hidden · dtype_bytes`（`I`）。约束：EP 与 TP 组合时必须开 SP 以统一 layout；Parallel Folding 将 attention 层与 MoE 层的并行拓扑解耦。

### 8. 数据搬运的重叠

数据侧边界是 `pretrain_gpt.get_batch`：从 iterator 取字典，按 TP source rank 做 CUDA 搬运与广播，再按 packed/CP/MTP 分支整理为固定 `BATCH_KEYS`（`C`，`M04-data-pipeline/implementation.md`）。TP source rank 承担收尾与搬运，它一慢整组都等，因此重活应放在 DataLoader worker、主进程只做轻量 pin 与异步 H2D（`I`）。

## 关键不变量

- `torch.distributed` 必须先初始化；`world_size` 必须能被模型并行规模（TP×PP×CP…）整除（`C`）。
- `RankGenerator` 的 order 必须包含所有非 1 轴（`C`）。
- VP 只有在 PP>1 时合法（`C`）。
- GTP rematerialization 与多个 distributed-optimizer instance 当前由初始化逻辑禁止组合（`C`）。
- decoder 与 expert rank generator 产生的 PP group 必须一致（`C`）。
- schedule 的 model/data iterator 数量必须与所选调度类型匹配（`C`）。
- `finalize_model_grads` 必须在所有 microbatch 反向之后、`optimizer.step` 之前恰好调用一次（`C`）。

## 常见陷阱与反例

- 省略 collective 的 `group` 参数，默认走 global group：TP>1 时把别的 data-parallel 副本也卷进 all-reduce，数值错但不报错。
- 在 `initialize_model_parallel` 之前调用 `new_group`：全局 rank 环境未就绪，创建失败或顺序错乱。
- 认为一个 rank 只属于一个组：它同时属于 TP/PP/DP 等多个组，通信时必须选对组。
- 用 `all-reduce` 顶替 `reduce-scatter`：只浪费带宽、结果正确，很难被正确性测试发现；反向（reduce-scatter 顶替 all-reduce）会拿到部分结果产生静默数值错误。
- 漏调 `finalize_model_grads`：梯度只在本地累积，各 rank 参数发散；重复调用则把梯度加两遍。
- axis order 与 stride 不一致：逐层并行切换时同一 rank 被复用，隐式错误。
- EP+TP 忘记开 SP：token dispatch 的 layout 与 TP 分片不一致，前向出错或静默错误。
