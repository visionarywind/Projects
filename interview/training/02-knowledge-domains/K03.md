# K03 数据并行

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。

## 范围

本域回答"同一个模型副本如何在不同数据上训练，并让梯度跨副本一致"。核心是梯度归约、contiguous grad buffer 与 bucket、distributed optimizer（状态分片）、梯度与数据分片的采样一致性。

本域**不负责**：单层内的参数切分（K04）、层间流水（K05）、优化器内部 Adam 的数学（K08 讲更新，本域讲 DP 维度的归约与分片）。

## 先修知识

- 反向传播与梯度语义。
- `all-reduce` 与 `reduce-scatter` 的差异（K02）。
- sampler/DataLoader 与 epoch/seed 概念。

## 核心机制

### 1. 为什么同步梯度而不是参数

DP 每个 rank 持完整模型副本、喂不同数据。一个 step 的梯度先在本地累积，再在 DP 组内归约，使所有 rank 拿到同一份梯度，然后各自更新——梯度一样、初值一样，更新后参数仍一致（`C`，`insights §5.2`）。

同步参数需要每步广播全量权重（参数量级）；同步梯度同样保证一致，且能与 bucket、overlap、reduce-scatter 分片结合，把通信藏进计算（`I`）。注意 DP 只增加 batch，不减少激活；模型必须整体装进单卡（`C`）。

```text
for each microbatch:
    loss.backward()                       # 梯度就地累积到 grad buffer
grad_buffer.scale(1 / num_microbatches)
reduce over DP group:
    all_reduce()       # 普通 DP：每 rank 全量平均梯度
    reduce_scatter()   # distributed optimizer：每 rank 只留分片
optimizer.step()
```

有效 batch：`global_batch = micro_batch × DP × num_microbatches`（K01）。

### 2. contiguous grad buffer 与 bucket

DDP 将参数和梯度放入 `_ParamAndGradBuffer` 的连续 `param_data/grad_data`，bucket 只是 view 和通信边界（`C`，`90-cross-module/pooling-and-resource-management.md`）。buffer 生成时计算全局 `numel`、bucket offset 与 padding；**distributed optimizer 要求 buffer 大小可被 DP world size 整除**（`C`，`param_and_grad_buffer.py:1051-1175`）。

要点：

- 用连续 buffer 是为了减少 collective 次数、改善通信重叠；代价是 padding 与布局复杂（`C`）。
- `reset()` 只把 grad buffer 清零、**不释放 storage**；"清梯度"和"回收显存"是两个不同动作（`C`，`param_and_grad_buffer.py:1243-1270`）。
- `start_grad_sync`/`start_param_sync` 可返回异步 handle；后续 `finish_*_sync` 必须 wait handle 后才能把 bucket view 当作已完成数据（`C`，`param_and_grad_buffer.py:646-700`）。
- `offload_grad_buffers()` 先 synchronize，再把 grad storage resize 为 0，可选 `empty_cache()`；`restore_grad_buffers()` 重新扩容并清零（`C`，`distributed_data_parallel.py:740-775`）。

### 3. distributed optimizer：状态分片

`DistributedOptimizer` 以参数 range 和 DP shard 管理 optimizer state，保存/恢复时需与 model sharding metadata 对齐（`C`，`core/optimizer/distrib_optimizer.py`）。它是"DP + 状态分片"的组合，与 ZeRO-1 同族（只分片优化器状态）；FSDP 则走到参数/梯度/状态全分片（`C`，`insights §15.6`）。

每参数状态账（fp16 + fp32 master，`I`）：

```text
weight(2) + grad(2) + master(4) + m(4) + v(4) = 16 B/param
state_total ≈ P · 12B / DP        # master+m+v 分片，grad 也分片
step: reduce_scatter(grad) -> local Adam -> all_gather(param)
```

通信账：`all-reduce` 被拆成 `reduce-scatter`（梯度）+ `all-gather`（参数）。按 ring 等价性，两者带宽之和与一次 all-reduce 相当，分片本身不额外增加带宽，但把通信切成两段，需要 overlap 才能隐藏（`I`，`insights §15.3`）。

约束：优化器分片布局必须与 model shard metadata 对齐，换并行度要 reshard；GTP rematerialization 与多个 distributed-optimizer instance 当前被初始化逻辑禁止组合（`C`，`M02/README.md`）。M02 不决定 optimizer 是否 sharded，只提供通信域（`C`，`M02/design.md`）。

### 4. fused optimizer 的边界

`get_megatron_optimizer` 按参数组、混合精度、distributed optimizer、FSDP、CPU offload、MuP 与 TE/Apex/PyTorch fallback 选择实现；`ChainedOptimizer` 可组合多个 optimizer（`C`，`M05/README.md`）。optimizer 模块优先 import Transformer Engine，再 Apex，最后 Torch fallback（`C`，`core/optimizer/__init__.py:13-35`）。

因此"fused optimizer"不是一种优化器，而是一组后端实现。边界分三类：

- **参数组边界**：多 lr/weight-decay 组、空梯度、稀疏梯度、部分参数 `requires_grad=False` 可能让融合 kernel fallback 或产生与参考实现不同的数值（`I`）。
- **溢出边界**：混合精度下 loss scaling 溢出时 step 被 skip，融合路径必须与普通路径一样保留状态、不推进 scheduler（`C`）。
- **状态布局边界**：checkpoint 中 optimizer state 形状取决于具体实现；切换实现或改并行度时需能对应（`C`）。

验证做法：同一组梯度下比较融合路径与 PyTorch 参考路径更新后的参数 diff，并制造一次 overflow 确认两条路径都 skip 且 scheduler 不推进（`U / 待验证`）。

### 5. DP sampler 一致性

数据链是 `GPTDatasetConfig → Indexed/Mock dataset → GPTDataset → blended builder → sampler/DataLoader → get_batch`（`C`，`M04-data-pipeline/README.md`）。普通 sampler、random sampler、hybrid CP sampler、full validation sampler 把 dataset sample 变为 rank-local batch；`build_pretraining_data_loader` 选择 loader（`C`，`training/datasets/data_samplers.py`）。

两层切分（`C/I`）：

```text
global batch G ── DP 切 ──> 每 rank G/DP ── schedule 切 ──> MB 个 micro-batch
micro_batch_size = G / (DP × MB)
sampler: DP rank/size -> 本进程样本集合
resume: consumed_samples -> epoch/offset 重建
blend:  多数据集按权重混合，并集 = global batch
```

`GPTDataset` 用 document index、sample index、shuffle index 把文档级存储映射为训练样本（`C`）。随机数据集包装器用独立 seed 控制 shuffle，epoch/seed 决定样本顺序（`C/I`）。恢复时由 `load_checkpoint` 返回的 consumed samples 重建 sampler 的 epoch 与偏移（`C`，`M05/execution-flows.md`）。

## 关键不变量

- `world_size % (tp*pp*cp) == 0` 决定 DP 大小（`C`）。
- 各副本用同一份梯度更新 ⇒ 每步后参数数值一致（`C`）。
- 累积梯度必须按 `num_microbatches` 缩放，且只缩一次（`C/I`）。
- distributed optimizer 的 buffer 大小须被 DP world size 整除（`C`）。
- 同一 step 内各 DP rank 的样本集合互不相交，并集覆盖 global batch（`C`）。
- optimizer shard 布局必须与 model sharding metadata 对齐（`C`）。

## 常见陷阱与反例

- 在梯度 all-reduce 之前 `optimizer.step()`：各 rank 用局部梯度更新，参数发散（K08）。
- 忘记缩放累积梯度：micro_batch=4 时等效学习率放大 4 倍，训练震荡。
- 把 DP 通信写在 global group 上：混入 TP rank，跨副本错误求和。
- 把"优化器状态 1/N"误读成"总显存 1/N"：权重与激活并不因此下降。
- 只改 DP 度数却沿用旧 optimizer 分片 checkpoint：load 后分片对不上导致数值漂移。
- 各 DP rank 同 seed 无偏移：样本重复，global batch 减半，收敛变慢但不报错。
- 恢复时把 consumed_samples 设为 `iteration × G`：忽略 shuffle 与 blend，样本顺序错位。
- 以为融合 kernel 数值逐位等价：浮点累加顺序与 fallback 分支带来微小差异，验收应做近似 diff（`I`）。
