# K12 数据管线与交付

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。

## 范围

本域回答"文本如何变成 rank-local batch、哪些数据不变量一旦破坏就是静默错误、如何用门禁与可观测性保证质量、训练产物如何交付给推理与服务"。核心是 dataset 样本语义、sampler 与 DP 分片、packed sequence、数据治理门禁、可观测性分层、训练-推理一致性、平台化抽象。

本域**不负责**：并行拓扑（K02）、优化器（K08）、checkpoint 字节布局（K10）。但采样一致性、恢复时的数据位置与 K03/K10 强耦合。

## 核心机制

### 1. dataset 样本语义

数据链是 `GPTDatasetConfig → Indexed/Mock low-level dataset → GPTDataset → blended builder → sampler/DataLoader → get_batch`（`C`，`M04-data-pipeline/README.md`）。

`GPTDataset.__getitem__` 把文本转为 long tensor：

- 配置 `add_extra_token_to_sequence` 时用 `text[:-1]`/`text[1:]`；否则 labels 是左移后的 text，最后位置填 pad token（`C`，`gpt_dataset.py:264+`）。
- pad 位置从 loss mask 排除，输入中的 pad token 映射为安全 token。
- mask 与 position ids 可缓存；`reset_position_ids`、`reset_attention_mask`、`eod_mask_loss` 和 inter-document masking 会改变缓存与 `cu_seqlens` 生成。

```text
tokens = [t0 t1 t2 ... tN]
labels = [t1 t2 t3 ... pad]        # 左移一位
loss_mask = [1 1 1 ... 0]          # pad 位为 0
loss = -Σ loss_mask_i · log p(labels_i | tokens_≤i)
```

`get_batch` 从 iterator 取字典，按 TP source rank 做 CUDA 搬运和广播，再根据 packed sequence、CP 和 MTP 分支整理为固定 `BATCH_KEYS`；它是 M04 到 M01/M03 的主要边界（`C`，`pretrain_gpt.py:111+`）。

### 2. sampler 与 DP 分片

普通 sampler、random sampler、hybrid CP sampler 和 full validation sampler 把 dataset sample 变为 rank-local batch；`build_pretraining_data_loader` 负责选择 loader（`C`，`training/datasets/data_samplers.py:19-380`）。random sampler 包装器用于 epoch/seed 可复现。

`GPTDataset` 通过 document index、sample index 和 shuffle index 将文档级存储映射为训练 sample；builder 可按 train/valid/test split 和 blended dataset 配置分配样本（`C`，`gpt_dataset.py:734-800`，`blended_megatron_dataset_builder.py:30+`）。

核心不变量：**sampler 的 DP rank/size 决定每个进程看到的 batch**（`C`，`M04/README.md`）。数据分片与并行拓扑强绑定。

### 3. tokenizer 与词表对齐

- **编码对齐**：训练与推理、checkpoint 与续训必须使用同一 tokenizer，否则同一文本编码不同（`I`）。
- **词表列切**：TP 输入 embedding 按词表维列切 `E=[E1,E2]`，每 rank 持一块词表子集；为每块等大，词表要 padding 到 `N·t`（`C`，`insights §6.10`）。
- 论文为对齐把 GPT-2 词表 50257 padding 到 128 的倍数再乘 8 路并行，得到 51200（`C`，`insights §6.10`）。
- 数据集要与 tokenizer 匹配、最长序列不得超过 max seq len（`C/I`）。

### 4. packed sequence 的正确性边界

打包把多条短样本拼成一条长序列，减少 padding 浪费、提升 GPU 利用率。代价是三条正确性边界（`C/I`，`expert.md` T-A009）：

1. **loss mask 对齐**：mask 必须与有效 label 一一对应；标签左移后 mask 也要相应左移。
2. **跨文档隔离**：用 `reset_attention_mask` 和 `reset_position_ids` 让文档 A 看不到文档 B、位置从每段重新编号。
3. **attention 后端契约**：packed 的 flatten tensor 必须伴随 `cu_seqlens`（每段起止与最大长度）；varlen 与稠密 block mask 不能混。

```text
doc1: [a b c]   doc2: [d e]
packed: [a b c d e]
cu_seqlens: [0, 3, 5]
pos:        [0 1 2 0 1]        # reset
attn:  a 只看 a..; d 只看 d..  # 段间隔离
loss_mask: 有效 label 处为 1，pad 处为 0
```

M04 明确把"loss mask 必须与有效 label 对齐""packed sequence 的 flatten tensor 必须伴随 cu-sequence metadata"列为不变量（`C`）。

### 5. 数据治理门禁

把数据侧不变量做成构建期与 get_batch 期门禁（`I`，`expert.md` T-E011）：

```text
build_time_assert:
  tokenizer.matches(corpus)
  min_seq <= len <= max_seq
  sum(blend_weights) == 1
  no_duplicate(contamination_check)

get_batch_assert:
  len(tokens) == len(labels)
  loss_mask[i] == 1  => label[i] is valid and != pad
  if packed: cu_seqlens 单调, 覆盖全长, 段数与文档数一致
  sampler_rank_local_batch == expected(global_batch, dp)
```

静默错误（不报错、loss 照降、目标错误）：mask/label 错位、packed 段 metadata 缺失、pad 未从 loss 排除。对这三类用**断言**而非告警，因为告警不会阻止错误数据进入训练。CI 用 mock dataset 做自包含验证（`C`，`MockGPTDataset`）。

| 不变量 | 破坏后果 | 门禁位置 | 是否静默 |
|---|---|---|---|
| tokens/labels 等长 | 张量错位 | build | 否（多会崩） |
| loss mask 对齐 | 学错目标 | get_batch | 是 |
| packed cu_seqlens | 段拼接错误 | build | 是 |
| pad 排除 | 学 pad token | build | 是 |
| sampler DP 一致 | 数据重复/丢失 | get_batch | 部分 |

### 6. 可观测性分层

分四层（`I`，`expert.md` T-E012）：

| 层 | 主要指标 | 回答的问题 | 基数策略 |
|---|---|---|---|
| 作业 | goodput、重启数 | 是否有效推进 | 低 |
| step | compute/comm/idle | 慢在算还是等 | 中 |
| 通信 | 每原语耗时/体积 | 哪条通信拖 | 按组聚合 |
| kernel | trace 空隙 | 为何 idle | 按需采样 |

`pretrain` 把 fault tolerance、telemetry 等横切能力注入运行时，`--log-interval` 打印 tokens/s、MFU、loss（`C`，`M03/implementation.md`）。三分钟定位的固定流程：先比 step time 与基线 → 查 idle 占比 → 通信层看是否某 group 变慢 → compute 高则查 batch/序列/重算 → 都正常查数据加载。per-rank 指标只上报聚合分位（p50/p99），异常时再按 rank 下钻；per-step 指标按 log-interval 采样（`I`）。

### 7. 训练-推理一致性

给等价性一个可判定的定义（`I`，`expert.md` T-E007）：

```text
Equiv(train, infer; x) := || f_train(x; sharded) - f_infer(x; engine) || <= eps

分解偏差来源:
  d_total <= d_layout + d_precision + d_kernel + d_preprocess
定位顺序:
  1) 单卡 TP=1、无 CP/EP、一致精度   -> 应近似相等（隔离布局与精度）
  2) 加布局 (TP/CP/EP)                -> 看 d_layout
  3) 换精度 (FP8)                     -> 看 d_precision
  4) 换 attention kernel              -> 看 d_kernel
```

四类偏差来源：布局（TP head / GQA KV / MLA latent，错的是语义而非形状）、精度（FP8/bf16 kernel 差异）、kernel（flash vs 朴素 attention 的累加顺序）、预处理（mask/position/packed）。还有执行路径类：M06 的 `StaticInferenceEngine` 非 legacy 路径会尝试转 dynamic，异常回退 legacy，同名调用不代表同一 backend（`C`，`M06-inference-and-tools/implementation.md`），验证必须覆盖实际路径。

### 8. 平台化抽象

Megatron-Core 的第三代变化（`C`，`insights §2.3`）：配置驱动（`TransformerConfig` 作为单一事实源）、并行状态显式化（`parallel_state`/`ProcessGroupCollection`）、调度函数化（`get_forward_backward_func`）、ModuleSpec 把模块规格与实现分离。

抽象决策沿"变化轴"切（`I`，`expert.md` T-E013）：

```text
抽象 = f(变化频率, 隔离价值, 复杂度成本)
  TransformerConfig: 变化频率高(模型/并行) -> 高隔离 -> 值得
  ModuleSpec:        变化频率中(后端)     -> 高隔离 -> 值得
  一次性分支:         变化频率低           -> 低隔离 -> 不合算

迁移(strangler):
  新调用点 -> 显式 ProcessGroupCollection
  旧调用点 -> 全局 parallel_state 兼容层
  逐步替换, 每步可回滚
```

平台的三个核心契约：配置（可复现）、状态（checkpoint sharded schema 可迁移）、失败（错误分类成配置/数值/系统）。新旧 API 并存是迁移的桥（`C`，`architecture.md` 关键边界）。

## 关键不变量

- tokens/labels 长度与 sequence-length 约束一致（`C`）。
- loss mask 必须与有效 label 对齐（`C`）。
- packed sequence 的 flatten tensor 必须伴随 cu-sequence metadata（`C`）。
- sampler 的 DP rank/size 决定每个进程看到的 batch（`C`）。
- 训练/推理/续训使用同一 tokenizer，词表按 TP 整除（`C/I`）。
- 数据门禁对静默错误用断言而非告警（`I`）。

## 常见陷阱与反例

- 建数据集用 tokenizer A、训练用 B：token id 语义错位，模型在噪声上学，loss 缓慢下降但无报错。
- 各 DP rank 同 seed 无偏移：样本重复，global batch 减半。
- epoch 切换时忘记重新 shuffle/reset：每轮顺序相同。
- 标签左移了但 loss mask 没跟着移：监督落在错误 token 上，难定位。
- 打包后只传 flatten tensor、不传 `cu_seqlens`：varlen attention 把整条序列当一段，段间隔离失效。
- pad 未从 loss mask 排除：模型学习预测 pad。
- 恢复时把 consumed_samples 设为 `iteration × G`：忽略 shuffle 与 blend，样本顺序错位。
- blend 权重未归一：采样分布偏斜，等价于改变数据配比。
- 只上报全局平均 step time：掩盖单 rank 的长时间等待。
- 把 idle 一律归因为"通信慢"：未区分气泡、未重叠与 kernel 抖动。
- 以逐位相等作为训练-推理通过标准：任何 kernel 升级都被判失败。
- 为"将来可能换后端"提前抽象，让所有代码走 registry 跳转：实际只有一个实现。
