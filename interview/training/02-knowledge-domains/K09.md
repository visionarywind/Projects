# K09 混合精度与数值稳定

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。

## 范围

本域回答"存储、计算、通信各用什么精度，为什么需要缩放，数值风险在哪里暴露，如何治理"。核心是 fp16/bf16 的格式差异与 loss scaling、FP8 的 E4M3/E5M2 分工与 delayed scaling、跨 rank 的 scale 一致性、梯度裁剪与 NaN 传播、以及精度治理闭环。

本域**不负责**：优化器状态构成与分片（K08）、checkpoint（K10）。数值问题与 K08 的 step 边界强耦合。

## 先修知识

- IEEE 浮点：符号位、指数位、尾数位与动态范围/精度的权衡。
- 下溢/上溢、inf/nan。
- Adam 的 fp32 master 概念（K08）。

## 核心机制

### 1. fp16 与 bf16：范围 vs 精度

两种 16 位格式的取舍在"范围"与"精度"之间（`C`，`insights §12A`）：

```text
fp16:  sign(1) exp(5)  mantissa(10)   范围窄，精度高 -> 需 loss scaling
bf16:  sign(1) exp(8)  mantissa(7)    范围宽(≈fp32)，精度低 -> 无需 scaling
```

| 维度 | fp16 | bf16 |
|---|---|---|
| 指数位 | 5 | 8 |
| 尾数位 | 10 | 7 |
| 动态范围 | 窄 | ≈fp32 |
| loss scaling | 需要 | 不需要 |
| 主参数精度 | fp32 | fp32 |

训练里梯度经常非常小。fp16 范围窄，小梯度会下溢成 0，所以要 loss scaling：

```text
fp16 step:
  loss' = loss * scale
  loss'.backward()            # 梯度被放大
  if scaler.has_inf_nan(): scale /= 2 ; skip
  grad /= scale               # 除回
  optimizer.step()            # fp32 master 更新
```

bf16 范围够大，不需要这套机制；但两者都保持 fp32 的主参数与优化器状态以保证更新精度（`C`）。fp16 下 scale 必须成对地乘（loss）与除（梯度），否则等效步长错。

### 2. FP8：格式分工与 delayed scaling

FP8 在 Hopper 及以后的硬件上把 QKV 投影、MLP 等 GEMM 再减半（`C`，`insights §12A.1`）。风险在于可表示带窄，必须靠缩放把 tensor 搬进可表示范围。经典分工（`I`，`insights §12A.3`）：

| 格式 | 指数/尾数 | 适用 | 缩放 |
|---|---|---|---|
| fp32 | 8 / 23 | master、LN、softmax | 否 |
| bf16 | 8 / 7 | 默认前反向 | 否 |
| fp16 | 5 / 10 | 旧默认 | 是（loss scaling） |
| FP8 E4M3 | 4 / 3 | forward 权重/激活 | delayed scaling |
| FP8 E5M2 | 5 / 2 | 梯度（动态范围更极端） | delayed scaling |

delayed scaling（`I`）：

```text
amax_t   = max(|x|)                            # 本迭代统计
scale_t  = amax_history_window_max / FP8_MAX   # 用近窗历史, 而非当前瞬时
x_fp8    = quantize(x * scale_t)
```

要点：用历史窗口而非瞬时 amax，避免单次幅值突变把 scale 拉坏。scale 是**逐 tensor** 的，需要额外的 scale 元数据在 kernel 间传递。

### 3. 跨 rank 的 scale 一致性

TP 下各 rank 的激活分片不同：若各自独立统计 amax，scale 可能不一致，进而让梯度数值不一致、降低收敛确定性（`I`，`insights §12A.4`）。工程上要把 amax 在并行组内归约（`all-reduce`/`max`），保证同一个逻辑张量用同一套 scale。这是 FP8 最隐蔽的坑之一：reduce 后与单卡基线的偏移常被误判为"学习率问题"。

```text
step t:   张量 ── amax_t ── 存历史
step t+1: 张量 ── 用 amax_t 算 scale ── 量化 ── GEMM ── 反量化
TP:       各 rank 局部 amax ──(allreduce/max)──► 统一 scale
```

### 4. 梯度裁剪与 NaN 传播

NaN 的传播是"一点污染、全局扩散"：某 rank 某梯度出现 NaN，all-reduce 一求和，整个 DP 组都变 NaN；若此时还 step，NaN 写进主参数，之后每步都 NaN。两道防线（`C/I`）：

```text
# 归约后
total_norm = sqrt(sum(p.grad^2 for p in params))
clip_coef = max_norm / (total_norm + eps)
if clip_coef < 1: grads *= clip_coef

# 更新前防线
if scaler.has_inf_nan(): skip update; adjust_scale()   # 防线一
else: optimizer.step() -> update_successful            # 防线二
if successful: scheduler.step()
```

裁剪必须基于 DP 归约后的全局梯度，否则各 rank 阈值不同。典型 NaN 源：全零 loss mask 导致除零、fp16 下溢/上溢、FP8 scale 失配、学习率过大（`I`，`insights §1258` 列出数值/收敛类错误）。**bf16 范围大不等于不会出 NaN**（除零、坏数据仍会产生）。

### 5. 数值稳定性治理

仅有 loss scaling 不够，治理需要闭环（`I`，`expert.md` T-E004）：

- 持续上报：溢出步计数、被跳过的步数、loss scale 历史轨迹、FP8 每张量 amax 分布。
- 治理规则：连续溢出超过阈值就告警并回退精度档；scale 长期贴边说明该张量不适合 FP8。
- 并行一致性：TP/CP 组内统计 scale 必须同源或做归约。
- 灰度验证：固定 seed → 单卡 fp32/bf16 基线 → 逐层开 FP16/FP8 → 多卡验证，避免"一次全开"难以定位。

动态 loss scaling 的更新规则（标准形式，`I`）：

```text
每步:
  if any(isinf(grad)) or any(isnan(grad)):
      skip optimizer.step
      scale /= 2                     # 回退
      overflow_counter += 1
  else:
      if overflow_counter == 0: scale *= 2
      scale = min(scale, scale_max)
      apply(grad / scale)
```

### 6. 精度格式的失效模式对照

| 格式 | 范围风险 | 精度风险 | 需要的机制 | 主要监控 |
|---|---|---|---|---|
| FP16 | 下溢/上溢 | 中 | fp32 master、动态 scaling | 溢出计数、scale 轨迹 |
| BF16 | 低 | 累加误差 | 无需 scaling | 长链误差、loss 曲线 |
| FP8(E4M3/E5M2) | 高（靠 scale） | 高 | delayed scaling、分级格式 | per-tensor amax、贴边率 |

（`I`。）FP16 主要怕下溢（梯度趋零）与上溢；BF16 不怕范围但精度低，误差在长链累加中累积；FP8 范围与精度都紧，靠 per-tensor scale 把动态范围搬回来，scale 失配会整块精度崩塌。

### 7. 与 checkpoint 的耦合

FP8 的 scale 元数据、fp16 的 loss scaler scale 都可能是需要随 checkpoint 保存的状态，否则恢复后首个 step 的数值会跳（`I`）。`check_checkpoint_args` 会拦结构参数不匹配，但不覆盖 scale 这类运行时状态（K10）。

## 关键不变量

- 主参数与优化器状态保持 fp32 更新（`C`）。
- fp16 下 loss scale 必须成对地乘（loss）与除（梯度）（`C`）。
- 裁剪阈值基于 DP 归约后的全局 grad norm（`I`）。
- 任何 inf/nan 都不允许进入参数更新（`C`）。
- FP8 同一逻辑张量的 scale 必须在并行组内一致（`I`）。
- LayerNorm、softmax、归约等幅值敏感算子保持高精度（`I`）。

## 常见陷阱与反例

- fp16 不用 loss scaling：小梯度下溢为 0，局部参数永不更新。
- 只乘不除：等效学习率被放大 scale 倍，训练发散。
- 以为混合精度会把参数也存成 bf16：主参数仍是 fp32。
- 各 TP rank 独立统计 amax：scale 不一致，梯度聚合后数值偏差累积，loss 抖动。
- 把 loss scaling 的 scale 当作 FP8 的 scale：两者机制不同（loss scale 在损失上、FP8 scale 在张量上），混用导致下溢或溢出。
- 一次性全模型开 FP8：出现问题无法定位。
- 在不支持 FP8 的硬件上强行开启又没有 fallback：训练直接不可用。
- 检测到 NaN 仍 step，或 overflow 后仍推进 lr/iteration：状态错位。
