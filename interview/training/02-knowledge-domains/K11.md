# K11 显存、性能与吞吐

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。论文锚点 arXiv:2205.05198。

## 范围

本域回答"显存被谁吃掉、每一步时间花在哪、如何用统一口径度量吞吐与成本"。核心是激活显存建模、activation recompute 的取舍、MFU/step time 分解、profiler 归因、瓶颈判别、以及训练到服务的权重交接。

本域**不负责**：并行拓扑如何建立（K02）、优化器状态的具体构成（K08）、checkpoint 一致性（K10）。本域消费这些域产生的量。

## 先修知识

- FLOPs 与单卡峰值算力。
- attention 的 `s²` 复杂度。
- TP/SP/CP/PP 对显存的切分方式（K04/K05/K06）。

## 核心机制

### 1. 激活显存的来源与切分

TP 只切 GEMM，LayerNorm 与 Dropout 等逐元素算子的激活在 TP 组内复制，论文给出这部分约 `10·s·b·h` 不被 t 除（`C`，论文）。SP 把这些激活按序列维切开后，这部分也被 t 除（K06）。

按增长源拆（`I`）：

```text
每层激活 ≈ [attention: a·s²·b 分数矩阵] + [其余: c·s·b·h]
TP:   hidden 维 /t，但 LN/Dropout 段仍复制
SP:   复制段也 /t
CP:   序列激活 /CP（attention 的 s² 被摊开）
PP:   每 rank 驻留"在飞 MB 数 × stage 激活"，不随总 MB 线性涨
```

分片与重计算的叠加：

| 手段 | 作用对象 | 激活收益 |
|---|---|---|
| TP | GEMM 区 hidden | /t（不含复制区） |
| SP | LN/Dropout 复制区 | 复制区 /t |
| CP | 序列激活与 attention | /CP |
| selective recompute | attention 内部大激活 | 按判据省 |
| micro-batch 控制 | 在飞激活 | 线性 |

（`C/I`，`insights §7/§12.3`。）

### 2. activation recompute：拿计算换显存

- **full recompute**：把整层激活都重算，省显存最多，但额外计算约 30–40%（`C`，论文）。
- **selective recompute**：只对"激活体积大、计算密度低"的区域（attention 的 QKᵀ、softmax、softmax dropout、V 乘）做 checkpoint，其余保留（`C`）。
- **判据**：`5·a·s/h > 34` 时重算更划算（a=heads, s=seq, h=hidden）（`C`，论文）。
- 论文示例：GPT-3（96 heads, s=2048, h=12288）算出 80 > 34，省约 70% 激活；MT-NLG（128 heads, s=2048, h=20480）算出 64 > 34，省约 65%；额外 FLOPs 仅约 2.7% 与 1.6%（均为论文报告，非本地复现）。

```text
判据:  5·a·s/h > 34  → 该区域重算更划算
GPT-3: 5·96·2048/12288 = 80  > 34 → 省 ~70% 激活, 额外 FLOPs ~2.7%
MT-NLG:5·128·2048/20480 = 64 > 34 → 省 ~65% 激活, 额外 FLOPs ~1.6%
full recompute：compute 开销 30–40%
```

直觉：比值越大，attention 中间激活相对 hidden 激活越"胖"，重算节省的显存越值那点额外计算。重算在同样精度下确定性，但浮点累加顺序可能与不重算不同，逐位一致不保证。

### 3. step time 三分解与 MFU

```text
step_time ≈ compute_time + communication_time + idle_time
compute = 总 FLOPs / (GPU 数 × 单卡峰值 × MFU)
comm     = Σ(原语体积 / 有效带宽) + 原语次数 × 延迟
idle     = PP bubble + 未重叠等待 + kernel 启动开销

MFU = 模型 FLOPs / (GPU 数 × 单卡峰值 FLOPs × 运行时长)
训练 FLOPs/token ≈ 2 × 参数量（前向），训练约 3 倍前向量级（fwd+bwd ≈ 6N/token）
```

（`C/I`，`insights §12B.1–12B.6`。）MFU 分子必须是**模型** FLOPs（按参数量与 token 数估），不把重算、通信等额外计算算进分子；分母是"GPU 数 × 单卡峰值 × 墙钟时长"，峰值口径要一致。

为什么 MFU 比"每秒样本数"更能反映效率：样本大小不统一（packed sequence 下每样本 token 数不同），样本/秒会把"长样本多"误判成"效率高"；MFU 以模型 token 级计算量为分子，跨长度、跨模型可比（`I`）。

### 4. 吞吐与成本的标准化口径

两个人报出的吞吐能差一倍，主因是口径不同（`I`，`expert.md` T-E009）：

| 指标 | 定义 | 常见坑 | 可比前提 |
|---|---|---|---|
| tokens/s | 每步 token / step 时间 | 序列长度未绑定 | 固定 batch/seq |
| MFU | 模型 FLOPs / 峰值算力时间 | 与 HFU 混用 | 声明 FLOPs 口径 |
| HFU | 含重算 FLOPs 利用率 | 被当成 MFU | 声明含重算 |
| 扩展效率 | 相对单卡/小规模 | strong/weak 混用 | 固定 scaling 类型 |
| cost/token | 花费 / 有效 token | 用 raw 吞吐低估 | 用 goodput |

```text
t_墙钟 = t_有效训练 + t_重启白跑 + t_加载
goodput  = t_有效训练 / t_墙钟
cost/token = t_墙钟 * N_gpu * price / tokens_有效
```

HFU ≥ MFU（HFU 把重算的额外 FLOPs 也算进实际计算量），两者不可直接比。strong scaling（固定 global batch）与 weak scaling（batch 随卡数放大）口径完全不同，比较前必须声明。

### 5. profiler 归因

Megatron 内置 timer 统计 per-iteration、per-microbatch、FP/BP 耗时（`timers('forward-compute')` 等），`--log-interval` 打印 throughput、MFU 和 loss；分布式性能分析用 nsys/NCCL 查看每 step 的通信与空闲比（`C/I`，`insights §14.6`）。性能关键路径文档列出热点：attention/MLP forward、pipeline P2P、data loading、gradient reduce、checkpoint、inference KV cache，并强调结论必须依赖 profiler 或 benchmark（`C`，`performance-critical-paths.md`）。

归因顺序（`I`）：

```text
1) MFU 低?        → 小 GEMM / recompute / 精度
2) comm 未重叠?   → overlap 开关 / stream 依赖
3) idle 来源?     → PP bubble / 数据加载 / kernel launch
```

| 观测现象 | 可能根因 | 处置 |
|---|---|---|
| MFU 低但 NCCL 少 | GEMM 碎片化、recompute | 调 TP/MB、关 full recompute |
| NCCL 与计算不并行 | overlap 未生效 | 检查 stream 依赖与开关 |
| GPU 周期性空档 | PP bubble | 增大 MB/PP、interleaved |
| 空档非周期 | 数据加载/启动抖动 | 预取、CUDA Graph |

度量纪律（`C/I`）：固定 global batch、用每 step 时间而非样本/秒、warmup 后至少重复 3 次取中位数、用 profiler 区分 comm 与 idle。

### 6. OOM 判别：激活 vs 状态

OOM 分两类（`I`）：

```text
判别实验：
  减小 micro-batch → 显存显著下降  ⇒ 激活主导
  减小 micro-batch → 显存基本不变  ⇒ 权重/优化器状态主导
```

- **激活爆**：随 micro-batch/序列增长而增长，对 recompute/SP/CP 敏感。处置：开 SP、selective recompute、降在飞 microbatch（interleaved）。
- **状态爆**：与模型规模、TP/PP/DP 相关，与 micro-batch 基本无关。处置：distributed optimizer 分片、调 TP/PP，极端情况上 FSDP。

避免"看到慢就怪通信"：先用 trace 确认瓶颈类型，再动对应旋钮，改一步测一步。

### 7. 训练到服务的权重交接

训练产物是 sharded state dict（每 rank 局部 shard + metadata），推理引擎通常按 TP head 分片读取权重，二者布局不同，需要转换契约（`C/I`）：

```text
train layout: (TP_t, PP_t, EP_t) sharded state dict + metadata
infer layout: (TP_i) 推理引擎权重（KV 按 head 分片）
映射：reshard → 合并 PP stage → 对齐 head 分片 → 补非权重张量
```

- Megatron-Core 提供 `save_distributed_checkpoint`/`load_distributed_checkpoint`，支持并行度变化时 reshard（`C`）。
- Megatron-Bridge 提供与 HuggingFace 的双向转换，模型并行感知（`C`）。
- **GQA 约束**：`num_kv_heads % TP_i == 0`，否则需复制或 padding KV 投影；MLA 的 latent 解压 GEMM 也要按推理 TP 对齐（`C`）。
- 非权重张量（LayerNorm、bias）与 FP8 scale 元数据必须一起转，漏掉会静默偏差（`I`）。
- 验证：固定 prompt 对比训练侧与推理侧 logits/生成结果，差异在容差内才放行（`U / 待验证`）。

## 关键不变量

- MFU 分子只算模型 FLOPs，不含重算/通信（`C/I`）。
- 分母用一致的峰值口径与真实时长（`C/I`）。
- step time 三分解在量级上闭合：compute + comm + idle ≈ step_time（`I`）。
- 重算区域必须能由保存的边界张量确定性重建（`C`）。
- 权重交接的 head 分片、非权重张量、量化 scale 必须全部一致（`C/I`）。

## 常见陷阱与反例

- 把重算/通信 FLOPs 计入 MFU 分子：MFU 被系统性夸大。
- 把 MFU 与 HFU 混比：得出"新配置更快"的错误结论。
- 用 samples/s 比较不同序列长度的配置：得出相反结论。
- 只开 recompute 不开 SP：复制区激活仍在，省下的量小于预期。
- 对计算密集的 MLP 主体全重算：显存收益有限，step 时间显著上升。
- 把激活 OOM 当作状态 OOM，盲目上 FSDP：真正需要的是 SP + recompute。
- 假设训练 checkpoint 可直接被推理引擎加载：忽略 TP/PP 布局差异。
- 只转权重、漏掉 LayerNorm/bias 与 FP8 scale：推理结果静默偏差。
- 在共享或不稳定环境测扩展性，未做重复与中位数：结论不可复现。
