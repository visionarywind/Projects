# K06 序列与上下文并行

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。论文锚点 arXiv:2205.05198。

## 范围

本域回答"序列维如何被切开，以及两种不同动机的序列并行（SP 与 CP）各自付什么代价"。核心是 g/ḡ layout 转换、SP 的带宽等价、CP 的不切权重与额外梯度归约、RoPE 在序列切分下的位置一致性、长序列的显存分解。

本域**不负责**：hidden/head 维切分（K04）、层间流水（K05）、数据维（K03）。

## 先修知识

- TP 只切 GEMM 区、复制区不被切（K04）。
- ring all-reduce = reduce-scatter + all-gather（K02）。
- attention 的 `s²` 复杂度、RoPE 的基本旋转形式。

## 核心机制

### 1. SP：补 TP 的漏

TP 只切 GEMM 密集区，LayerNorm 与 Dropout 在 TP 组内仍是复制的，这部分激活约 `10·s·b·h` 不被 t 除（`C`，论文）。SP（sequence parallel）把这些逐元素算子沿序列维切开，用 g/ḡ 在"序列切分"与"hidden 切分"两种 layout 间转换（`C`，`insights §7.2`）：

```text
SP (g):   forward = all-gather(seq 维)   ; backward = reduce-scatter
SP (ḡ):  forward = reduce-scatter       ; backward = all-gather
带宽: g/ḡ 合计 = all-reduce，故 SP 不增加带宽
```

因为 ring all-reduce = reduce-scatter + all-gather，把一次 all-reduce 拆成 g/ḡ 两个半步并移到正确位置，总量不变（`C`）。SP 的真实收益在激活显存与等待时间分布，不是"省带宽"。

### 2. CP：长序列的 s² 分摊

CP（context parallel）沿序列维切分激活，但**不切权重**，attention 的 `s²` 代价被分摊到多个 rank（`C`，`insights §9.2`）。代价有三：

1. attention 需要在 CP 组内交换 KV/softmax 统计（ring/zigzag 等），通信量随序列长度增长；可能走 P2P（`--cp-comm-type p2p`）或集合型（`I`，`insights §9.6`）。
2. 因为权重被复制，backward 要额外归约复制份的权重梯度，且归约域是 `DP ∩ CP` 的复合（`C`，`M02/design.md`）。
3. 未与计算重叠时通信占主，可能负收益；官方建议 sequence length ≥ 8K 时启用并强调 overlap（`C`）。

| 维度 | SP | CP |
|---|---|---|
| 切分对象 | LN/Dropout 复制区 | 整个序列激活 |
| 权重 | 不额外复制 | 复制 |
| 主通信 | g / ḡ（集合） | KV/统计交换（可能 P2P） |
| 激活收益 | 非 TP 区 /t | 峰值 /CP |
| 触发条件 | 与 TP 并用 | seq ≥ 8K |

（`C/I`，`insights §7/§9`，`M02/design.md`。）

### 3. RoPE 与位置语义

RoPE 把位置编码为对 Q/K 的分组旋转变换（`I`，通用模型知识）：

```text
θ_i = base^(-2i/d),  i = 0, 1, ..., d/2 - 1
q_rot = R(θ, pos) · q,  k_rot = R(θ, pos) · k
相对位置性质：<q_rot(p), k_rot(m)> 只依赖 (p - m)
```

长序列外推的常见缩放（`I`，通用做法）：

```text
NTK-aware：base' = base · (scale)^(d/(d-2))
YaRN      ：混合频率插值与注意力温度缩放
position interpolation：pos' = pos · (L_train / L_target)
```

RoPE 在并行训练中的坑集中在"位置语义"与"序列切分"的交互：

- **packed sequence** 必须按文档重置 position ids，否则跨文档拼接被当作连续位置。
- **CP 切分**时每段的 position ids 必须相对全局序列而非局部切片，否则 attention 旋转相位错位。
- **改 base 频率**通常需要相应微调，否则训练分布不匹配（`I`）。

（`C`，`M04-data-pipeline/README.md` 记录 `reset_position_ids`/`cu_seqlens` 分支；`I` 为通用外推方法。）

### 4. packed sequence 与 cu_seqlens

`_get_ltor_masks_and_position_ids` 按配置创建 causal attention mask、loss mask 与 position ids；跨文档 masking 时额外生成每个 packed segment 的起止位置与最大长度，供 varlen attention 使用（`C`，`M04-data-pipeline/implementation.md`）。`reset_position_ids`、`reset_attention_mask`、`eod_mask_loss`、inter-document masking 会改变缓存与 `cu_seqlens` 生成。

CP 切序列时 `cu_seqlens` 等元数据必须随序列切片一起调整，否则 varlen attention 段边界跨 rank 错位（`C/I`，`T-A009`）。

### 5. 长上下文的显存分解

按增长源拆激活（`I`，`expert.md` T-E005）：

```text
mem_act(s) ≈ mem_linear(s) + mem_attention(s²)
  mem_linear    ~ L * s * b * h          # 被 SP 除, 或 recompute
  mem_attention ~ a * s² * b / CP        # 被 CP 除
CP 代价:
  grad_reduce_domain = CP ∪ DP           # 权重复制份额外归约
recompute 判据:
  if 5*a*s/h > 34: recompute region      # 重算更省激活
```

设计顺序：s² 中间量用 CP 切序列、线性激活用 SP 切 LN/Dropout、残余用 selective recompute 兜底、overlap 决定 CP 是否划算。

### 6. 配置约束

- MoE + TP 组合时必须开 SP，因为 token dispatch 需要统一 layout（`C`，官方 MoE 文档）。
- SP 与 TP 绑定：SP 依赖 TP 的 hidden 切分布局（`C`）。
- CP 的梯度归约域与 DP 复合；引入 CP 时必须重算这条不变量（`C/I`）。
- axis order 与 stride 必须一致，否则 TP 与 CP 的 stride 混淆产生隐式错误（`I`）。

## 关键不变量

- ring all-reduce = reduce-scatter + all-gather ⇒ SP 带宽等价（`C`）。
- CP 不切权重 ⇒ backward 需额外归约复制权重的梯度（`C`）。
- packed sequence 的 flatten tensor 必须伴随 `cu_seqlens` 元数据（`C`）。
- CP 下 position ids 相对全局序列；packed 下逐文档重置（`C`）。
- loss mask 必须与有效 label 对齐（`C`，K12）。

## 常见陷阱与反例

- 以为 SP 增加了通信开销而拒绝开启：错失几乎零带宽代价的激活收益。
- 只开 SP 不开 TP，或只开 CP 期望权重显存下降：SP 依赖 TP 的 hidden 切分，CP 不切权重。
- 开 CP 却不做通信重叠：长序列下通信占比上升，吞吐不升反降（`U / 待验证`）。
- 把 CP 当成 TP 的替代来切 hidden：attention head 与序列维布局不匹配，静默错误。
- packed sequence 不重置 position ids：跨文档位置被当作连续，长上下文能力被破坏且不易察觉。
- CP 下每 rank 从 0 编号位置：attention 相位错位，loss 异常但不报错。
- CP 切片时忘记同步切 `cu_seqlens`/position：段边界错位。
