# K04 张量并行

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。论文锚点 arXiv:1909.08053。

## 范围

本域回答"如何在单个 Transformer 层内把 GEMM 切开，以及切分方向为什么由非线性算子决定"。核心是列切/行切的推导、f/g 共轭算子、每层通信次数与体积、GQA 整除约束、以及与 sequence parallel 的 layout 转换。

本域**不负责**：序列维切分（K06）、数据维复制（K03）、流水层间（K05）。TP 只切权重与激活的 hidden/head 维，不切数据。

## 先修知识

- 矩阵乘法维度与 GEMM 分块。
- GeLU/softmax 的逐元素性质。
- `all-reduce`（K02）。

## 核心机制

### 1. 切分方向由非线性决定

考虑 `Y = GeLU(X·A)`：

- **列切 A**：`A = [A1, A2]`，得 `[Y1, Y2] = [GeLU(X·A1), GeLU(X·A2)]`。GeLU 逐元素，各分片可独立施加，无中间同步（`C`，论文）。
- **行切 A（第一步不行）**：`Y = GeLU(X1·A1 + X2·A2)`，而 `GeLU(X1A1) + GeLU(X2A2) ≠ Y`，必须在 GeLU 之前 all-reduce，凭空多一个同步点（`C`）。

所以原则是：**任何需要跨分片求和的中间量，必须在施加非线性之前完成归约**。Megatron 的解法是把非线性夹在两次 GEMM 之间：

- **MLP 配方**：第一个 GEMM 列切、第二个 GEMM 行切，第二个 GEMM 输出是部分和，末尾一次 all-reduce（g）。
- **Attention 配方**：QKV 投影按列切（head 维），本地 attention，输出投影按行切，末尾一次 all-reduce。

### 2. layout 与通信量

设 hidden 为 h、TP 为 t、激活为 s×b×h（`C/I`，`insights §6`）：

```text
MLP:      X ── W1[h, 4h/t] ── GeLU(local) ── W2[4h/t, h] ── ⊕
                                                          └─ allreduce(g) ─→ out
Attention: X ── QKV[h, (3h)/t] ── local attention(head 完整) ── outproj[h/t, h] ── ⊕
                                                          └─ allreduce(g) ─→ out
```

- 列切权重 `W1: [h, 4h]`，每 rank 持 `[h, 4h/t]`；行切权重 `W2: [4h, h]`，每 rank 持 `[4h/t, h]`。
- 单卡 GEMM 计算量正比于 `h·4h/t`，t 越大单卡矩阵越小、计算密度越低（碎片化）。
- 每次 all-reduce 在 ring 算法下搬运约 `2(t-1)/t·s·b·h` 个元素（reduction + broadcast 两段）。
- **每层共 4 次 all-reduce**（forward 两次 g、backward 两次 f），**与 t 无关**。变多的是单次体积与未 overlap 时的延迟占比。

### 3. f 与 g 共轭算子

```python
class f(torch.autograd.Function):   # forward 恒等，backward all_reduce
    def forward(ctx, x): return x
    def backward(ctx, g): dist.all_reduce(g); return g
```

- `f`：forward 恒等、backward all-reduce。
- `g`：forward all-reduce、backward 恒等。

（`C`，论文 `insights §6.6`。）放置错误会立刻显形：把 f/g 位置放反，forward 的 all-reduce 落到 backward，梯度只聚合了一部分输入沿，TP=2 首步 loss 就偏离 TP=1 基线。

### 4. GQA / MLA 的整除约束

GQA 的 KV head 数（query groups）必须能被 t 整除，否则无法让每个 rank 持有整数个 KV head；Megatron 需要复制 KV 投影或 padding（`C/I`，`insights §6.10`）。配置上先确认 `num_query_groups % t == 0` 再决定 TP 度数。MLA 的 latent 投影与解压 GEMM 也要 TP 化，且更难与 head 维对齐（`I`）。

### 5. 与 CE 融合、词表分片的关系

输出层 `parallel_output=True` 时 logits 保持 TP 分片 `[b, s, v/t]`，调用方不能假定全词表已 gather（`C`，`M01-core-models/implementation.md:48`）。Megatron 把 logits 与交叉熵损失融合，先算局部 `[Y1, Y2]`，只对 loss 标量跨 rank all-reduce，通信量从 `b·s·v` 降到 `b·s`（`C`，`insights §6.13`）。

词表要 padding 到能被 t 整除、各分块等大（`C`，`insights §6.10`）；论文示例把 GPT-2 词表 50257 padding 到 51200（×8 路）。embedding 按词表列切后需一次 all-reduce 汇总 token 的 embedding（`C`）。

### 6. 与 sequence parallel 的接缝

TP 只切 GEMM 密集区，LayerNorm/Dropout 在 TP 组内仍是复制的，这部分激活约 `10·s·b·h` 不被 t 除（`C`，论文）。SP 把这些逐元素算子沿序列维切开，用 g/ḡ 在"序列切分"与"hidden 切分"两种 layout 间转换：g forward 是 all-gather、backward 是 reduce-scatter；ḡ 相反（`C`，`insights §7.2`）。因为 ring all-reduce = reduce-scatter + all-gather，SP 不增加带宽（K06 展开）。

## 关键不变量

- 需要跨分片求和的中间量，必须在施加非线性之前完成归约（`C`）。
- 一个 Transformer 层 TP 通信次数为常数 4（不随 t 增长），体积随 t 变化（`C`）。
- `num_query_groups % t == 0`（GQA）；否则需复制或 padding（`C/I`）。
- 词表大小能被 t 整除，各 rank 词表子块等大（`C`）。
- `parallel_output=True` ⇒ logits 不 gather（`C`）。
- 列切参数各 rank 不同、梯度无需跨 rank 归约；行切参数经过 f 的 all-reduce，梯度沿 f̄ 传播（`I`）。

## 常见陷阱与反例

- MLP 第一层按行切、GeLU 前不归约：各 rank 对局部和取 GeLU，输出与全量不一致。
- 把 all-reduce 放在第二层 GEMM 之前：得到"先和对再乘"的错误组合。
- 以为 TP 越大通信越多：次数恒定，增多的是体积与 GEMM 碎片化。
- 忽略 query groups 整除约束：直接设 TP=16 跑到 QKV projection 才报 shape 错，或复制 KV 后误以为显存没变。
- 对分片 logits 直接做全词表 softmax/argmax：把分片当全量，产生错误 token 且不报错（K13）。
