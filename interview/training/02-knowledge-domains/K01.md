# K01 训练入口与生命周期

版本锚点：Megatron-LM `main` @ `3703d4e33a3a2b2d11ebcc8e41f45af7ce7d1eda`。证据：`C` 源码/模块文档明确、`I` 跨文档推断、`U / 待验证` 运行类。

## 范围

本域回答"命令行参数如何变成一个可恢复的训练作业，并在每个 global step 上被正确地提交或回滚"。它覆盖三段职责的边界与顺序：入口脚本产配置、`initialize_megatron` 定拓扑、`train`/`train_step` 做迭代与提交。

本域**不负责**：

- 单个算子/层的数学（见 K13、K04）。
- 进程组内部如何生成 rank（见 K02）。
- 优化器内部如何更新参数分片（见 K08）。
- 检查点文件的字节布局（见 K10）。

## 先修知识

- `torch.distributed` 的 `init_process_group`、`world_size`、`rank`。
- 前向/反向/参数更新的基本训练循环。
- `global batch`、`micro batch`、梯度累积的区别（K05 展开）。

## 核心机制

### 1. 三层职责与调用顺序

启动被拆成三个阶段，职责不共享可变状态（`C`，`megatron-lm/00-overview/architecture.md`：分层职责 1–5；`01-modules/M03-training-runtime/README.md` 主控制流）：

1. **入口脚本**（`pretrain_gpt.py` / `pretrain_gpt.main`）：解析命令行与 YAML，构造 `TransformerConfig`，注册 model provider（`ModuleSpec`）与数据 provider。它决定"训练什么"。
2. **`initialize_megatron`**：把配置落到运行环境——`init_process_group`、`initialize_model_parallel`（经 `RankGenerator` 建 TP/PP/DP/CP/EP 组）、设置随机种子与 CUDA 设备、构建全局 buffer。它决定"在什么拓扑上训练"（`C`，`megatron/training/initialize.py:48-176`）。
3. **`pretrain` → `train`**：`setup_model_and_optimizer` 构造 model list/optimizer/scheduler，取 `get_forward_backward_func`，进入 `global_step` 循环，逐步 forward、backward、`optimizer.step()`、日志。它决定"怎么迭代"（`C`，`megatron/training/training.py:1530+,4309+`）。

调用链（`C`，`M03-training-runtime/call-chains.md`）：

```text
pretrain_gpt.main
  -> pretrain
    -> initialize_megatron
       -> torch.distributed.init_process_group
       -> initialize_model_parallel
            -> RankGenerator -> create_group(NCCL/Gloo)
       -> set_seed / set_cuda_device
    -> setup_model_and_optimizer
       -> get_model
       -> get_megatron_optimizer
       -> get_optimizer_param_scheduler
    -> build_train_valid_test_data_iterators
    -> train
       -> get_forward_backward_func
       -> train_step
          -> schedule
          -> optimizer.step
          -> opt_param_scheduler.step
```

### 2. `train_step` 的提交语义

`train_step` 的单步顺序是（`C`，`megatron/training/training.py:3092+`；`M03-training-runtime/implementation.md`）：

```text
train_step:
  1. clear grad buffer / optimizer.zero_grad
  2. 处理特殊 iterator 与 variable shape
  3. forward_backward_func：schedule 前向反向 + finalize grads
  4. 收集 loss / activation 统计
  5. optimizer.step() -> (update_successful, grad_norm, ...)
  6. 聚合更新状态（跨并行组）
  7. if update_successful: scheduler.step() 且推进 iteration 计数
```

关键点：**只有 `optimizer.step()` 报告 update successful 时才推进学习率调度与迭代计数**（`C`）。溢出步（inf/nan）被丢弃时，参数、学习率、迭代计数都不动，状态原子地停留在上一步。这是"跳过步不损坏状态"的根据。

### 3. global batch 的构成

优化意义上的批量由三层相乘（`C/I`，`megatron-lm/01-modules/M05-optimizer-checkpointing/execution-flows.md`；`insights §5.6`）：

```text
global_batch = micro_batch_size × num_microbatches × DP
```

导出关系：

```text
local_batch      = global_batch / DP
num_microbatches = global_batch / (micro_batch_size × DP)
约束: global_batch % (micro_batch_size × DP) == 0
```

梯度累积在 grad buffer 上做，累积阶段对每个 microbatch 的梯度除以 `num_microbatches`，再在归约阶段触发 reduce-scatter/all-reduce（`I`，`insights §3.4`；`M02-parallelism/implementation.md` 无 pipeline 调度）。除以 M 只做一次；漏掉会让有效学习率放大 M 倍（K08 展开）。

### 4. 形式化不变量

把"训练正确"写成可判定的谓词，并挂到四个触发点（`I`，据 `M02/README.md`、`M03/implementation.md`、`M05/README.md` 归纳；`expert.md` T-E001）：

```text
I1 topology:  before model_build:
    pg_initialized == true
    world_size % (tp*pp*cp) == 0
    (vp > 1) ==> (pp > 1)
    not (gtp_remat and multi_distopt)
I2 schedule:  at train_step.exit, before opt.step:
    all_microbatches_backwarded == true
    finalize_model_grads_called_once == true
I3 commit:    if opt.step.success:
    scheduler.step(); iteration += 1
  else:
    state := state_k            # 本步不提交
I4 numeric:   every K steps:
    max_rank_spread(loss(step)) <= eps_loss
I5 state cut: at checkpoint:
    forall rank r: step_r == step_0
    saved_set == {model, opt, sched, rng, data_pos} at same step
```

设计要点：不变量 = 谓词 + 触发点 + 提交语义，并且失败要能归因到 `(axis, stage, step, rank)`。拓扑类与状态类只在边界判定（近零开销），数值类做周期采样。

## 关键不变量

- `init_process_group ≺ initialize_model_parallel ≺ model construction`（`C`）。顺序颠倒会让 TP 层不知道自己的 rank，权重分片错位且不报错。
- `world_size % (tp*pp*cp) == 0`（`C`，`M02/README.md` 关键不变量）。
- VP 只在 `PP > 1` 时合法（`C`）。
- GTP rematerialization 与多个 distributed-optimizer instance 当前互斥（`C`）。
- `optimizer.step()` 成功才推进 scheduler 与迭代计数（`C`）。
- 每个 step 恰好一次 `finalize_model_grads`，且在所有 microbatch 反向之后、`optimizer.step` 之前（`C/I`）。

## 常见陷阱与反例

- 在 `initialize_model_parallel` 之前 `build_model()`：TP 权重按默认 rank=0 分片，其余 rank 拿错切片，loss 异常但不报错。
- 把梯度 finalize 放在 `optimizer.step()` 之后：用未归约的局部梯度更新，各 rank 参数发散（K02、K08）。
- 忘记按 `num_microbatches` 缩放累积梯度：等效学习率随累积步数放大。
- 只改 `micro_batch_size` 与只改 `num_microbatches` 对 global batch 等价，但前者吃显存、后者增通信与调度；动态 microbatch（每步 M 不同）若仍按固定 M 缩放会破坏等价性（`U / 待验证`）。
- 把 `losses_reduced` 当成完整训练状态：它只是单步产物，不是 checkpoint 状态（`C`，`M03-training-runtime/data-structures.md`）。
- 溢出/异常时仍推进 iteration 与 lr：恢复点与状态错位，表现为"重启后 loss 跳变"。
