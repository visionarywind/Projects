# K08 性能测量与可观测性

## 学习目标

建立「先证明正确再谈性能」的度量习惯，掌握 kernel/step/端到端三级延迟口径与日志/metrics/trace 的分工，能设计固定环境与输入、带 oracle 门禁、可一键重跑的性能对比实验，并把观测性归因与因果归因分开、用对照实验确立因果。

## 核心机制

- 正确性优先：优化前先固定输入与期望、建立可复现 baseline，并用独立于被测实现的 oracle 校验数值等价，容差作为回归门禁。
- 三级口径：kernel 用设备 event 计时、不含 launch 与排队；step 是一个迭代的墙钟、含该步全部 kernel/通信/同步；端到端含排队、网络、前后处理，面向 SLO。
- 时间轴对齐：host 与 device 时间不同轴，需用 trace 对齐；端到端由最长关键路径决定，重叠段不能简单相加，同步时间常是被忽略的隐藏大头。
- 三级可观测性：metrics 是聚合时间序列（发现异常），trace 是请求级跨组件调用链（定位慢在哪一段），日志是离散事件（查明具体原因），粒度与成本互补。
- 实验设计：同环境、锁频、固定种子与 shape、充分 warmup，交替 A/B 抵消时间漂移，报告分位数与方差而非单次值。
- 归因分层：观测性归因用 trace 找出哪一段变长，因果归因用单因素对照实验确认该因素导致端到端变化，并排查共因与环境漂移。

## 常见坑

- 用 kernel 时间代表端到端，忽略排队与同步，或把各段直接相加而忽略重叠。
- 拿被测实现自己当 oracle，或先优化后补测试，结果「更快但算错」。
- 不预热、不隔离环境、不锁频就下结论，把冷启动或噪声当成收益。
- 只报平均值或单次跑分，不看分位数与方差。
- 从观测到的相关直接跳到因果结论，一次改多个因素，或忽略环境漂移与共因。
