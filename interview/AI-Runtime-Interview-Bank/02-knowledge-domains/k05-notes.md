# K05 集合通信

## 学习目标

掌握 AllReduce 的语义及其与 ReduceScatter + AllGather 的等价分解，理解 ring/tree 与分层拓扑按消息规模选型的依据，能管理通信 buffer 的跨流生命周期，并为集合通信设计通信计算重叠与局部分级故障恢复。

## 核心机制

- AllReduce 语义：对 N 个 rank 的输入按元素归约并把结果广播给所有 rank，完成后各 rank 输出一致，是数据并行正确性的前提；它等价于 ReduceScatter + AllGather。
- 算法与拓扑：ring 每 rank 通信量趋近常数倍、带宽友好，步数随 N 线性增长；tree 步数约 2logN、延迟低但靠近根的链路负载更重。大消息偏环、小消息偏树。
- 分层级联：节点内优先走 NVLink 做局部归约，节点间再跨层聚合，按消息大小设阈值自动切换算法。
- 通信 buffer 生命周期：send 侧完成前只读、recv 侧完成前不可读取；释放前必须排空引用它的通信；跨流使用要登记到全部相关流。
- 重叠：按层或 chunk 切分，用「该块计算完成的 event」建立依赖后发起通信，把通信塞进后续计算空隙；尾块无法隐藏，chunk 大小以最小化尾块为目标。
- 局部失败：集合操作是全体同步，成员失联需幂等重建 communicator，straggler 需统计检测并隔离或降级参与度，二者处置不同。

## 常见坑

- 把 AllReduce 当成 AllGather，漏掉归约，或忽略「各 rank 结果必须一致」。
- 把通信调用返回当成完成，立即读取 recv buffer 或释放被引用的 tensor。
- 忽略拓扑分层，只按消息大小选算法；或混淆「步数」与「通信量」来衡量优劣。
- 跨流使用 buffer 却只登记部分流，分配器提前复用导致偶发数值错乱。
- 全连接建 QP 造成资源平方级增长，或重建通信域非幂等、留下半重建状态导致重复提交。
