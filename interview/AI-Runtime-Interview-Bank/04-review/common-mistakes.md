# 常见错误与反例

## 技术回答错误

1. **API 返回 = 设备完成**：忽略异步队列和 completion。
2. **Tensor 引用存在 = buffer 可复用**：忽略跨 Stream 访问。
3. **reserved 高 = 内存泄漏**：未区分 cache、deferred、workspace 和外部占用。
4. **free 总量足够 = 分配必成功**：忽略最大连续块、对齐和布局。
5. **全局同步解决一切**：可能止血但损失重叠，且掩盖依赖错误。
6. **开线程即可 overlap**：没有说明 stream、event、buffer 和 GPU/NIC 实际时间线。
7. **通信库快 = 端到端快**：忽略 rank skew、pipeline fill/drain、P99 和数据准备。
8. **把 TCP 经验等同 RDMA**：必须说明协议、数据路径和自己做过的层。

## 项目表达错误

- 用“参与”掩盖无法说明本人负责边界；
- 用宏观模块名替代入口、数据结构、状态和副作用；
- 没有 baseline、指标、环境就报性能提升百分比；
- 把读源码、设计方案、实现代码和线上验证混为一谈；
- 遇到追问时编造函数名、版本、故障或数据。

## 纠正模板

> 我先区分已确认事实和我的推断。已确认的是 ______；我亲自负责的是 ______；关于 ______ 我目前只有源码/设计层面的理解，没有生产验证。若要确认，我会在 ______ 环境，用 ______ 对照，观察 ______ 指标，判定 oracle 是 ______。

## 失败模式对照表

| 现象 | 首先不要做 | 应先做 |
|---|---|---|
| 偶发错误 | 直接加全局同步并结束调查 | 建立有/无依赖对照，画 happens-before |
| OOM | 盲目清 cache/加显存 | 记录 allocated/reserved/free/deferred/workspace |
| P99 上升 | 只看平均延迟 | 分解排队、同步、传输、回收和尾部请求 |
| collective hang | 重启所有进程 | 保留 rank/step/顺序/连接/CQ/stream 证据 |
| 编译失败 | 直接修改 kernel | 先核对 compiler、driver、框架、ABI 和 flags |
