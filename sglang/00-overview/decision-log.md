# 决策记录

## D001：以当前 checkout 而非远程 release 为版本锚点

- 状态：已采用。
- 原因：源码分析必须能复现；远程 release 可能比本地 checkout 新。
- 影响：文档写明 commit、分支和未跟踪状态；远程版本只作为外部参考，不作为证据。

## D002：保留已有 `02-request-flow/` 文章

- 状态：已采用。
- 原因：这些文章已经覆盖请求、调度、执行、配置和 IPC，删除会丢失面向小白的叙述。
- 影响：新知识库通过索引和模块映射复用它们，不复制同样的全文；旧文件名保留兼容链接。

## D003：模块 ID 按职责/接口边界划分

- 状态：已采用。
- 原因：单纯按目录会把同一生命周期拆散，也会把独立 runtime 混在一起。
- 影响：M06 模型加载和 M07 分布式是不同模块，但在启动链上相互依赖。

## D004：先建立总览，再补实现和 Demo

- 状态：进行中。
- 原因：没有稳定的数据流、错误边界和模块 ID，Demo 解剖会退化为命令说明。
- 影响：`analysis-state.md` 记录阶段和缺口；未执行的 Demo 不声称成功。

## D005：普通 HTTP LLM 作为主线，变体单列

- 状态：已采用。
- 原因：Ray、diffusion、speculative、disaggregation 和多模态改变局部拓扑；把它们强行合并会误导初学者。
- 影响：主线先解释共用协议，再在模块/跨模块文章中说明替换点。
