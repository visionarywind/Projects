# 《NEO：通过 CPU Offloading 缓解在线 LLM 推理的 GPU 内存危机》中文详译

- 原文：NEO: Saving GPU Memory Crisis with CPU Offloading for Online LLM Inference
- arXiv：<https://arxiv.org/abs/2411.01142>
- PDF/抽取文本：[`../2411.01142-neo-cpu-offloading.pdf`](../2411.01142-neo-cpu-offloading.pdf)、[`../2411.01142-neo-cpu-offloading.txt`](../2411.01142-neo-cpu-offloading.txt)
- 翻译范围：摘要、在线推理背景、CPU offload、非对称流水、负载感知调度、实验结论与 KV pool 边界。

## 摘要中文翻译

在线 LLM 推理直接面向用户，因此既需要低延迟，也需要高吞吐。GPU 显存限制会约束 batch size，尤其在长上下文和大模型场景下，KV cache 占用会持续增长。NEO 提出将一部分 decoding attention computation 和 KV cache 从 GPU 转移到本机 CPU，以扩大有效 batch size 并提升吞吐。

为降低 CPU offload 带来的性能损失，NEO 采用非对称 GPU-CPU pipelining 和 load-aware scheduling。系统在每个 iteration 中同时处理 GPU 路径和 CPU 路径的 sub-batch，并跨 iteration 平衡两者负载。论文在多种 workload、GPU 和模型上评估，并报告不同硬件条件下的收益。

## 引言与问题背景中文翻译

在线 serving 的核心矛盾是：更大的 batch 往往能提高 GPU 利用率，但 KV cache 和中间状态会占用大量显存，使系统无法继续增加 batch。量化、压缩、稀疏等方法可以降低内存压力，但可能影响精度或需要模型/系统改动。另一类方法是把部分权重、KV cache 或计算 offload 到 CPU。

NEO 关注 decode 阶段的 attention 和 KV cache。Decode 是逐 token 迭代执行，单步计算相对小，但会频繁访问历史 KV。将部分请求的 attention/KV 移到 CPU，可以释放 GPU memory，让 GPU batch 接纳更多请求。

## 核心机制中文翻译

### CPU offloading

NEO 把一部分请求的 KV cache 和 decoding attention computation 放到 host CPU。GPU 仍处理其余请求。这样，系统不再要求所有请求的 KV 都驻留 GPU HBM。

### 非对称 GPU-CPU 流水

CPU 和 GPU 的计算能力、内存带宽、访问延迟差异很大，因此不能简单平均分配请求。NEO 使用 asymmetric pipelining：在同一 iteration 中，GPU 处理一个 sub-batch，CPU 处理另一个 offloaded sub-batch。两个 sub-batch 大小和工作量可以不同，目标是让 GPU 与 CPU 都尽量保持忙碌。

### Load-aware scheduling

NEO 使用负载感知调度来决定哪些请求走 CPU 路径、哪些保留在 GPU，以及每个 iteration 如何划分 sub-batch。调度目标是在 GPU memory pressure、CPU compute、PCIe/host memory 访问和 latency 之间取平衡。

## 系统与资源管理要点中文翻译

NEO 的 KV pool 不再是单一 GPU pool，而是 GPU resident KV 与 CPU resident KV 的联合资源。请求的 KV ownership 可能在 GPU/CPU 之间切换；scheduler 需要知道 offload 后的执行路径、CPU 队列长度、GPU batch 余量和延迟 SLO。

该设计要求 attention kernel 或等价计算路径在 CPU 上可执行，并且 CPU 路径结果能与 GPU decode 流程同步。

## 实验与作者报告结果中文翻译

论文在代码生成、文本摘要等 workload，以及 T4、A10G、H100 等 GPU 和 7B/8B/70B 模型上评估。作者报告 NEO 在弱 GPU 或 CPU 资源更匹配的条件下收益更明显，而不同硬件组合收益差异较大。本仓库未复现实验。

## 局限与不能外推的内容

- CPU offload 可能提升容量，但也可能引入 CPU 争用和 tail latency。
- 如果 PCIe/CPU 带宽不足，offload 会成为瓶颈。
- GPU 很强但 CPU 较弱时，收益可能有限。
- 当前仓库没有验证 NEO 在 SGLang 或本机上的可用性。
