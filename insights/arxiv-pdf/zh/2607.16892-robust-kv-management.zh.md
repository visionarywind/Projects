# 《输出 Token 长度不确定下的鲁棒 KV Cache 管理》中文详译

- 原文：Robust KV Cache Management for LLM Serving under Output Token Length Uncertainty
- arXiv：<https://arxiv.org/abs/2607.16892>
- PDF/抽取文本：[`../2607.16892-robust-kv-management.pdf`](../2607.16892-robust-kv-management.pdf)、[`../2607.16892-robust-kv-management.txt`](../2607.16892-robust-kv-management.txt)
- 翻译范围：摘要、输出长度不确定问题、reservation/preemption、routing、prefix caching、SLO 和成本模型边界。

## 摘要中文翻译

KV cache memory 是 LLM serving 的主要瓶颈之一。系统在请求到达时就必须决定为它预留多少 KV cache，但输出 token 长度只有在生成完成后才知道。预留过少会导致 preemption：请求被迫终止并重算，产生明显开销；预留过多则浪费显存，降低吞吐。Reservation 决策直接影响 throughput 和 service quality。

论文提出一个鲁棒优化框架，联合考虑 GPU parallelism configuration、每类请求的 KV cache reservation、跨异构 serving group 的 request routing、shared prompt 的 prefix caching 和 latency SLO。目标是在输出长度不确定和 workload 分布变化下控制成本并满足服务质量。

## 引言与问题背景中文翻译

不同任务的输出长度差异很大：简短问答可能只生成几十个 token，代码生成或长文任务可能生成数千 token。使用单一 global quantile 作为 reservation 策略，很难同时适配所有请求类型。如果 quantile 太低，长输出请求会频繁 preempt；如果太高，短请求会浪费大量 KV capacity。

同时，workload 分布具有 non-stationarity：真实流量会随时间变化。Serving 系统还可能有不同 TP/PP 配置、prefill/decode 分离和连续 batching，这些都会影响 KV capacity 与成本。

## 核心机制中文翻译

### Reservation 与 preemption

Reservation 是 admission 时为请求预留的 KV 空间。Under-reservation 会在输出超过预留时触发 preemption 或重算；over-reservation 会占用本可服务其他请求的 capacity。

### 联合优化

论文把 reservation 与 routing、GPU parallelism、prefix caching 和 latency SLO 一起建模。不同 serving group 具有不同吞吐、显存、成本和延迟特征；请求应被路由到合适 group，并使用适合其类别的 reservation。

### Prefix caching

共享 prompt prefix 可以减少 prefill 计算和 KV 占用，但也改变 reservation 的有效需求。鲁棒管理需要把 prefix hit 纳入容量与成本模型，而不是只看单请求最大长度。

## 系统与资源管理要点中文翻译

这篇论文强调：KV pool 管理不是 allocator 层单独能解决的问题。Admission control、scheduler、routing、parallelism config 和 prefix cache 都会改变实际可用 capacity。生产系统应记录每个请求的 reservation、实际输出长度、preemption、prefix hit 和最终释放时间。

## 实验与作者报告结果中文翻译

论文使用生产 trace 或公开 trace 进行评估，并报告相对 fixed-quantile baseline 的成本降低。这些结果依赖 trace、SLO、成本模型、硬件配置和 workload 分类。本仓库没有 trace 或 SLO 复现实验。

## 局限与不能外推的内容

- 需要真实输出长度分布和成本模型才能落地。
- Workload drift 会使历史 quantile 失效。
- Prefix caching 命中率受应用 prompt 结构影响。
- 当前仓库未验证该优化框架。
