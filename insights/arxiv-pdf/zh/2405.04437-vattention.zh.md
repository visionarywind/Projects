# 《vAttention：不使用 PagedAttention 的 LLM 服务动态内存管理》中文详译

- 原文：vAttention: Dynamic Memory Management for Serving LLMs without PagedAttention
- arXiv：<https://arxiv.org/abs/2405.04437>
- PDF/抽取文本：[`../2405.04437-vattention.pdf`](../2405.04437-vattention.pdf)、[`../2405.04437-vattention.txt`](../2405.04437-vattention.txt)
- 翻译范围：摘要、动机、CUDA VMM 机制、系统设计、实验结论和 KV pool 相关术语；不逐字翻译参考文献和排版噪声。

## 摘要中文翻译

LLM serving 系统需要动态管理 KV cache，因为请求长度和输出长度在运行时变化。PagedAttention 通过非连续 KV block 和自定义 attention kernel 缓解物理显存碎片，但这种非连续布局会改变 kernel 编程模型，并可能带来性能开销。vAttention 的目标是在不采用 PagedAttention 非连续虚拟布局的情况下，实现动态显存管理。

vAttention 使用 CUDA virtual memory management API，将虚拟地址空间和物理 GPU memory allocation 解耦。系统可以先为 KV cache 保留连续虚拟地址区域，再在运行时按需映射物理显存。这样，请求和 attention kernel 可以看到连续的 KV cache 视图，而物理 backing 仍然可以动态分配。论文报告该方法在作者实验条件下获得吞吐收益。

## 引言与问题背景中文翻译

PagedAttention 解决了传统连续 KV cache 布局的显存碎片问题，但它也把非连续布局暴露给 attention kernel。论文指出，在高度优化的 attention kernel 生态中，layout 变化会导致额外索引、访存不规则和 kernel 维护复杂度。作者用 vLLM 的 paged kernel 与连续布局 kernel 对比，说明非连续布局可能影响 decode 和 prefill 性能。

vAttention 的基本判断是：KV cache 需要动态物理内存，但不一定需要动态虚拟布局。如果能保持虚拟地址连续，同时在底层延迟分配和映射物理页，就可以兼得连续 layout 与动态物理分配。

## 核心机制中文翻译

### CUDA VMM 解耦虚拟地址与物理 backing

CUDA virtual memory management 允许程序保留一段虚拟地址空间，再把物理 GPU memory handle 映射到该虚拟地址范围。vAttention 利用这一点，为 KV cache 保留连续虚拟空间，并在 token 增长时按需追加物理 backing。

这与 PagedAttention 的差异在于：PagedAttention 让 kernel 通过 block table 访问非连续 physical block；vAttention 则尽量让 kernel 看到连续地址，从而复用或更接近传统连续 attention kernel。

### 运行期分配物理显存

论文的一个 observation 是：每个 token 的 KV footprint 通常是几十到几百 KB 量级，KV cache 对 allocation bandwidth 的要求不像计算 kernel 那样高。因此，可以把 physical allocation 推迟到 runtime，在请求实际增长时映射 backing，而不是一次性预留所有可能输出长度。

### 保持 virtual contiguity

vAttention 的设计目标是：虚拟地址连续，物理 backing 动态。这样系统减少 physical memory fragmentation，同时避免 attention kernel 因 non-contiguous virtual layout 付出太多代价。

## 系统与资源管理要点中文翻译

vAttention 需要管理三类状态：

1. 每个请求或 batch 的连续虚拟 KV 区间；
2. 已映射的物理 GPU memory page；
3. 未映射但保留的虚拟地址范围。

当序列增长时，系统决定是否分配新的物理页并映射到虚拟地址。释放时，系统需要 unmap 并回收 physical handle，同时保证没有 kernel 或 CUDA Graph 仍引用该范围。

## 实验与作者报告结果中文翻译

论文报告 vAttention 在若干 serving workload 下相对 paged attention 路线获得吞吐收益，并分析 paged kernel 相对连续 kernel 的开销。这些数字依赖 CUDA 驱动、GPU 架构、page 粒度、模型形状、batch 和 workload，本仓库未复现。

## 局限与不能外推的内容

- CUDA VMM 的 map/unmap 开销和 page granularity 对硬件/驱动敏感。
- 虚拟连续不自动解决 prefix cache eviction、跨节点 KV transfer 或输出长度 reservation。
- 若系统依赖 CUDA Graph，虚拟地址和 backing 生命周期必须与 graph capture/replay 边界协调。
- 当前仓库没有验证 vAttention 的驱动兼容性或性能。

## KV pool 术语对照

| 英文术语 | 中文译法 | 说明 |
|---|---|---|
| virtual memory | 虚拟内存 | CUDA VMM 中保留的地址空间 |
| physical memory | 物理显存 | 实际 GPU backing |
| virtual contiguity | 虚拟连续性 | kernel 看到连续地址 |
| map / unmap | 映射 / 解除映射 | 绑定或释放 virtual→physical 关系 |
| paged kernel | 分页 kernel | 显式处理 block table 的 kernel |
