## 摘要中文翻译

高吞吐地服务大语言模型需要同时批处理足够多的请求。由于每个请求生成的输出长度事先未知，推理系统必须持续保存随序列增长的 attention key/value cache。传统系统往往为请求预留过多内存，或者要求 KV cache 连续存放，导致显著的碎片、浪费和重复复制，最终限制 batch size。

论文提出 PagedAttention：它借鉴操作系统虚拟内存分页思想，把每个请求的 KV cache 划分为固定 token 数的 block。逻辑 block 不必在物理显存中连续存储，而是通过 block table 映射到物理 block。这样可以按需分配 KV block、减少内外部碎片，并支持多个请求或候选序列共享相同 prefix 的 KV block。论文基于该机制构建 vLLM，并报告在作者实验环境中相对 FasterTransformer 和 Orca 获得显著吞吐提升。

## 引言与问题背景中文翻译

LLM 推理的主要压力来自两类资源：模型权重占用的大量显存，以及随请求动态增长的 KV cache。模型权重相对固定，而 KV cache 的大小取决于输入长度、输出长度和 batch 中请求数。输出长度不可预知，使 serving 系统很难在 admission 时精确预留内存。

如果系统给每个请求按照最大长度预留连续 KV 空间，则大量空间会在请求短输出时被浪费。如果采用更保守的增长策略，又可能在 decode 阶段频繁遇到内存不足、迁移或复制。论文指出，这类碎片和重复复制会直接降低可以并行服务的请求数，从而限制吞吐。

## 核心机制中文翻译

### 分页式 KV cache

PagedAttention 把一个请求的 KV cache 拆成多个 logical KV block。每个 block 包含固定数量 token 的 key 和 value。系统维护 block table，将 logical block 映射到 physical KV block。这样，请求的逻辑序列可以连续增长，但物理 KV block 可以分散存放。

论文给出的类比是：block 类似操作系统中的 page，token 类似 byte，请求类似 process。通过较小的 block 按需分配，可以缓解 internal fragmentation；通过允许物理 block 不连续，可以避免 external fragmentation；通过 block 共享，可以避免相同 prefix 的 KV 重复存储。

### Block table 与动态增长

每个请求有自己的 block table。表项记录某个 logical block 对应的 physical block，以及该 block 中已经填充的位置。decode 每生成新 token 时，系统将新的 key/value 写入当前 logical block 对应的 physical block；如果当前 block 已满，则分配新的 physical block 并更新 block table。

这种设计把“请求序列连续”与“显存物理连续”分离。attention kernel 通过 block table 找到每个 token 的实际 KV block，而不是假设整段 KV 在物理地址上连续。

### Prefix 共享与 copy-on-write

在 parallel sampling、beam search 或多个请求共享 prompt prefix 时，不同候选序列前缀相同。PagedAttention 可以让这些候选共享已有 physical block。只有当某个候选要写入与其他候选不同的 suffix 时，才执行 copy-on-write，为分歧部分分配或复制新的 block。

这使 KV cache sharing 从 token 级或整段复制，变成 block 粒度的引用共享。对长 prefix、多候选生成场景，block sharing 可以显著减少冗余 KV 存储。

## 系统与资源管理要点中文翻译

vLLM 基于 PagedAttention 组织内存管理。系统维护可用 physical block 池，请求通过 block table 持有 block 引用。调度器在请求进入、扩展、decode、完成和释放时更新 block ownership。对共享 block，需要引用计数或等价机制防止仍被其他请求使用的 block 被提前释放。

PagedAttention 的关键不是调用 CUDA malloc/free 为每个请求分配一大段 KV，而是在系统启动或运行中维护一个可管理的 physical block pool，并用逻辑映射表在请求层动态分配。

## 实验与作者报告结果中文翻译

论文报告 vLLM 在其评测环境中显著降低 KV cache waste，并相对 FasterTransformer、Orca 等系统提升吞吐。论文中的数字依赖模型、GPU、请求长度分布、sampling 设置和实现版本，本仓库未复现实验。

## 局限与不能外推的内容

- PagedAttention 降低碎片和共享成本，但 attention kernel 必须能够处理 block table 和非连续物理布局。
- Block size 影响 page 内浪费、kernel 访存效率和共享粒度，不能脱离 workload 固定一个最优值。
- 论文结果不能直接外推到所有 GPU、所有模型或所有 serving 框架。
- 本仓库没有复现 throughput、waste、block size sweep 或 kernel 性能结果。
