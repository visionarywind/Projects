# 《P/D-Serve：大规模分离式大语言模型服务》中文详译

- 原文：P/D-Serve: Serving Disaggregated Large Language Model at Scale
- arXiv：<https://arxiv.org/abs/2408.08147>
- PDF/抽取文本：[`../2408.08147-pd-serve.pdf`](../2408.08147-pd-serve.pdf)、[`../2408.08147-pd-serve.txt`](../2408.08147-pd-serve.txt)
- 翻译范围：摘要、P/D 分离背景、KVCache transfer、资源编排、实验结论和 KV ownership 边界。

## 摘要中文翻译

LLM 推理通常包含 prefill 和 decode 两个阶段。Prefill 处理输入 prompt，计算量大、并行度高；decode 逐 token 生成，受 KV cache 访问和延迟约束。P/D-Serve 采用分离式 serving：把 prefill 和 decode 部署在不同实例上，并根据 workload 动态调整两类资源比例。

在这种架构下，prefill 产生的中间状态（KVCache）必须传输给 decode 实例。论文关注大规模 GPU/NPU 集群中 P/D 分离服务的可靠性能，尤其是请求多样性、P/D 资源比例不匹配、以及 RDMA 上 D2D KVCache transfer 利用率不足等问题。

## 引言与问题背景中文翻译

如果把 prefill 和 decode 混在同一资源池中，系统很难同时优化 TTFT 和 decode latency。Prefill 希望大 batch 和高吞吐，decode 希望稳定低延迟和持续 token 输出。分离部署可以让两类阶段采用不同 batch size、调度策略和实例规格。

但分离后必须解决 KVCache 交接问题：prefill 实例生成的 KV 需要在 decode 开始前或过程中传到 decode 实例。大规模集群中，D2D/RDMA transfer 的调度、带宽、失败恢复和流控会成为系统瓶颈。

## 核心机制中文翻译

### Prefill/decode 分离

P/D-Serve 将 prefill phase 和 decoding phase 放在不同服务实例中。系统需要把请求路由到合适的 prefill 实例，并在 prefill 完成后选择 decode 实例继续生成。

### KVCache transfer

论文明确指出，prefill 产生的 intermediate data 即 KVCache，需要在 P/D 之间传输。KVCache transfer 不是普通结果返回，而是大量张量页/块的跨设备移动，通常依赖高速互联和 RDMA。

### 动态 P/D 比例和请求组织

论文强调请求具有不同 prefix、长度和到达模式。简单把请求放在混合池中会造成不匹配。P/D-Serve 通过更细粒度组织请求相似性、动态调整 P/D ratio 和实例迁移来提升整体效率。

## 系统与资源管理要点中文翻译

P/D 场景中的 KV pool ownership 从“单进程内 allocator”扩展为跨实例协议。Prefill 端创建并拥有初始 KV；transfer layer 负责传输和确认；decode 端接收并开始消费；失败时需要重试、回滚或重算。系统还需要处理 transfer queue、网络拥塞、实例失联和 KV 生命周期清理。

## 实验与作者报告结果中文翻译

论文报告 P/D-Serve 在大规模设备和特定 workload 下改善 TTFT、throughput 与 transfer time。这些数字依赖集群规模、设备类型、RoCE/RDMA 配置、路由策略和请求分布。本仓库未运行多机或 D2D 实验。

## 局限与不能外推的内容

- “P/D 资源池管理”不等于存在一个全局共享显存池。
- KV transfer 的收益高度依赖网络和设备拓扑。
- 失败恢复、幂等传输和数据校验是生产系统必须补齐的部分。
- 当前仓库未验证 RDMA、NPU/GPU 集群或真实 P/D serving。
