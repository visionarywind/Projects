## D-001：按 M01–M07 拆分

**决定**：把核心算法、阻塞包装、信号量平台、C ABI、验证、benchmark、交付工程分成七个模块。

**依据**：源码文件和构建入口形成自然边界；仓库没有显式 module system，因此这是文档抽象而非代码架构声明。

**影响**：跨模块关系集中写入 `90-cross-module/`，避免各页复制完整实现。

## D-002：D01 使用 unit test 作为主 Demo

**决定**：把 `tests/unittests/unittests.cpp` 作为主端到端 Demo，把 benchmark 作为第二 Demo。

**依据**：unit test 同时触及核心、阻塞和 C API，且有明确命令行入口；benchmark 更适合展示测量而非语义正确性。

## D-003：未执行命令统一标为未验证

**决定**：静态分析得到的命令只记录来源和预期职责，不写成运行成功。

**依据**：本批知识库生成没有执行构建、测试、benchmark 或 RISC-V 工具链验证。

## D-004：第三方内部不展开

**决定**：记录 Boost、dlib、TBB、Relacy、CDSChecker 的项目依赖和入口，不虚构其内部调用。

**依据**：任务边界聚焦当前仓库；第三方细节不能由项目源码直接证明。
