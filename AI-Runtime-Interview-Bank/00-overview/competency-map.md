# 面试能力地图

## 能力层级

| 能力 ID | 能力 | 入门表现 | 高级/专家表现 |
|---|---|---|---|
| C01 | 概念解释 | 定义对象和边界 | 对照相邻概念、版本和失效条件 |
| C02 | 原理推导 | 说明因果和基本公式 | 从不变量、资源约束和上限推导结论 |
| C03 | 流程追踪 | 讲清入口到结果 | 讲清分派、状态、资源和异步边界 |
| C04 | 实现分析 | 能读伪代码/API | 映射到数据结构、锁、错误和清理路径 |
| C05 | 复杂度/容量 | 给出数量级 | 同时分析带宽、排队、P99、成本和扩展瓶颈 |
| C06 | 方案设计 | 给出最小可行方案 | 给出约束、替代、迁移、回滚和验证 |
| C07 | 故障排查 | 按现象分类 | 保护系统、建立假设、取证、止损和复盘 |
| C08 | 测试验证 | 写测试输入和预期 | 定义 oracle、控制变量、故障注入和误差范围 |
| C09 | 工程落地 | 考虑接口和资源 | 考虑兼容、灰度、观测、SLO、成本和维护 |
| C10 | 专家表达 | 结论清楚 | 明确个人证据、推断、争议和待验证边界 |

## 面试回答通用骨架

```text
先确认目标和约束
  → 定义对象/状态/所有权
  → 画调用链或依赖图
  → 说明正常路径
  → 补异常、取消、超时和清理
  → 给容量/性能模型
  → 比较替代方案
  → 设计测试 oracle 和观测指标
  → 绑定个人真实经历并标记证据等级
```

## 评分维度

每题按 7 个维度、每项 0–4 分，总分 28：

1. 概念准确性；
2. 原理与因果；
3. 流程/实现细节；
4. 边界、异常与反例；
5. 工程实践与验证；
6. 性能、成本和可靠性；
7. 权衡与表达清晰度。

若证据纪律不足，即使技术答案正确，也不能视为准备完成：回答个人经历时必须区分 `[P-已确认]`、`[P-待补充]`、`[S-已确认]` 和 `[待验证]`。
